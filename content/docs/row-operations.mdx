Inserting, duplicating, deleting, and reordering whole rows. All four act on **view-space**
indices (the sorted/filtered positions the user sees), emit one `onDataChange` with
`source: "row-op"` each, and work in both controlled and uncontrolled grids.

**See the live examples:** [Row operations](/docs/examples/rows/row-operations) · [Row
markers](/docs/examples/rows/row-markers) · [Drag &
drop](/docs/examples/rows/drag-reorder) · [Action buttons](/docs/examples/rows/actions) ·
[Streaming](/docs/examples/rows/streaming)

## Enable props

| Prop | Enables | Without it |
|---|---|---|
| `createRow: (index: number) => TData` | Insert row above/below | `insertRow` is a silent no-op with a dev-only warning. The context menu hides the two Insert items |
| `duplicateRow: (row: TData, index: number) => TData` | Duplicate row(s) | `duplicateRows` is a silent no-op with a dev-only warning. The context menu hides Duplicate |
| (none) | Delete row(s) | Always available |

`duplicateRow` receives the source row and the data index the copy lands at, and must give the
copy a distinct id (a spread copy with a fresh `id`), so a duplicate never collides with its
source row's React key. `createRow` receives the data-space insertion index. `insertRows`,
`deleteRows`, and `duplicateRows` are no-ops with a dev-only warning while an edit session is
open: the editor pins a view coordinate the row shift would invalidate.

## Default shortcuts

| Action | Default | Keymap action |
|---|---|---|
| Insert row below | <kbd>Ctrl</kbd>/<kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>F</kbd> | `insertRowBelow` |
| Duplicate row(s) | <kbd>Ctrl</kbd>/<kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>X</kbd> | `duplicateRow` |
| Delete row(s) | (no default binding) | (none) |

Both bindings live in `DEFAULT_KEYMAP`, so they can be remapped or dropped through the `keymap`
prop like every other binding (see [Keybindings](/docs/addons/keybindings#remapping)).

## Reorder

**See the live example:** [Drag & drop reorder](/docs/examples/rows/drag-reorder)

Drag a row marker vertically to reorder rows. A thin line marks the drop target, and the row
moves on release. The gesture is zone-based — the press location decides the behavior, not later
movement. In the `reorder`-family marker modes (`reorder`, `reorder-number`, `reorder-checkbox`,
`reorder-both`), the **grip zone** — the grip handle plus everything in the marker cell except
the number and checkbox glyphs (the whole cell in `reorder` mode) — is the only reorder entry:
a press there selects the row, and a vertical drag that leaves the row reorders it. The **number
and checkbox glyphs stay pure row-select surfaces**: a press on them selects (click) or drags a
row range (drag), never reorders. Plain `number`, `checkbox`, and `both` markers are selection
surfaces across the cell — a selection drag can never accidentally reorder.
<kbd>Shift</kbd>+drag from the grip is always the row-select range gesture.

| Prop | Role | Default |
|---|---|---|
| `rowMarkers` (`reorder` family) | supplies the grip zone (drag handle) | `none` has nothing to grab |
| `enableRowReorder` | grid-wide switch | `true` |

The programmatic form is `reorderRows(from, to)` from `useDataGridActions`, where `to` is the
**final** landing position (arrayMove semantics: moving row 0 to index 3 shifts rows 1–3 up).
It emits one id-keyed `move` op, so undo/redo restores the previous order in a single step.
Row-channel selection remaps by row id (the moved row keeps its selection state) and the active
cell follows its row. Each completed move is announced through the grid's `aria-live` region
(`labels.markers.reorderAnnouncement`).

<Callout type="warn" title="reorderRows is a no-op in these situations">
  It returns `false` (dev-warning where the cause is a misconfiguration) in these situations:

  - `enableRowReorder` is off, or the grid is `readOnly`
  - An edit session is open (the editor pins a view coordinate that the move invalidates)
  - A sort or filter is active (the view order belongs to the sort/filter, not the data)
  - A lazy grid has unloaded holes (a reorder shifts the lazy add-on's index bookkeeping)
  - The drop leaves the row where it already is

  There is no keyboard reorder.
</Callout>

<Callout type="warn" title="Position-based data goes stale">
  Search match counts and presence highlights in the original view-space `range` form reference
  positions, not row ids, so they go stale after a move — the same parity as `insertRows`.
  Presence's rowId-native range form ([Multiplayer presence](/docs/addons/presence)) tracks
  its rows through the move.
</Callout>

## Context menu

The row-operation items ship with the [context menu add-on](/docs/addons/context-menu), which installs
a right-click menu on the grid's cell and header surfaces. Right-clicking a cell makes it the
active cell with a single-cell selection before the menu opens, so the items always act on a
known target.

The cell-surface items, in order:

1. **Cut** / **Copy** / **Paste** — the native clipboard pipeline (see [Clipboard](/docs/clipboard)).
2. **Clear contents** — empties the selection to each type's `clearValue()` (the `deleteContents`
   action, <kbd>Delete</kbd>/<kbd>Backspace</kbd>).
3. **Insert row above** / **Insert row below** — anchored at the right-clicked row. Hidden without
   `createRow`.
4. **Duplicate row(s)** — <kbd>Ctrl</kbd>/<kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>X</kbd>. Hidden
   without `duplicateRow`.
5. **Delete row(s)** — destructive item, no default keyboard binding.

The row-operation items act on **every view row covered by the current selection**, falling back
to the right-clicked row when nothing is selected, so a range selection duplicates or deletes all
of its rows at once. Every mutating item (everything but Copy) is disabled on a `readOnly` grid.

Row markers, the empty space below the last row, and the scrollbar gutter have no menu (and
suppress the browser's). The header surface gets its own menu, documented on [Columns](/docs/columns).

## Programmatic actions

```tsx
import { useDataGridActions } from "@/components/data-grid/data-grid";

function MyToolbar() {
  const actions = useDataGridActions();

  return (
    <button
      onClick={() => {
        // view-space indices: [0] is the top visible row
        actions.insertRow(2, "below");
        actions.insertRows(0, 5, "above"); // a row-count dialog is one gesture, one undo step
        actions.duplicateRows([1, 2]);
        actions.deleteRows([4]);
      }}
    >
      {/* the button label is omitted */}
    </button>
  );
}
```

- `insertRow(viewRowIndex, "above" | "below")` inserts one row built by `createRow`.
- `insertRows(viewRowIndex, count, "above" | "below")` inserts `count` rows as ONE batch (one
  `onDataChange`, one history entry) instead of `count` consecutive gestures. `createRow` is
  called once per row with its landing data index. A no-op for `count <= 0`. `deleteRows`
  already takes a range, so this is the batch counterpart of a range delete.
- `duplicateRows(viewRowIndexes)` inserts each copy directly after its source row (a duplicate of
  a range lands interleaved, each after its own source).
- `deleteRows(viewRowIndexes)` deletes the named rows in one batch.

Selection behavior: insert and duplicate keep the selection, offsetting it around the inserted
rows. Delete clears the entire selection and the active cell. All three fire `onDataChange` with
`source: "row-op"` and id-keyed `insert`/`delete` ops, which is what undo/redo and export consume.

## Row markers

A pinned-left marker column sits entirely outside the data column index space. It is separate
from the `columns` array, and reorder and resize do not affect it. Set `rowMarkers` on
`DataGridProvider` (or `DataGrid`). The default is `"none"`:

<ComponentPreview name="data-grid-row-markers-demo" />

```tsx
<DataGridProvider rowMarkers="both" {...grid} columns={columns}>
```

| Mode | Shows |
|---|---|
| `"none"` | No marker column (default). |
| `"number"` | The 1-based view row index, non-interactive. |
| `"checkbox"` | A per-row checkbox that drives the rows selection channel, plus a select-all checkbox in the marker header. |
| `"both"` | The row number, replaced by the checkbox on hover or when the row is selected (a group-hover pattern). The number is never gone. The checkbox only sits in front of it at the moment the checkbox is actionable. |
| `"reorder"` | A grip handle — the whole cell is the grip zone that drag-reorders the row. No number or checkbox. |
| `"reorder-number"` / `"reorder-checkbox"` / `"reorder-both"` | The grip zone (grip handle + cell background) plus the number and/or checkbox content, which stay row-select surfaces. |

Only the `reorder` family arms the [drag-to-reorder gesture](#reorder). The plain modes are pure
row-select surfaces. Marker press and drag, in the plain modes, selects a contiguous multi-row
range that follows the pointer from the press row — dragging back over selected rows de-selects
them (contrast the header gesture, whose column range only grows). See
[Selection & keyboard](/docs/selection-keyboard#mouse-gestures). The aria-labels of the marker
column (`markers.selectAll` and `markers.selectRow`) are translatable through `labels`. See
[i18n](/docs/i18n#coverage-by-group).

Try all four modes alongside every other toggle in the [playground](/docs/playground).

### Custom markers

`DataGridRoot` and `DataGrid` accept two render slots that replace the marker column's content
while keeping its chrome and gestures:

- `renderMarker` replaces the built-in row number/checkbox in every marker cell. It receives the
  0-based `viewRowIndex` plus two independent selection signals: `isRowChannelSelected` (the rows
  channel only, so a cell click never flips it) and `isCellSelected` (the cell or column channel
  covers at least one cell of the row). A renderer can therefore tell "this row is selected" apart
  from "cells in this row are selected" and render them differently.
- `renderMarkerHeader` replaces the select-all checkbox in the marker header. It receives the
  `allSelected` state (`"checked"`, `"indeterminate"`, `"unchecked"`). In `"number"` mode there is no
  select-all checkbox, so the renderer replaces the blank header cell instead.

The `rowMarkers` mode still sets the track width (`"number"` 44px, `"checkbox"` 36px, `"both"`
56px, `"reorder"` 32px, the `reorder-` family 48–64px), and `"none"` renders no marker column
at all, so neither renderer is ever called. The
cell's own press and drag row-selection gesture stays on the wrapper: with a custom renderer,
clicking or dragging a marker cell still selects rows.

```tsx
import { Check, Circle, List, ListChecks, Minus } from "lucide-react";
import { useDataGridActions, type MarkerCellRenderer, type MarkerHeaderRenderer } from "@/components/data-grid/data-grid";
import { Button } from "@/components/ui/button";

const renderMarker: MarkerCellRenderer = ({ isRowChannelSelected, isCellSelected }) => (
  <span className="flex size-5 items-center justify-center">
    {isRowChannelSelected ? (
      <Check className="size-3.5 text-muted-foreground" aria-hidden="true" />
    ) : isCellSelected ? (
      <Minus className="size-3.5 text-muted-foreground" aria-hidden="true" />
    ) : (
      <Circle className="size-3.5 text-muted-foreground" aria-hidden="true" />
    )}
  </span>
);

function SelectAllMarker({ allSelected }: { allSelected: "checked" | "indeterminate" | "unchecked" }) {
  const { setAllRowsSelected } = useDataGridActions();
  const checked = allSelected === "checked";
  return (
    <Button
      type="button"
      variant="ghost"
      size="icon"
      aria-label={checked ? "Unselect all rows" : "Select all rows"}
      onClick={() => setAllRowsSelected(!checked)}
    >
      {checked ? <ListChecks aria-hidden="true" /> : <List aria-hidden="true" />}
    </Button>
  );
}

const renderMarkerHeader: MarkerHeaderRenderer = (ctx) => <SelectAllMarker {...ctx} />;
```

Define both renderers at module scope (stable identity, the same rule as `getRowClassName`, see
[Performance](/docs/performance#keeping-it-fast)) — a component-body function re-renders every
marker cell on every root update.

The built-in checkboxes carry the translatable `labels.markers.*` aria-labels. A custom renderer
with interactive content must supply its own accessible name on that content.

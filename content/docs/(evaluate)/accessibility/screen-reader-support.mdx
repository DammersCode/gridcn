How does the grid present itself to a screen reader? It follows the WAI-ARIA grid pattern. This page lists the roles and counts, the focus rules, the loading state, and the live regions. [Keyboard test coverage](/docs/accessibility/keyboard-test-coverage) lists what the tests check. [Accessibility gaps](/docs/accessibility/accessibility-gaps) lists what they leave out.

## Conformance target [#conformance-target]

The target is WCAG 2.1 AA. gridcn makes no conformance claim, and no conformance audit has run. The automated checks run axe-core in Chromium on two core fixtures and the saved-views menu. One fixture has a toolbar, markers, a pinned row, and a sort. One has column groups. The repository records no manual pass with a screen reader.

## Roles and indices [#semantics]

### Roles [#grid-semantics]

The scroll root has `role="grid"`. Each rendered row has `role="row"`. Each data cell has `role="gridcell"`. Each column header has `role="columnheader"`.

The marker column holds `gridcell` cells and a `columnheader` with a screen-reader-only label (`labels.markers.columnHeader`). A checkbox cell is a display-only `role="checkbox"` with `aria-checked`. Its `aria-label` is the column `headerText`, a string header, or the column id.

### Counts and indices [#the-aria-index-and-count-model]

`aria-rowcount` and `aria-colcount` sit on the grid root. `aria-rowindex` sits on rows (1-based). `aria-colindex` sits on cells and column headers.

`aria-rowcount` includes the header rows, both pinned-row bands, and every row of the view, rendered or not. A screen reader announces the true total. The rows follow this order:

| Position | Rows |
|---|---|
| First | Header rows: one per group level, then the column header row. |
| Second | Pinned-top rows. |
| Third | Data rows. |
| Last | Pinned-bottom rows. |

With column groups, each header row has `aria-rowindex`. A grid without groups has one header row and no `aria-rowindex` on it. A group header has `aria-colindex` for its first column and `aria-colspan` for the columns it covers. A column that spans several header rows has `aria-rowspan`.

The marker column sits outside this index space. It has no `aria-colindex`. `aria-colcount` counts the visible data columns only. Virtualization mounts a subset of columns, and each mounted cell keeps its true `aria-colindex`.

### Sort and state [#sort-and-read-only-state]

A sortable column header has `aria-sort` set to `ascending`, `descending`, or `none`. The attribute appears in every `headerClickBehavior` mode. The visual arrow shows on every sorted column with a string header. In `"sort"` mode, it shows on the other sortable columns too. A column with `sortable: false` has no `aria-sort`.

With `readOnly`, the root has `aria-readonly`. While any of `enableRangeSelection`, `enableRowSelection`, `enableColumnSelection`, or `enableMultiRange` is true, the root has `aria-multiselectable`. All four default to `true`.

A cell with a validation error has `aria-invalid="true"` and the message in `aria-description`. While the cell is in edit mode, the message also shows in an element with `role="alert"`.

## Focus, selection, and loading [#selection-and-editor]

### Roving tabindex [#roving-tabindex]

The grid uses the roving tabindex pattern. Before a cell is active, a grid with rows gives the root `tabindex="0"`, and the root is the one tab stop. Once a cell is active, that cell alone has `tabindex="0"`. The other cells have `-1`, and the root drops to `-1`.

DOM focus follows the active cell. The grid keeps the active row mounted after it scrolls out of view, so focus stays in place. Pinned-row cells and skeleton cells have no `tabindex`.

### Selection [#selection-announcement-model]

The active cell and every cell of a range, a checked row, or a selected column has `aria-selected="true"`.

A checked row has `aria-selected="true"` on the row. A cell range does not set it. With a checkbox marker (`rowMarkers` is `"checkbox"`, `"both"`, `"reorder-checkbox"`, or `"reorder-both"`), an unchecked row has `aria-selected="false"`. Without one, an unchecked row has no `aria-selected`.

### Editors [#editor-focus-behavior]

A text editor is a native `<input>` inside the `gridcell`, so a screen reader reads it as a form field. Select and date editors open a popup. When the editor closes, focus returns to the cell. If a commit moved focus to a control outside the grid with Tab, focus stays on that control.

### Loading state [#aria-busy-and-loading]

- The root has `aria-busy="true"` while `loading` is true.
- With `loading` and zero rows, the skeleton block has `role="presentation"` and an `aria-label` from `labels.grid.loading`.
- With `loading` and rows present, a slim bar shows. The bar is hidden from the accessibility tree. A visually hidden `role="progressbar"` outside the grid announces it, with `aria-label` and `aria-valuetext` from `labels.grid.loading`.
- A custom `loadingState` replaces the skeleton or the bar. The grid adds no role, label, or progressbar. The node owns its accessibility.
- In scroll mode, a row and its cells that have not arrived have `aria-busy="true"`.

## Live regions [#live-regions]

Each grid adds one live region: a `role="status"` element with `aria-live="polite"`. A live region cannot sit inside `role="grid"`, so the grid places it in `<body>`. The region reads these changes:

- A row move, for example "Row 3 moved to position 4 of 8" (`labels.markers.reorderAnnouncement`).
- The number of checked rows after a check, an uncheck, or Escape, for example "3 rows checked" (`labels.grid.rowsChecked`). The count includes hidden checked rows.
- "All matching rows checked" after select all matching on a result of unknown size (`labels.grid.allMatchingChecked`).

The region waits 500 ms after the last change. A marker range drag gets one reading, with its final count. A repeat of the same change gets the same text again.

With `announceResults`, the region also reads the number of rows of the view after a client filter or sort change, for example "42 rows" (`labels.grid.resultsCount`). A filter change that keeps the same rows in the same order stays quiet. Every sort change announces. A mount stays quiet. In scroll mode, while some rows have not arrived, the region counts the loaded rows only, for example "42 loaded rows" (`labels.grid.resultsCountLoaded`). With client pagination, the count covers the rows of the current page.

A server sort or a server filter stays quiet. A client filter announces under `sortMode="server"`. With `announceResults` in a server grid, a new numeric `totalRowCount` becomes the result count.

`announceResults` is a `boolean` prop of the grid. The default is `false`. The props table of [Checked rows](/docs/selection-shortcuts/checked-rows) lists it.

Add-ons bring their own live regions:

- The toolbar search reads its match count.
- The filter menu and the sort list read each reorder, for example "Name filter moved to position 2 of 3" (`labels.toolbar.filterReorderAnnouncement`, `labels.sort.sortReorderAnnouncement`).
- The find and replace panel and the status bar read their status text.
- The header filter and the value list of an `isAnyOf` filter read their status text.

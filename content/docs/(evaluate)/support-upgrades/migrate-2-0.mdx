Release 2.0 renames the save APIs, replaces the `data-grid-lazy` add-on with `data-grid-server`, and changes some defaults of selection, filters, and pushes. Until 2.0 has a tag, the [changelog](https://github.com/DammersCode/gridcn/blob/main/CHANGELOG.md) lists these changes under Unreleased.

Before you start, upgrade to 1.3.0 and commit your work. For an older version, first apply the **Breaking:** entries up to 1.3.0.

## Steps [#steps]

1. Reinstall the core and each add-on that you use, as [Upgrade gridcn](/docs/support-upgrades/upgrade-gridcn) shows.
2. If you used `data-grid-lazy`, install `data-grid-server` and move the grid to it. See [Server rows](#server-rows).
3. After the move, delete the `components/data-grid-lazy/` folder. A reinstall does not remove it.
4. Rename the identifiers in the tables below.
5. Check each behavior change below, and the [changed defaults](#changed-defaults).
6. Run `npx tsc --noEmit` and your tests. A removed or renamed export fails the type check.

### Changed defaults [#changed-defaults]

- A grid with a `totalRowCount` prop defaults `sortMode` and `filterMode` to `"server"`. Set `sortMode="client"` and `filterMode="client"` to keep the 1.3 behavior.
- Every body cell carries an integer `z-index`. A `z-*` class from `cellClassName` or `getCellClassName` does not change its stacking. Portal a popup that must sit above other cells. See [Style contract](/docs/contracts/style-contract).

### Callback timing [#callbacks]

In 1.3, `onSortChange`, `onFilterChange`, and `onSearchTextChange` fired before the write, and a throw stopped it. In 2.0, a callback fires after the write. A throw keeps the write, and the grid rethrows it after the other [callbacks](/docs/events-state/event-shapes#callback-errors).

### Labels [#labels]

`labels.contextMenu.pasteBlocked` and `clipboardFailed` can be a function of the modifier key. Handle both forms where you read them.

## Save APIs [#save-apis]

| 1.3 | 2.0 |
| --- | --- |
| `onWriteRejected` | `onSaveRejected`. Its context adds `error`. |
| `WriteAck`, `WriteRejection`, `RowWriteStatus` | `SaveAck`, `SaveRejection`, `RowSaveStatus` |
| `useDataGridRowWriteStatus`, `useDataGridPendingWriteCount` | `useDataGridRowSaveStatus`, `useDataGridPendingSaveCount` |
| `clearWriteStatus` | `clearSaveStatus` |
| `data-write-status` row attribute | `data-save-status` |
| `writeStatus`, `pendingWriteCount` store fields | `saveStatus`, `pendingSaveCount` |

## Server rows [#server-rows]

`useDataGridServerRows({ mode: "scroll" })` from `data-grid-server` replaces `useDataGridLazyRows` and `useDataGridInfiniteRows`. `DataGridLazyGuard` has no replacement. If a client sort or filter changes over unloaded rows, the core warns in development.

| 1.3 | 2.0 |
| --- | --- |
| `fetchRows` resolves the rows | `fetchRows(request)` resolves `{ rows, totalRowCount?, hasMore?, nextCursor? }` |
| `total`, `hasNextPage` | `totalRowCount`, `hasMore` in the answer |
| `batchSize`, `pageSize` | `blockSize` |
| `reset()`, `isLoading` | `refresh()`, `loading` |
| `LazyFetchContext` | `ServerRowsRequest` |
| `Range`, `ServerSpec`, `serverSpecKey` from `data-grid-lazy` | `RowRange`, `ServerSpec`, `serverSpecKey` from `data-grid` |
| `spec.search` | `spec.searchText`, also in `defaultSpec` |
| `maxFetchRows` | none. Each request covers one block. |

The hook owns the spec. Remove your `spec`, `sortMode`, `filterMode`, and `onRenderedRowsChange` wiring, and spread `server.gridProps`:

```tsx
"use client";

import { DataGrid, defineColumns } from "@/components/data-grid/data-grid";
import {
  useDataGridServerRows,
} from "@/components/data-grid-server/data-grid-server";

type Order = { id: string; customer: string };

const columns = defineColumns<Order>()([
  { id: "customer", header: "Customer", accessorKey: "customer" },
]);

export function OrdersGrid() {
  const server = useDataGridServerRows<Order>({
    mode: "scroll",
    blockSize: 100,
    fetchRows: async ({ start, end, signal }) => {
      const query = `offset=${start}&limit=${end - start}`;
      const response = await fetch(`/api/orders?${query}`, { signal });
      const answer = await response.json();
      return { rows: answer.rows, totalRowCount: answer.total };
    },
  });

  return <DataGrid {...server.gridProps} columns={columns} className="h-96" />;
}
```

Scroll mode starts a block request after `loadDelay` milliseconds (default 100). Pass `loadDelay: 0` for the 1.3 timing. It keeps at most `maxLoadedRows` rows (default 10,000). `Infinity` keeps every row.

### Pushes and row operations [#pushes]

- A `source: "stream"` call of `updateCells` or `updateRows` skips a row whose save is in flight (reason `"saving"`). Push again after the save settles.
- A stream call takes at most 100,000 patches. The rest skip as `"limit"`.
- A stream call of `updateCells`, `updateRows`, or `deleteRowsById` writes into a `readOnly` grid and read-only columns and rows. Pass `source: "edit"` to keep the read-only checks.
- In a scroll-mode grid, `deleteRows`, `duplicateRows`, `insertRow`, and `insertRows` do nothing if the target touches an unloaded row. Delete known rows with `deleteRowsById`.

## Pagination [#pagination]

- `useDataGridPagination` pages an array on the client and returns `{ pageData, pager }` in place of `{ pageData, controls }`. Its `pageSize` needs `onPageSizeChange`, and `defaultPageSize` seeds the size.
- For server pages, call `useDataGridServerPager({ page, pageSize, totalRowCount, hasMore, onPageChange })`. It returns `{ pager }` and hides the size select without `onPageSizeChange`.
- `total` is `totalRowCount` in the server options, `pager`, and `useDataGridUrlPagination`. `null` marks an unknown size.
- `reconcilePage` is gone. A server page outside the range calls `onPageChange` once with the clamped page.
- To page the grid view, set `pageSize` on the provider instead of `pageData`.

## Filters [#filters]

- A `fetchFilterValues` entry is `{ value, label?, count? }`. Rename its `label` to `value`. Add `label` only for other display text.
- The `search` field of the `fetchFilterValues` context is `query`.
- `FilterOperator` accepts any string. A `switch` over it needs a default branch. `BuiltInFilterOperator` is the closed set.
- A grid that a filter or the search empties shows `labels.grid.noResults` ("No results"). Set that label to keep "No rows".

## Selection [#selection]

- The header checkbox, the row marker checkboxes, `aria-selected`, Ctrl+Shift+Space, and the "3 rows checked" announcement read the checked rows only. Ctrl+A selects cells and checks no rows. To check every row from code, call `setAllRowsSelected(true)`.
- `DataGridSelectedRows.count` and `labels.statusBar.allSelected` take `null` for an unknown size.
- `checkedRowsLifetime` replaces `keepCheckedRows` and `keepHiddenCheckedRows`. Map your props like this:

| 1.x props | 2.0 prop |
|---|---|
| neither | the default: `"until-click"`, or `"across-filters"` with `totalRowCount` |
| `keepCheckedRows` | `checkedRowsLifetime="until-cleared"` |
| `keepCheckedRows` and `keepHiddenCheckedRows` | `checkedRowsLifetime="across-filters"` |
| `keepHiddenCheckedRows` alone | Drop it. It had no effect. |
| `totalRowCount` with `keepCheckedRows` | `checkedRowsLifetime="until-cleared"` |

## Removed exports [#removed-exports]

Twelve names leave the `data-grid` barrel: `useDataGridRowCount`, `useDataGridHasActiveCell`, `useDataGridIsSearchMatch`, `useDataGridIsRowSelected`, `useDataGridIsRowChannelSelected`, `useDataGridIsRowCellSelected`, `useDataGridAllRowsSelected`, `useDataGridHeaderClickBehavior`, `useDataGridRowMarkers`, `useDataGridSelectionConfig`, `deepMergeLabels`, and `measureTextWidths`. A [`createDataGridSelector`](/docs/types-hooks/store-hooks#createdatagridselector) hook reads the same values. An add-on imports `useDataGridSelectionConfig` from `data-grid-sdk`.

The `data-grid-pagination` barrel drops `pageCount`, `clampPage`, `pageRange`, `pageWindow`, and `DEFAULT_PAGE_SIZES`. The toolbar, io, and keybindings barrels drop untaught helpers such as `operatorLabel` and `downloadBlob`.

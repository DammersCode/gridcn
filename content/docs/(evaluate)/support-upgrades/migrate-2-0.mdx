Release 2.0 replaces the `data-grid-lazy` add-on with `data-grid-server` and changes some defaults of selection, filters, and pushes. [Changelog](https://github.com/DammersCode/gridcn/blob/main/CHANGELOG.md) lists every breaking change.

Upgrade to 1.3.0 and commit your work first. For an older version, apply the **Breaking:** entries up to 1.3.0.

## Steps [#steps]

1. Reinstall the core and each add-on that you use, as [Upgrade gridcn](/docs/support-upgrades/upgrade-gridcn) shows.
2. If you used `data-grid-lazy`, move the grid to `data-grid-server` as [Server rows](#server-rows) shows. Then delete the `components/data-grid-lazy/` folder, which a reinstall does not remove.
3. Rename the identifiers in the tables below, and check each behavior change and the [changed defaults](#changed-defaults).
4. Run `npx tsc --noEmit` and your tests. A removed or renamed export fails the type check.

### Changed defaults [#changed-defaults]

- If you add `totalRowCount`, `sortMode` and `filterMode` default to `"server"`. Set both to `"client"` to sort or filter the window in the browser.
- Text sorts use the `locale` prop, then `"en-US"`, not the runtime language. The tag sets text range filters and value lists too. Pass it on server and browser.
- `pasteFromClipboard` <NewBadge /> resolves `"refused"` when the grid starts no paste, where 1.3 resolved `"empty"`. `"empty"` means no text on the clipboard.
- `labels.contextMenu.pasteBlocked` and `clipboardFailed` can be a function of the modifier key. Handle both forms where you read them.
- Every body cell carries an integer `z-index`, so a `z-*` class from `cellClassName` or `getCellClassName` does not change its stacking. Portal a popup that must sit above other cells.

### Callback timing [#callbacks]

In 1.3, `onSortChange`, `onFilterChange`, and `onSearchTextChange` fired before the write, and a throw stopped it. In 2.0, a callback fires after the write. A throw keeps the write, and the grid rethrows it after the other [callbacks](/docs/events-state/event-shapes#callback-errors).

## Server rows [#server-rows]

`useDataGridServerRows({ mode: "scroll" })` from `data-grid-server` replaces `useDataGridLazyRows`. `DataGridLazyGuard` has no replacement. If a client sort or filter changes over unloaded rows, the core warns in development.

| 1.3 | 2.0 |
| --- | --- |
| `fetchRows(start, end, signal)` resolves the rows | `fetchRows({ start, end, signal })` resolves `{ rows, totalRowCount?, hasMore?, nextCursor? }` |
| `total` | `totalRowCount` in the answer |
| `batchSize` | `blockSize` |
| `reset()`, `isLoading` | `refresh()`, `loading` |
| `Range` from `data-grid-lazy` | `RowRange` from `data-grid` |
| `maxFetchRows` | none (one block for each request) |
| `onError(error, range)` | `onError(error)` |

Remove your `onRenderedRowsChange` and `onDataChange` wiring, and spread `server.gridProps`:

```tsx
"use client";

import { DataGrid, defineColumns } from "@/components/data-grid/data-grid";
import {
  useDataGridServerRows,
} from "@/components/data-grid-server/data-grid-server";

type Order = { id: string; customer: string };

const columns = defineColumns<Order>()([
  { id: "customer", header: "Customer", accessorKey: "customer" },
]);

export function OrdersGrid() {
  const server = useDataGridServerRows<Order>({
    mode: "scroll",
    blockSize: 100,
    fetchRows: async ({ start, end, signal }) => {
      const query = `offset=${start}&limit=${end - start}`;
      const response = await fetch(`/api/orders?${query}`, { signal });
      const answer = await response.json();
      return { rows: answer.rows, totalRowCount: answer.total };
    },
  });

  return <DataGrid {...server.gridProps} columns={columns} className="h-96" />;
}
```

Scroll mode starts a block request after `loadDelayMs` milliseconds (default 100). Pass `loadDelayMs: 0` for the 1.3 timing. It keeps at most `maxLoadedRows` rows (default 10,000). `Infinity` keeps every row.

### Pushes and row operations [#pushes]

- A stream call takes at most 100,000 patches. The rest skip as `"limit"`.
- `updateCells` and `updateRows` default to `source: "stream"`. A stream call writes into a `readOnly` grid and into read-only columns and rows, and so does `deleteRows` with `source: "stream"`. Pass `source: "edit"` to keep the read-only checks. A call without `source` into a `readOnly` grid warns once in development.
- In a scroll-mode grid, `deleteRows`, `duplicateRows`, `insertRow`, and `insertRows` do nothing when the target touches an unloaded row.

## Renamed and moved [#renamed]

| 1.3 | 2.0 |
|---|---|
| `deleteRows(viewIndexes)`, `duplicateRows(viewIndexes)` | `deleteRows(rowIds)`, `duplicateRows(rowIds)`. The `At` forms take `viewIndexes([2])`. |
| `setRowSelected`, `setAllRowsSelected` | `setRowCheckedAt`, `setAllRowsChecked`. `setRowChecked(rowId, checked)` takes an id. |
| `pin: "left"` and `"right"`, `pin-left`, `data-pinned="left"`, `data-scrolled-left`, `--grid-pin-shadow-left-x` | `start` and `end` in each name. The old `pin` values still read. |
| Def `pin` or `hidden` on a known id | Ignored. Use `setColumnPin`, `setColumnHidden`, `columnLayout`. |
| `filterOperators`, `filterMatch`, `filterCompare` | `filter: { operators, match, compare }` |
| `processFill({ values })` | `processFill({ cells })` |
| Keys of `undo`, `redo`, `fillDown`, `fillRight`, `openFind`, `openFindReplace` in the core | The add-on binds them. Your command [declares the name and binds a key](/docs/plugins/plugin-commands-shortcuts#add-on-actions). |
| `DataGridKeybindingsShortcut` | `useDataGridKeybindings()` |
| `validationMode: "warn"` drops invalid bulk values | Paste, fill, `updateCells`, and import accept them and flag them in `cellErrors`. |

## Pagination [#pagination]

- `useDataGridPagination` pages an array on the client and returns `{ pageData, pager }` in place of `{ pageData, controls }`. Its `pageSize` needs `onPageSizeChange`, and `defaultPageSize` seeds the size.
- Server mode of `useDataGridPagination` moves to `useDataGridServerPager({ page, pageSize, totalRowCount, hasMore, onPageChange })`. It returns `{ pager }` and hides the size select without `onPageSizeChange`. Its options type is `UseDataGridServerPagerOptions`.
- `total` is `totalRowCount` in the pager and in `useDataGridUrlPagination`. `null` marks an unknown size.
- `reconcilePage` is gone. A server page outside the range calls `onPageChange` once with the clamped page.
- To page the grid view, set `pageSize` on the provider instead of `pageData`.

## Filters [#filters]

- `FilterOperator` accepts any string. A `switch` over it needs a default branch. `BuiltInFilterOperator` is the closed set.
- A grid that a filter or a server search empties shows `labels.grid.noResults` ("No results"). Set that label to keep "No rows".

## Selection [#selection]

- The header checkbox, the row marker checkboxes, the row `aria-selected`, Ctrl+Shift+Space, and the "3 rows checked" announcement read the checked rows only. Ctrl+A selects cells, unchecks every checked row, and ends all matching. To check every row from code, call `setAllRowsChecked(true)`.
- `checkedRowsLifetime` replaces `keepCheckedRows` and `keepHiddenCheckedRows`. Map your props like this:

| 1.x props | 2.0 prop |
|---|---|
| neither | the default: `'until-click'`, or `'across-filters'` with `totalRowCount` |
| `keepCheckedRows` | `checkedRowsLifetime="until-cleared"` |
| `keepCheckedRows` and `keepHiddenCheckedRows` | `checkedRowsLifetime="across-filters"` |
| `keepHiddenCheckedRows` alone | Drop it. It had no effect. |

`useDataGridSelectionConfig()` and the store state return `checkedRowsLifetime` in place of `keepCheckedRows` and `keepHiddenCheckedRows`. A custom `CompactSelectionLike` implements `runs()`.

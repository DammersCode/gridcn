Each column of this grid rejects a bad value in its own way. A list above the grid names the rule of each column. Type a value that breaks a rule and press <kbd>Enter</kbd>. A blocking rule keeps the editor open and shows the message next to the cell. A soft rule commits the value and flags the cell.

## What the demo shows [#what-the-demo-shows]

- **Age** uses a function rule. It rejects a number below 18 and fires a toast from inside the function. The toast has a fixed id, so a paste with many bad cells shows one toast.
- **Email** uses a sync Standard Schema. It rejects a value without an `@`.
- **SKU** uses an async Standard Schema with about 800 ms of latency. SKU-001 and SKU-002 already exist. See [Async validation example](/docs/validation-examples/async-validation-example).
- **Price** uses a transforming schema. The text `42.9` commits as `43`, because the schema output is what the cell stores.
- **Notes** uses `validationMode: "warn"`. A note over 12 characters commits, and the cell stays flagged until a valid commit.
- **Zod Score**, **Joi Code**, and **Valibot Tag** each use a library schema. Break each one to read its message.

To try the bulk path, copy a column of mixed ages from a spreadsheet and paste it onto Age. The valid cells commit and the invalid cells drop.

## Blocking and soft rules [#blocking-and-soft-rules]

<NewBadge />

The demo lists the kind of every column above the grid. `validationMode: "warn"` makes a rule soft.

| | Blocking rule (default) | Soft rule (`validationMode: "warn"`) |
| --- | --- | --- |
| Demo columns | Age, Email, SKU, Price, Zod Score, Joi Code, Valibot Tag | Notes |
| <kbd>Enter</kbd>, <kbd>Tab</kbd>, or a click on another cell | The editor stays open | The editor closes |
| The value | Stays out of the data | Enters the data as typed |
| Message on hover | Yes, while the editor is open | Yes, always |
| Message in a line next to the cell | Yes, while the editor is open | When the user edits the flagged cell again |
| <kbd>Escape</kbd> | Cancels the edit and restores the old value. The error goes away | Cancels the edit. A flagged cell keeps its flag |
| The error ends when | The user commits a valid value, or cancels with <kbd>Escape</kbd> | The user commits a valid value |
| Paste and fill | Invalid cells drop | Invalid cells keep their value and carry a flag |

For a value that must never reach your data, such as an amount, use a blocking rule. For a value that is allowed but needs a second look, such as a long note, use a soft rule.

Every cell that shows an error also shows its message on hover, and carries it in `aria-description`. A cell that is not being edited shows a tooltip. A cell with an open editor shows the native tooltip (its `title`). It also shows the line next to the cell, so the user reads the message without a hover.

A server rejection set with `actions.setCellErrors` looks like a soft flag. It has the same ring, tint, and tooltip, and the value stays in the grid. The cell shows the line when the user opens it. The next commit of a new value clears the error. See [Server errors example](/docs/validation-examples/server-errors-example).

## Write the rules [#function-form]

`validate` takes a function that returns a message or `null`, or a Standard Schema. The grid detects a schema by its `"~standard"` key, so a library needs no adapter. This grid uses a function rule, a soft rule, and a Zod schema:

```tsx
import { z } from "zod";
import { DataGrid, defineColumns } from "@/components/data-grid/data-grid";

type Person = { id: string; age: number; note: string; score: number };

const columns = defineColumns<Person>()([
  {
    id: "age",
    header: "Age",
    accessorKey: "age",
    type: "number",
    validate: (value) =>
      typeof value === "number" && value < 18 ? "Must be 18 or older" : null,
  },
  {
    id: "note",
    header: "Note",
    accessorKey: "note",
    validate: (value) =>
      typeof value === "string" && value.length > 12 ? "Too long" : null,
    validationMode: "warn",
  },
  {
    id: "score",
    header: "Score",
    accessorKey: "score",
    type: "number",
    validate: z.number().int().min(0).max(100),
  },
]);

export function People({ people }: { people: Person[] }) {
  return (
    <DataGrid defaultData={people} columns={columns} getRowId={(p) => p.id} />
  );
}
```

Joi and Valibot schemas go in the same `validate` key. Joi rejects an empty string unless the schema adds `.empty("")`, as the Joi Code column does. A schema checks the cell value, not the row. Match the schema to the type of the column: a `number` column takes `z.number()`.

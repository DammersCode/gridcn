Each column of this grid rejects a bad value in its own way. A list above the grid names the rule of each column. Type a value that breaks a rule and press <kbd>Enter</kbd>. The editor stays open and shows the message under the cell.

## What the demo shows [#what-the-demo-shows]

- **Age** uses a function rule. It rejects a number below 18 and fires a toast from inside the function. The toast has a fixed id, so a paste with many bad cells shows one toast.
- **Email** uses a sync Standard Schema. It rejects a value without an `@`.
- **SKU** uses an async Standard Schema with about 800 ms of latency. SKU-001 and SKU-002 already exist. See [Async validation example](/docs/validation-examples/async-validation-example).
- **Price** uses a transforming schema. The text `42.9` commits as `43`, because the schema output is what the cell stores.
- **Notes** uses `onInvalid: "warn"`. A note over 12 characters commits, and the cell stays flagged until a valid commit.
- **Zod Score**, **Joi Code**, and **Valibot Tag** each use a library schema. A rejection shows the message of the library.

To try the bulk path, copy a column of mixed ages from a spreadsheet and paste it onto Age. The valid cells commit and the invalid cells drop.

## Write the rules [#function-form]

`validate` takes a function that returns a message or `null`, or a Standard Schema. The grid detects a schema by its `"~standard"` key, so a library needs no adapter. This grid uses a function rule, a soft rule, and a Zod schema:

```tsx
import { z } from "zod";
import { DataGrid, defineColumns } from "@/components/data-grid/data-grid";

type Person = { id: string; age: number; note: string; score: number };

const columns = defineColumns<Person>()([
  {
    id: "age",
    header: "Age",
    accessorKey: "age",
    type: "number",
    validate: (value) =>
      typeof value === "number" && value < 18 ? "Must be 18 or older" : null,
  },
  {
    id: "note",
    header: "Note",
    accessorKey: "note",
    validate: (value) =>
      typeof value === "string" && value.length > 12 ? "Too long" : null,
    onInvalid: "warn",
  },
  {
    id: "score",
    header: "Score",
    accessorKey: "score",
    type: "number",
    validate: z.number().int().min(0).max(100),
  },
]);

export function People({ people }: { people: Person[] }) {
  return (
    <DataGrid defaultData={people} columns={columns} getRowId={(p) => p.id} />
  );
}
```

Joi and Valibot schemas go in the same `validate` key. Joi rejects an empty string unless the schema adds `.empty("")`, as the Joi Code column does. A schema checks the cell value, not the row. Match the schema to the type of the column: a `number` column takes `z.number()`.

Some checks need a server before the grid acts. A paste can need normalizing. A new row can need an id from the server. Each of these props accepts a function that returns a value or a promise. The grid holds the gesture until the promise settles, then writes once.

In this grid, `processPaste` upper-cases pasted SKUs on the server, `createRow` waits for a server id, and `validateRow` flags a taken SKU. Paste lower-case text, add a row, or type AB-100 in the SKU column. The status line shows the pending call.

## Return a promise [#the-gates]

This provider uses the three gates of the demo:

```tsx
import {
  DataGridBody,
  DataGridHeader,
  DataGridProvider,
  DataGridRoot,
  defineColumns,
} from "@/components/data-grid/data-grid";

type Sku = { id: string; sku: string };

const columns = defineColumns<Sku>()([
  { id: "sku", header: "SKU", accessorKey: "sku" },
]);

const rows: Sku[] = [{ id: "r1", sku: "CD-100" }];

export function SkuGrid({ api }: { api: SkuApi }) {
  return (
    <DataGridProvider
      defaultData={rows}
      columns={columns}
      getRowId={(row) => row.id}
      processPaste={async ({ cells }) => api.normalize(cells)}
      createRow={async () => ({ id: await api.newId(), sku: "" })}
      validateRow={async (row) =>
        (await api.isTaken(row.sku)) ? { sku: "SKU is already taken" } : null
      }
    >
      <DataGridRoot>
        <DataGridHeader />
        <DataGridBody />
      </DataGridRoot>
    </DataGridProvider>
  );
}

type SkuApi = {
  normalize: (cells: string[][]) => Promise<string[][]>;
  newId: () => Promise<string>;
  isTaken: (sku: string) => Promise<boolean>;
};
```

## What a pending promise does [#what-the-grid-checks-when-a-promise-settles]

| Gate | A promise holds | While pending | If it rejects |
|---|---|---|---|
| `processPaste` | the whole paste | the grid ignores a second paste | the paste does not happen |
| `processCellFromClipboard` | the paste, until every cell settles | the grid ignores a second paste | the paste does not happen |
| `onBeforeEditStart` | the start of the edit | a second edit start does nothing | the edit does not start |
| `createRow` | the insert, until every row settles | a second insert does nothing | the insert does not happen |
| `duplicateRow` | the duplicate, until every copy settles | a second duplicate does nothing | the duplicate does not happen |
| `validateRow` | nothing: the write commits first | a newer verdict for the row replaces it | the row gets no verdict |
| `onBeforeDeleteRows` | the delete | the grid ignores a second delete | the delete does not happen |

`mapColumn` and the `createRow` of the import also accept a promise, and the import dialog waits for it. See [Import](/docs/import-export/import). A function that returns a plain value acts in the same call. `processPaste` returns `false` and `onBeforeEditStart` returns `false` to cancel.

The grid reads its state again when the promise settles. It discards the result without an error in these cases:

- Paste: the grid is `readOnly`, a cell is in edit, the sort or filter changed, or a target row left the data.
- Insert: the grid is `readOnly`, or the row beside the insert left the data. A duplicate skips each source row that left.
- Edit start: the grid is `readOnly`, the cell is gone, or the user moved to another cell.
- Row verdict: the row left the data.

A row that moved keeps its gesture, because the grid follows the row id. The grid ignores a second gesture of the same kind until the promise settles.

The grid also passes an `AbortSignal` to every gate. [Cancel async gates](/docs/editing-cells/cancel-async-gates) covers the signal, `gateTimeoutMs`, and the pending state.

## Client and server modes

A held gesture emits one change when the promise settles. A refetch that removes a row cancels the gesture on it, because the grid drops the result for a row that left. With `sortMode="server"`, the grid never reorders rows when a promise settles. The server owns the order. For a server grid, see the [async gates](/docs/contracts/server-rows-contract#async-gates) of the server contract.

<Callout type="warn" title="Copy stays synchronous">
  `processCellForClipboard` returns a string, not a promise. Cell `renderCell` and `accessorFn` return values, not promises.
</Callout>

`useDataGridServerRows` owns the sort, filter, search text, page, and page size of a server grid. You write the one `fetchRows` function that calls your API. The hook fetches a page for each state and aborts a request that a newer state replaces. It goes back to page 1 when the spec or the page size changes. It keeps the last good rows on screen while the next page loads, and after an error. The grid sorts and filters nothing itself.

In the demo, the Pages and Scroll buttons switch the mode of the hook. Sort a header, filter, search, and page. Each change sends one request to a fake server with about 300 ms of latency.

## What the demo shows [#whats-in-the-demo]

- Pages and Scroll switch the `mode` of the hook. Pages mode sets `prefetchNextPage`, so Next shows the next page with no wait.
- Revalidate every 10 s sets `revalidateIntervalMs` and fetches the rows again on that timer. See [Tune row retention](/docs/scroll-mode/tune-row-retention).
- Server pushes changes three scores every 500 ms with `updateRows`. A row whose score the sort reads keeps its place and turns dim and italic until a refresh places it. See [Push into a server-ordered view](/docs/rows-live-data/push-server-ordered-view).
- The Reshape select sets `reshapeDelayMs`. With Reshape off, a refresh places the pushed rows. With Reshape 1 s, the hook refreshes one second after the pushes.
- Delete on server removes the first row on the server and deletes it in the grid with `source: "stream"`.
- The grid starts sorted by Score, highest first.

## The wiring [#the-wiring]

This grid loads orders by page and saves edits through `onSave`:

```tsx
import { DataGrid, defineColumns } from "@/components/data-grid/data-grid";
import type { DataChange } from "@/components/data-grid/data-grid";
import {
  DataGridPaginationBar,
} from "@/components/data-grid-pagination/data-grid-pagination";
import {
  useDataGridServerRows,
} from "@/components/data-grid-server/data-grid-server";

type Order = { id: string; customer: string };

const columns = defineColumns<Order>()([
  { id: "customer", header: "Customer", accessorKey: "customer" },
]);

async function saveOrders(change: DataChange<Order>) {
  const response = await fetch("/api/orders", {
    method: "POST",
    body: JSON.stringify(change.ops),
  });
  if (!response.ok) throw new Error(`Save failed: ${response.status}`);
}

export function OrdersGrid() {
  const server = useDataGridServerRows<Order>({
    onSave: saveOrders,
    fetchRows: async ({ spec, page, pageSize, signal }) => {
      const response = await fetch("/api/orders/query", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ spec, page, pageSize }),
        signal,
      });
      const answer = await response.json();
      return { rows: answer.rows, totalRowCount: answer.total };
    },
  });

  return (
    <>
      <DataGrid
        {...server.gridProps}
        columns={columns}
        className="h-96"
      />
      <DataGridPaginationBar {...server.pager} />
    </>
  );
}
```

### The request and the answer [#the-request-and-the-answer]

- The request holds `spec` (`sorts`, `filters`, `searchText`), `page`, `pageSize`, `start`, `end`, `cursor`, and `signal`. `cursor` is `undefined` until a page answer returns `nextCursor`. `start` is `(page - 1) * pageSize` and `end` is `start + pageSize`.
- `fetchRows` resolves `{ rows, totalRowCount }`. A server without a count resolves `{ rows, hasMore }`. [Server rows options](/docs/add-options/server/server-rows-options#serverrowsanswer) lists how the hook checks an answer.
### What gridProps carries [#what-gridprops-carries]

- `server.gridProps` carries the data, the server sort and filter modes, the controlled spec, `totalRowCount`, `loading`, `error`, `onRetry`, `plugins`, `headerClickBehavior: "sort"`, and your `onSave`. The hook fetches again after the saves settle (`refreshAfterSave`). A header click sorts. Set `headerClickBehavior` after the spread to change that.
- Put your own `onDataChange` in the hook options. A spread override drops the merge of the hook. Put your own plugins in the `plugins` option. The hook mounts them after its refresh guard.
- A composed layout spreads `server.providerProps` onto `DataGridProvider` and `server.rootProps` onto `DataGridRoot`. The demo does this.

<Callout type="warn">
  Pass the request through `parseServerSpec(body.spec, { columns })` from `data-grid-server` before you build a query, and cap the request body size. The function throws a `ServerSpecError` for an unknown column, an unknown operator, a tree that is too large, or a long value. The [ORM examples](/docs/server-data-examples/orm-examples/drizzle-example) call it.
</Callout>

A failed request keeps the last good rows on screen and shows an error state with Retry. See [Handle failures](/docs/server-path/handle-failures).

To own the spec, the page, or the page size, pass the value with its change callback. See [Query server rows](/docs/data-modes/query-server-rows#controlled-mode-server-side-sortfilter), [Load rows by page](/docs/server-pagination/load-rows-page), and [Keep pages in URL](/docs/server-pagination/keep-pages-url).

## Delay every request [#wait-for-typing-to-pause]

Text inputs in the filter and the search box wait 200 ms (`inputDebounceMs`) after the last keystroke before they change the spec. To delay every request, wait inside `fetchRows`. The wait ends when the signal aborts:

```tsx
import type {
  UseDataGridServerRowsOptions,
} from "@/components/data-grid-server/data-grid-server";

type Order = { id: string; customer: string };

const delay = (ms: number, signal: AbortSignal) =>
  new Promise<void>((resolve, reject) => {
    const timer = setTimeout(resolve, ms);
    signal.addEventListener(
      "abort",
      () => {
        clearTimeout(timer);
        reject(signal.reason);
      },
      { once: true },
    );
  });

const fetchRows: UseDataGridServerRowsOptions<Order>["fetchRows"] = async ({
  spec,
  page,
  pageSize,
  signal,
}) => {
  await delay(300, signal);
  const response = await fetch("/api/orders/query", {
    method: "POST",
    body: JSON.stringify({ spec, page, pageSize }),
    signal,
  });
  const answer = await response.json();
  return { rows: answer.rows, totalRowCount: answer.total };
};
```

`useDataGridServerRows` owns the sort, filter, search text, page, and page size of a server grid. You write the one `fetchRows` function that calls your API. The hook fetches a page for each state and aborts a request that a newer state replaces. It goes back to page 1 when the spec or the page size changes. It keeps the last good rows on screen while the next page loads, and after an error. The grid sorts and filters nothing itself.

In the demo, the Pages and Scroll buttons switch the mode of the hook. Sort a header, filter, search, and page. Each change sends one request to a fake server with about 300 ms of latency.

## The wiring [#the-wiring]

This grid loads orders by page and saves edits through `onSave`:

```tsx
import { DataGrid, defineColumns } from "@/components/data-grid/data-grid";
import type { DataChange } from "@/components/data-grid/data-grid";
import {
  DataGridPaginationBar,
} from "@/components/data-grid-pagination/data-grid-pagination";
import {
  useDataGridServerRows,
} from "@/components/data-grid-server/data-grid-server";

type Order = { id: string; customer: string };

const columns = defineColumns<Order>()([
  { id: "customer", header: "Customer", accessorKey: "customer" },
]);

async function saveOrders(change: DataChange<Order>) {
  const response = await fetch("/api/orders", {
    method: "POST",
    body: JSON.stringify(change.ops),
  });
  if (!response.ok) throw new Error(`Save failed: ${response.status}`);
}

export function OrdersGrid() {
  const server = useDataGridServerRows<Order>({
    getRowId: (row) => row.id,
    fetchRows: async ({ spec, page, pageSize, signal }) => {
      const response = await fetch("/api/orders/query", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ ...spec, page, pageSize }),
        signal,
      });
      const answer = await response.json();
      return { rows: answer.rows, totalRowCount: answer.total };
    },
  });

  return (
    <>
      <DataGrid
        {...server.gridProps}
        columns={columns}
        headerClickBehavior="sort"
        onSave={saveOrders}
        className="h-96"
      />
      <DataGridPaginationBar {...server.pager} />
    </>
  );
}
```

- The request holds `spec` (`sorts`, `filters`, `searchText`), `page`, `pageSize`, `start`, `end`, `cursor`, and `signal`. `cursor` is `undefined` in pages mode. `start` is `(page - 1) * pageSize` and `end` is `start + pageSize`.
- `fetchRows` resolves `{ rows, totalRowCount }`. A server without a count resolves `{ rows, hasMore }`. [Server rows options](/docs/add-options/server/server-rows-options#serverrowsanswer) lists how the hook checks an answer.
- `server.gridProps` carries the data, the server sort and filter modes, the controlled spec, `totalRowCount`, `keepCheckedRows`, `loading`, `error`, `onRetry`, and `plugins`. A header click sorts only with `headerClickBehavior="sort"`.
- Treat the request as untrusted input. Check that the filter tree has at most 2 levels of groups, 16 groups, and 64 rows. Allow only known column ids, and allow only `"and"` or `"or"` as a `join`. Cap the request body size. The [ORM examples](/docs/server-data-examples/orm-examples) show the check.
- Put your own `onDataChange` in the hook options. A spread override drops the merge of the hook. A `plugins` prop of your own goes after the guard: `plugins={[...server.gridProps.plugins, mine]}`.
- A composed layout spreads `server.providerProps` onto `DataGridProvider` and `server.rootProps` onto `DataGridRoot`. The demo does this.

## Errors and retry [#errors-and-retry]

A failed request sets `server.error` and keeps the last good rows visible. `DataGridRoot` shows an error state. With no rows loaded, it is a message with a Retry button. With rows present, it is a bar under the header. The text is `labels.grid.errorState`. Pass `errorState` to replace it: a node, or a function that receives `{ error, retry }`. The grid never renders the error object.

`server.retry()` repeats the failed request and does nothing without an error. `server.refresh()` fetches the current page again and keeps the rows on screen until the answer lands. The error clears when a new request starts. `server.status` is `"loading"`, `"error"`, or `"ready"`, and `"error"` wins over `"loading"`.

`onError(error)` fires when a request fails. `onLoaded({ start, end })` fires when rows land. A throw in either goes to the console and does not drop the answer. [Change server rows](/docs/rows-live-data/change-server-rows) describes what a refresh does with a row that has a pending edit or save.

## Control the spec and the page [#control-the-spec-and-the-page]

Pass `spec` with `onSpecChange`, `page` with `onPageChange`, or `pageSize` with `onPageSizeChange` to own that state. Each pair works like a controlled input. `defaultSpec`, `defaultPage`, and `defaultPageSize` seed the state when you do not control it. A spec change asks `onPageChange` for page 1, except before the first answer lands, so a restored spec keeps a deep-linked page.

To keep the page and the page size in the URL, spread `useDataGridUrlPagination()` into the options. See [Keep pages in URL](/docs/server-pagination/keep-pages-url).

## Wait for typing to pause [#wait-for-typing-to-pause]

The hook sends one request for each state and aborts a replaced one. To also wait for typing to pause, wait inside `fetchRows`. The wait ends when the signal aborts:

```tsx
import type { UseDataGridServerRowsOptions } from "@/components/data-grid-server/data-grid-server";

type Order = { id: string; customer: string };

const delay = (ms: number, signal: AbortSignal) =>
  new Promise<void>((resolve, reject) => {
    const timer = setTimeout(resolve, ms);
    signal.addEventListener(
      "abort",
      () => {
        clearTimeout(timer);
        reject(signal.reason);
      },
      { once: true },
    );
  });

const fetchRows: UseDataGridServerRowsOptions<Order>["fetchRows"] = async ({
  spec,
  page,
  pageSize,
  signal,
}) => {
  await delay(300, signal);
  const response = await fetch("/api/orders/query", {
    method: "POST",
    body: JSON.stringify({ ...spec, page, pageSize }),
    signal,
  });
  const answer = await response.json();
  return { rows: answer.rows, totalRowCount: answer.total };
};
```

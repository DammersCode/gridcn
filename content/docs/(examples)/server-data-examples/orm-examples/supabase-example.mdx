</Callout>

A server grid sends its spec (`sorts`, `filters`, `searchText`) and a row range (`start`, `end`) to your route. The route checks the request, builds one query, and answers `{ rows, totalRowCount }`. The route reads a `users` table with an `id` column and the text columns `name`, `email`, and `role`.

## The route [#the-route]

The route follows the [server rows contract](/docs/contracts/server-rows-contract). It writes every filter as a PostgREST condition string and combines the strings with `.or()`. It rejects a request that fails the check with status 400. It adds `id` as the last sort, so no two rows tie and a page never repeats a row:

```ts fragment="needs @supabase/supabase-js"
// app/api/grid/route.ts
import { createClient } from "@supabase/supabase-js";

const supabase = createClient(
  process.env.SUPABASE_URL!,
  process.env.SUPABASE_SERVICE_ROLE_KEY!,
);

type Query = { or: (conditions: string) => Query };
const COLUMNS = new Set<string>(["name", "email", "role"]);

// A condition string splits on commas and parentheses, so quote every value.
const quote = (value: string) =>
  `"${value.replace(/\\/g, "\\\\").replace(/"/g, '\\"')}"`;
const list = (values: string[]) => `(${values.map(quote).join(",")})`;

const CLAUSES: Record<string, (c: string, v: any) => string> = {
  contains: (c, v) => `${c}.ilike.${quote(`%${v}%`)}`,
  notContains: (c, v) => `${c}.not.ilike.${quote(`%${v}%`)}`,
  startsWith: (c, v) => `${c}.ilike.${quote(`${v}%`)}`,
  endsWith: (c, v) => `${c}.ilike.${quote(`%${v}`)}`,
  equals: (c, v) => `${c}.eq.${quote(v)}`,
  notEquals: (c, v) => `${c}.neq.${quote(v)}`,
  gt: (c, v) => `${c}.gt.${quote(v)}`,
  gte: (c, v) => `${c}.gte.${quote(v)}`,
  lt: (c, v) => `${c}.lt.${quote(v)}`,
  lte: (c, v) => `${c}.lte.${quote(v)}`,
  empty: (c) => `${c}.eq.""`,
  notEmpty: (c) => `${c}.neq.""`,
  isAnyOf: (c, v) => `${c}.in.${list(v)}`,
  isNoneOf: (c, v) => `${c}.not.in.${list(v)}`,
};

function isValidLeaf(node: any): boolean {
  if (!COLUMNS.has(node?.columnId)) return false;
  if (!Object.hasOwn(CLAUSES, node.operator)) return false;
  if (node.operator === "empty" || node.operator === "notEmpty") return true;
  if (node.operator === "isAnyOf" || node.operator === "isNoneOf") {
    return Array.isArray(node.value) && node.value.length <= 1000
      && node.value.every((item: unknown) => typeof item === "string");
  }
  return typeof node.value === "string";
}

function isValidTree(nodes: any, depth = 0, budget = { left: 64 }): boolean {
  return Array.isArray(nodes) && nodes.every((node: any) => {
    if (--budget.left < 0) return false;
    if (!Array.isArray(node?.filters)) return isValidLeaf(node);
    const joins = node.join === "and" || node.join === "or";
    return joins && depth < 2 && isValidTree(node.filters, depth + 1, budget);
  });
}

const isValidSort = (sort: any) =>
  COLUMNS.has(sort?.columnId) &&
  (sort.direction === "asc" || sort.direction === "desc");

function isValidRequest(body: any): boolean {
  const { spec, start, end } = body ?? {};
  const { sorts, filters, searchText } = spec ?? {};
  return (
    Number.isSafeInteger(start) && start >= 0 && start <= 10_000_000 &&
    Number.isSafeInteger(end) && end > start &&
    typeof searchText === "string" && searchText.length <= 200 &&
    Array.isArray(sorts) && sorts.length <= 8 && sorts.every(isValidSort) &&
    isValidTree(filters)
  );
}

const isEmptyGroup = (node: any) =>
  Array.isArray(node.filters) && node.filters.length === 0;

function clause(node: any): string {
  if (!Array.isArray(node.filters)) {
    return CLAUSES[node.operator](node.columnId, node.value);
  }
  return `${node.join}(${node.filters.map(clause).join(",")})`;
}

// An empty group matches every row, so an "or" with one adds no condition.
function orClause(group: any): string {
  if (group.filters.some(isEmptyGroup)) return "";
  return group.filters.map(clause).join(",");
}

// The top level combines with "and": an "and" group flattens into it.
function applyNode(query: Query, node: any): Query {
  if (!Array.isArray(node.filters)) return query.or(clause(node));
  if (node.join === "and") return node.filters.reduce(applyNode, query);
  const text = orClause(node);
  return text ? query.or(text) : query;
}

export async function POST(request: Request) {
  const body = await request.json().catch(() => null);
  if (!isValidRequest(body)) {
    return new Response("Invalid request", { status: 400 });
  }

  const { spec, start, end } = body;
  const limit = Math.min(end - start, 500);
  let query = supabase.from("users").select("*", { count: "exact" });
  if (spec.searchText) {
    const pattern = quote(`%${spec.searchText}%`);
    query = query.or(`name.ilike.${pattern},email.ilike.${pattern}`);
  }
  query = spec.filters.reduce(applyNode, query);
  for (const sort of spec.sorts) {
    query = query.order(sort.columnId, { ascending: sort.direction === "asc" });
  }
  query = query.order("id");

  const { data, count, error } = await query.range(start, start + limit - 1);
  if (error) throw new Error(error.message);
  return Response.json({ rows: data, totalRowCount: count });
}
```

About the sample:

- `range(from, to)` includes both ends, hence the `- 1`.
- The grid compares text without case. The sample uses `ilike` for the pattern operators only.
- In `ilike` patterns, `%`, `_`, and `*` in the user text act as wildcards.
- The grid keeps at most two group levels in a filter tree. The check refuses a deeper tree.
- The sample sets the other caps, not the grid: 8 sorts, 200 characters of search text, 64 filters and groups, and 1,000 list values. A request over a cap gets status 400.
- Number and date columns also get `isBetween`, with a `[min, max]` pair in which either bound can be `""`. The sample refuses it. Map it before you add such a column.
- The grid's `empty` also matches a null cell. The sample compares with `""`, so a nullable column needs an `IS NULL` test too.
- The route caps a page at 500 rows. Keep the page size at or below 500. A larger page returns fewer rows than the grid asked for.

<Callout type="warn" title="Keep the key on the server">
The service role key bypasses row-level security, so read it only in the route. With the anon key, add a read policy on `users`. Check every column id against `COLUMNS` and quote every value, or a crafted request adds conditions to the query. Cap the body size at the framework or proxy, because the tree limits do not bound a large JSON text.
</Callout>

The client is the one in the [Drizzle example](/docs/server-data-examples/orm-examples/drizzle-example#the-client), and the same section covers [shareable state](/docs/server-data-examples/orm-examples/drizzle-example#shareable-state). Edits go through `onSave` and a `supabase.from("users").update(...)` call.

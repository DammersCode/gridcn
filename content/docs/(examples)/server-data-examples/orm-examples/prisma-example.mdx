A server grid sends its spec (`sorts`, `filters`, `searchText`) and a row range (`start`, `end`) to your route. The [query layer](/docs/data-modes/query-layer) checks the request and runs it with the Prisma Client object API on PostgreSQL or SQLite. This route serves a `User` model with an integer `id`, a nullable `name`, and a `tenantId`.

## The route [#the-route]

Prisma has no data model at run time, so you write the column map by hand. `definePrismaColumnMap` types it by the generated model: `nullable: true` must sit exactly on the fields that admit `null`. A request that fails the check gets status 400:

```ts title="lib/users-query.ts"
import { createPrismaGridQuery, definePrismaColumnMap } from "@/components/data-grid-server-query-prisma/data-grid-server-query-prisma";
import { Prisma, type User } from "./generated/prisma/client";
import { prisma } from "./db";

const columns = definePrismaColumnMap<User>()(Prisma.UserScalarFieldEnum, {
  id: { type: "number", numeric: "int4", primaryKey: true },
  name: { type: "text", searchable: true, nullable: true },
  tenantId: { type: "number", numeric: "int4", serverOnly: true },
});

export const usersQuery = createPrismaGridQuery<User, { tenantId: number }>({
  model: prisma.user,
  provider: "postgresql",
  columns,
  rowScope: (session) => ({ tenantId: session.tenantId }),
});
```

```ts title="app/api/grid/route.ts"
import { handleGridRequest } from "@/components/data-grid-server-query/data-grid-server-query";
import { getSession } from "./session";
import { usersQuery } from "./users-query";

export const POST = async (req: Request) => {
  const session = await getSession(req);
  if (!session) return new Response(null, { status: 401 });
  return handleGridRequest(req, usersQuery.fetchRows, { context: session });
};
```

The client is the one in the [Drizzle example](/docs/server-data-examples/orm-examples/drizzle-example#the-client).

## What Prisma declines [#declines]

The adapter refuses, before any call, a request that the object API has no exact form for. It answers `unsupported` and never returns wrong rows:

- A pivot on PostgreSQL whose pivot column is a native enum or uuid. Prisma orders such a column by its type, and the other adapters order it as text.
- A pivot on SQLite with `sum`, `min`, or `max` of a decimal column. Prisma's SQLite driver reads an aggregate in the type of its first row, so it would cut `12.5` to `12`.
- On SQLite: case-insensitive `equals` and set filters, case-sensitive LIKE filters, and excluded ids on a uuid key. A `%` or `_` in a LIKE filter answers `unsupported-value`.
- On PostgreSQL: a cursor sort on a `time` column, and grouping by a `time` column.
- LIKE filters on a native enum or uuid column.
- Set values of a `time` column or of text without `caseSensitive`, and a value query on a column that is not text.
- `min`, `max`, and `count` of text without `keepBlankText`.

Each statement also counts its bound values. Past the budget of the provider (PostgreSQL 32,766, SQLite 999), the adapter answers `limit-exceeded`. On SQLite, a selection of about 990 ids or excluded ids is over it. Group counts read one extra `groupBy` of at most `maxGroupRows` rows (default 10,000), and more answer `limit-exceeded`. A pivot reads its keys the same way, so a pivot column with more than `maxGroupRows` keys answers `limit-exceeded`. A pivot page whose groups times its kept keys exceed 40,000 also answers `limit-exceeded`.

## Cursors, selection, and saves [#more-routes]

- [Page queries by cursor](/docs/scroll-mode/page-queries-cursor): with `paging: "cursor"`, every sortable text column needs `maxLength`, and a sortable native enum throws at creation. `maxCursorBytes` (default 2,048) bounds the cursor.
- [Query the selected rows](/docs/rows-live-data/query-selected-rows): an id list renders `in` or `notIn` within the bound-value budget.
- [Validate server saves](/docs/save-server/validate-server-saves): each `where` holds the row id and `rowScope`. Run every write of a change in one `prisma.$transaction`.

This `apply` writes the updates and the deletes of a change:

```ts title="app/api/grid/save/route.ts" fragment="db is your Prisma client, which types tx"
import { handleGridRequest, type ApplyChange } from "@/components/data-grid-server-query/data-grid-server-query";
import type { PrismaWhere } from "@/components/data-grid-server-query-prisma/data-grid-server-query-prisma";
import { prisma } from "./db";
import { getSession } from "./session";
import { usersQuery } from "./users-query";

const apply: ApplyChange<PrismaWhere, { tenantId: number }> = (change) =>
  prisma.$transaction(async (tx) => {
    if (change.inserts.length > 0 || change.moves.length > 0) {
      throw new Error("Users have no inserts or row order");
    }
    const updates: number[] = [];
    for (const { where, values } of change.updates) {
      const result = await tx.user.updateMany({ where, data: values });
      updates.push(result.count);
    }
    const deletes: number[] = [];
    for (const { where } of change.deletes) {
      deletes.push((await tx.user.deleteMany({ where })).count);
    }
    return { updates, deletes, moves: [] };
  });

export const POST = async (req: Request) => {
  const session = await getSession(req);
  if (!session) return new Response(null, { status: 401 });
  return handleGridRequest(req, usersQuery.save(apply), { context: session });
};
```

A count of 0 answers `not-found` for that row. The written values are native: an `int8` is a `BigInt`, a date is a `Date`, and a decimal is text.

`useDebouncedInput` drives a text input. The input shows each keystroke at once. `onCommit` runs once with the text of the input, after the typing pauses. The toolbar search, the filter value inputs, find and replace, and the lookup editor use the hook.

<InstallCommand item="use-debounce" />

The hook ships in the `use-debounce` item, next to [`useDebounce`](/docs/types-hooks/use-debounce).

## useDebouncedInput [#usedebouncedinput]

```ts fragment="signature"
function useDebouncedInput(
  value: string,
  onCommit: (next: string) => void,
  options?: UseDebouncedInputOptions,
): UseDebouncedInputResult;
```

`value` is the text that the parent holds. Spread `inputProps` on an `input` or a `textarea`:

```tsx
import { useState } from "react";
import { useDebouncedInput } from "@/components/gridcn/use-debounce";

export function NameInput() {
  const [name, setName] = useState("");
  const input = useDebouncedInput(name, setName);
  return <input {...input.inputProps} />;
}
```

`name` changes 300 ms after the last keystroke. The input shows the typed text meanwhile.

To run your own handler too, spread `getInputProps({ onKeyDown })` in place of `inputProps`. Your handler runs first, then the one of the hook. A handler that you place after a plain `inputProps` spread replaces the one of the hook.

## Options [#options]

{/* props: UseDebouncedInputOptions */}

| Option | Type | Description | Default |
| --- | --- | --- | --- |
| `delayMs` | `number` | Wait after the last keystroke before `onCommit` runs. `0` calls `onCommit` on each keystroke. | `300` |
| `applyTimeoutMs` | `number` | Wait after the last commit for `value` to reach a committed text. Then the input shows `value` again. `Infinity` keeps the typed text. | `1000` |

## Result [#result]

{/* props: UseDebouncedInputResult */}

| Member | Type | Meaning |
| --- | --- | --- |
| `inputProps` | `DebouncedInputProps` | The props to spread: `value`, `onChange`, `onBlur`, `onKeyDown`, `onCompositionStart`, and `onCompositionEnd`. |
| `getInputProps` | `(own?) => DebouncedInputProps` | `inputProps` with the handlers in `own` chained. Each handler in `own` runs first, then the one of the hook. Other props in `own`, such as `className`, pass through. |
| `inputValue` | `string` | The text in the input. It equals `inputProps.value`. |
| `flush` | `() => void` | Calls `onCommit` with a pending value at once. |
| `cancel` | `() => void` | Drops a pending value and shows `value` again. |

## When onCommit runs [#when-the-value-commits]

- Blur calls `onCommit` with a pending value.
- <kbd>Enter</kbd> does the same.
- Unmount does the same, so closing a popover during the wait keeps the last keystrokes.
- <kbd>Escape</kbd> drops a pending value and shows `value` again. It does not call `onCommit`.
- During an IME composition (text that an input method editor builds, see [isComposingKey](/docs/types-hooks/is-composing-key)), the wait does not run, and <kbd>Enter</kbd> and <kbd>Escape</kbd> do nothing. When the composition ends, the hook schedules the call. Blur and unmount still call `onCommit` with the text so far.
- The call goes to the `onCommit` of the most recent render.

## What the input shows [#what-the-input-shows]

- While text is pending, the input keeps the text. When nothing is pending, a change of `value` from outside shows in the input.
- A committed text is a text that `onCommit` received. After `onCommit` runs, the input keeps the typed text until the parent applies the committed texts. When `value` changes to a text that `onCommit` did not receive, the input shows `value`.
- If the user types a committed text again, the echoes in between can show for a moment. The input ends on the typed text.
- If `value` reaches no committed text within `applyTimeoutMs`, the input shows `value`.
- The hook remembers the last 64 committed texts that the parent has not applied. A late echo of one of them does not replace newer typing. The echo of an older text counts as a change from outside.

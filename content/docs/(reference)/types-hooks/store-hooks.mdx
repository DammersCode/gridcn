Store hooks read the state of one grid. Inside a `DataGridProvider` they work. Outside it, they throw. Two items differ: `useDataGridStoreProps` runs outside the provider and creates the store, and `createDataGridSelector` is a factory that you call once at module scope. Import them from `@/components/data-grid/data-grid`. A hook that reads state subscribes to its own slice, so a component re-renders only when that slice changes.

## Handle and actions [#handle]

Hooks that reach the grid from code.

| Hook | Returns | Meaning |
| --- | --- | --- |
| <a id="usedatagridactions"></a>`useDataGridActions` | `DataGridActions` | The actions object. Its identity never changes, so the hook never re-renders. [Actions A to Z](/docs/cheatsheets-messages/actions-z) lists each action. |
| <a id="usedatagridapi"></a>`useDataGridApi` | `DataGridApi<TData>` | The imperative handle. `useDataGridApi(ref?)` returns the handle. Pass a `ref` to also assign it to that ref. Its identity is stable for the grid's lifetime. |
| <a id="usedatagridstoreprops"></a>`useDataGridStoreProps` | `{ store, actions }` | Creates the store outside the provider. Feed `store` to `DataGridProvider`. |
| <a id="usedatagridscrolltocell"></a>`useDataGridScrollToCell` | `(ref: CellRef) => void` | Scrolls a cell into view. It does nothing before `DataGridRoot` mounts, and warns in development for a ref that does not resolve. |
| <a id="usedatagridscrolltocellat"></a>`useDataGridScrollToCellAt` | `(coord: ViewCoord) => void` | The same scroll for a view coordinate. |
| <a id="usedatagridclipboard"></a>`useDataGridClipboard` | `UseDataGridClipboardResult` | Returns `copy`, `cut`, and `pasteFromClipboard`. `copy` and `cut` resolve `"ok"`, `"fallback"`, `"failed"`, or `"no-selection"`. `cut` also resolves `"refused"` while a cell editor is open. `pasteFromClipboard` resolves a `PasteFromClipboardResult`: `"ok"`, `"permission-denied"`, `"empty"` (the clipboard holds no text), or `"refused"` (the grid started no paste, as [Clipboard](/docs/clipboard-undo/clipboard) lists). The hook takes an optional `{ sanitizeFormulas }`. Its default is the `sanitizeClipboardFormulas` prop. |

These actions have no feature page:

- `setActiveCellAt` sets the active cell at a `ViewCoord`, or clears it with `null`.
- `extendToAt` extends the selection to the cell at a `ViewCoord`.
- `extendSelection` grows the selection by one cell in a direction (`"up"`, `"down"`, `"left"`, `"right"`), or to the edge with `{ toEdge: true }`. It does nothing when `enableRangeSelection` is `false`.
- `pushRangeAt` adds a range to the cell at a `ViewCoord`, like a Ctrl/Cmd+click. Without `enableMultiRange`, it selects the cell like a click.
- `checkRowRange` checks or unchecks the rows from the anchor row to a view row index. It does nothing when `enableRowSelection` is `false`.
- `clearCellSelection` clears the cell range and the selected columns and keeps the checked rows.
- `commitCellEdit` validates and commits the value of the open edit, then moves the active cell by an optional `{ dx, dy }`. A rejected value keeps the edit open and sets the editing error.
- `commitCellValueAt` validates and writes a value at a `ViewCoord` without an edit session, like a checkbox click.
- `deleteSelection` clears every writable cell of the selection to the empty value of its cell type, as one change.
- `applyCellUpdates` writes a list of `{ viewRowIndex, columnId, value }` updates as one change with a `source`. It skips read-only cells and unchanged values. Without `rejected` and `warnings`, it runs the column `validate` like a paste. Pass them to report your own results instead.

## Rows and addresses [#rows]

Hooks that read rows. [State and view index](/docs/concepts/state-view-index) explains the addresses.

| Hook | Returns | Meaning |
| --- | --- | --- |
| <a id="usedatagridviewindex"></a>`useDataGridViewIndex` | `readonly number[]` | The `viewIndex` array: the data index of the row at each view index. |
| <a id="usedatagridviewstale"></a>`useDataGridViewStale` | `boolean` | `true` while rows keep an old view index after a write. `actions.reconcileView()` clears it. With `useDataGridServerRows`, it stays `true` until the server answer delivers the stale rows again. |
| <a id="usedatagridrow"></a>`useDataGridRow` | `TData \| undefined` | The row at a view index. Pass `TData` as a type argument. It re-renders only when that row changes. |
| <a id="usedatagridrowid"></a>`useDataGridRowId` | `string \| undefined` | The row id at a view index. A row that scroll mode has not loaded returns a placeholder id. An index outside the view returns `undefined`. |
| <a id="usedatagridrowids"></a>`useDataGridRowIds` | `(string \| undefined)[]` | The row ids for a list of view indexes, in one subscription. |
| <a id="usedatagridrowidtoviewrow"></a>`useDataGridRowIdToViewRow` | `ReadonlyMap<string, number>` | A map from row id to view index. The map keeps its identity across writes that move no row. |

## Cells and editing [#cells]

Hooks that read the active cell and the edit session.

| Hook | Returns | Meaning |
| --- | --- | --- |
| <a id="usedatagridreadonly"></a>`useDataGridReadOnly` | `boolean` | The `readOnly` flag of the provider. It is correct on the first render, also on the server. |
| <a id="usedatagridactivecell"></a>`useDataGridActiveCell` | `ViewCoord \| null` | The active cell, or `null`. |
| <a id="usedatagridactivecolumn"></a>`useDataGridActiveColumn` | `number \| null` | The view column of the active cell. Vertical moves do not re-render the subscriber. |
| <a id="usedatagridediting"></a>`useDataGridEditing` | The open edit or `null` | The edit in progress, with its row id and column id. |
| <a id="usedatagridcelleditingerror"></a>`useDataGridCellEditingError` | `string \| null` | The live validation error of the cell at a `ViewCoord` while that cell is in edit. Every other cell gets `null`. |
| <a id="usedatagridcellstate"></a>`useDataGridCellState` | `DataGridCellState` | One subscription for one cell: `isActive`, `isSelected`, `isEditing`, `initialText`, `editSession`, `isSearchMatch`, and `cellError`. |
| <a id="usedatagridrowcellstate"></a>`useDataGridRowCellState` | `DataGridRowCellState` | One subscription for one view row. It covers the active and editing columns of the row, its `selectedColRanges`, its `saveStatus`, its `stale` flag, and its search match, error, and flashing columns. |
| <a id="usedatagridcelltypes"></a>`useDataGridCellTypes` | `Record<string, CellType>` | The resolved cell type registry: the built-in cell types merged with your `cellTypes` prop. A `null` entry removes a built-in type. |

Show the active cell and the read-only flag in a status line:

```tsx
import {
  useDataGridActiveCell,
  useDataGridReadOnly,
} from "@/components/data-grid/data-grid";

export function CellStatus() {
  const cell = useDataGridActiveCell();
  const readOnly = useDataGridReadOnly();
  return (
    <span>
      {cell ? `Row ${cell.row + 1}, column ${cell.col + 1}` : "No active cell"}
      {readOnly ? " (read only)" : ""}
    </span>
  );
}
```

## Labels, keys, and saves [#misc]

Hooks for text, keys, and server results.

| Hook | Returns | Meaning |
| --- | --- | --- |

## createDataGridSelector [#createdatagridselector]

`createDataGridSelector<TData>()` returns a hook that reads any slice of the store. Create the hook once at module scope. The selector receives the store state with `data` typed as `readonly TData[]`. The hook takes `(selector, eq?)`. `eq` defaults to `Object.is` and decides when the component re-renders.

Sum a column in a component below the provider:

```tsx
import { useMemo } from "react";
import { createDataGridSelector } from "@/components/data-grid/data-grid";

type Order = { id: string; total: number };

const useOrderSelector = createDataGridSelector<Order>();

export function TotalBadge() {
  const data = useOrderSelector((state) => state.data);
  const total = useMemo(
    () => data.reduce((sum, row) => sum + (row?.total ?? 0), 0),
    [data],
  );
  return <span>{total}</span>;
}
```

## createDataGridHooks [#createdatagridhooks]

`createDataGridHooks<TData>()` returns `useDataGridApi`, `useDataGridRow`, `useDataGridVisibleColumns`, `useDataGridAllColumns`, and `useDataGridSelector`, with the row type fixed. Call it once at module scope:

```tsx
import { createDataGridHooks } from "@/components/data-grid/data-grid";

type Order = { id: string; total: number };

export const { useDataGridRow, useDataGridSelector } =
  createDataGridHooks<Order>();

export function FirstTotal() {
  const row = useDataGridRow(0);
  const count = useDataGridSelector((state) => state.data.length);
  return (
    <span>
      {row?.total} of {count} rows
    </span>
  );
}
```

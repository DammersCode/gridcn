`useDataGridServerRows` owns the sort, filter, search text, and rows of one server source. You write `fetchRows`. The hook calls it, aborts a request that a newer one replaces, and keeps the last good rows on screen. `mode` picks how rows reach the grid. The steps and the contract are on [Server rows contract](/docs/contracts/server-rows-contract).

## Pages mode [#server-mode]

The default mode fetches one page for each state. If the sort, the filter, the search text, or the page size changes, the grid returns to page 1.

<AutoTypeTable path="./registry/default/blocks/data-grid-server/use-data-grid-server-rows.ts" name="UseDataGridServerRowsOptions" />

The hook keeps `page` between 1 and the last page of 10,000,000 rows at the current page size. A `page` that is not a positive integer becomes 1. At mount, it waits one timer tick before the first request, so a spec that your URL state restores replaces that request before it leaves. If `onError` or `onLoaded` throws, the hook logs the error and carries on.

### Pager options [#pager-options]

`pager` in pages mode comes from `useDataGridServerPager`. If you fetch rows without `useDataGridServerRows`, call that hook yourself. It returns `{ pager }`. Pass `page`, `pageSize`, `totalRowCount`, and `onPageChange`, and fetch each page yourself. If the server sends no count, pass `totalRowCount: null` and `hasMore`.

<AutoTypeTable path="./registry/default/blocks/data-grid-pagination/use-data-grid-pagination.ts" name="UseDataGridPaginationServerOptions" />

If `page` is outside the page range, the hook calls `onPageChange` once with the clamped page. It skips this while `totalRowCount` is `0`, so a deep link survives until the first count arrives. If you pass no `onPageSizeChange`, the bar hides the page-size select. `DataGridPaginationControls` is the result. See [Client pagination options](/docs/add-options/rows-pages-menus/client-pagination-options#result).

### Without a total [#without-a-total]

A server that sends no count answers `totalRowCount: null` and `hasMore`. The pager then reports `totalRowCount: null`:

- The footer shows "Page 3" in place of a range.
- Next stays enabled while `hasMore` is `true`, and Last stays disabled.
- The page count is the current page, plus 1 while `hasMore` is `true`.
- The hook lifts a page below 1. It caps the page at the last page of 10,000,000 rows. The pager itself leaves the upper end open when the count is unknown.

## Scroll mode [#scroll-mode]

Set `mode: "scroll"` to fetch fixed-size blocks as the rendered rows move. The first answer picks the fetch order. A `totalRowCount` without `nextCursor` gives random access. A `nextCursor`, or neither, gives a sequential source.

Set `source: "random"` or `source: "sequential"` to fix the order. A random source that answers without `totalRowCount` warns in development.

`getRowId` is optional in both modes. It defaults to the `id` field of the row, the same default as `DataGridProvider`. A row without a string or number `id` throws.

The hook sets `sortMode` and `filterMode` to `"server"`. A grid with `totalRowCount` defaults both to `"server"`, because a window of a result cannot be sorted or filtered in the browser without being wrong. Set `sortMode="client"` or `filterMode="client"` to sort or filter the window locally.

### Fetch limits [#fetch-limits]

{/* props: UseDataGridServerRowsScrollOptions */}

| Option | Default | Effect |
| --- | --- | --- |
| `loadDelayMs` | `100` | Milliseconds a block stays in the wanted range before its request starts. At most 2000. `0` starts at once. |
| `maxConcurrentFetches` | `3` | Most block requests in flight on a random access source. At most 16. |
| `maxLoadedRows` | `10000` | Most rows kept loaded. A value below `blockSize` counts as `blockSize`. `Infinity` keeps every row. |
| `revalidateIntervalMs` | off | Milliseconds between timed `refresh()` calls while the page is visible. At least 1000. A sequential source skips a tick while the rendered rows plus `overscan` end beyond 10 blocks. |
| `reshapeDelayMs` | off | Milliseconds after a push marked a row stale before one `refresh()`. At least 250. A sequential source skips it while the rendered rows plus `overscan` end beyond 10 blocks. |

The limits and the timers are on [Tune row retention](/docs/scroll-mode/tune-row-retention).

## Save options [#save-options]

Both modes take `onSave` and `refreshAfterSave`. `gridProps.onSave` runs your handler and then refreshes by the policy:

{/* props: SaveRefreshOptions */}

| Option | Default | Effect |
| --- | --- | --- |
| `onSave` | none | Sends a change to your server. Behaves as the `DataGridProvider` prop of the same name. |
| `refreshAfterSave` | `"settled"` | `"settled"` refreshes once after every save in flight has settled, or after 10 seconds when at least one save has settled by then. After the 10 seconds, each save still in flight refreshes when it settles. `"each"` refreshes after saves settle, without waiting for the saves still in flight. `false` never refreshes. A function of the save report returns whether to refresh, once after every save in flight has settled or after the same 10 seconds. A sequential source skips the refresh while the rendered rows plus `overscan` end beyond 10 blocks, so call `server.refresh()` there. Only an `onSave` that returns a promise triggers a refresh. |

`refresh()` stays available. See [Save edits](/docs/save-server/save-edits).

## Answer [#serverrowsanswer]

<AutoTypeTable path="./registry/default/blocks/data-grid-server/read-answer.ts" name="ServerRowsAnswer" />

The hook checks every answer before it uses it:

- An answer without a `rows` array fails the request and sets `error`.
- The hook drops rows beyond `end - start`, and development builds warn.
- A `totalRowCount` that is not a non-negative integer counts as unknown. A count above 10,000,000 clamps to 10,000,000. A browser scrolls fewer rows than that in scroll mode: see [Row limits](/docs/performance/row-limits).
- A repeated row id keeps its first row, and development builds warn once. In random access, the later copy leaves an empty slot that shows as a skeleton row. Pages mode and a sequential source drop the later copy, so the page holds one row fewer. Make the sort total, with the row id as the last sort key.
- An answer with `hasNextPage`, or with `total` and no `totalRowCount`, warns in development. The hook reads only `totalRowCount` and `hasMore`.

## Example

This sample loads orders by page from an API:

```tsx
import { DataGrid, defineColumns } from "@/components/data-grid/data-grid";
import { DataGridPaginationBar } from "@/components/data-grid-pagination/data-grid-pagination";
import { useDataGridServerRows } from "@/components/data-grid-server/data-grid-server";

type Order = { id: string; customer: string };

const columns = defineColumns<Order>()([
  { id: "customer", header: "Customer", accessorKey: "customer" },
]);

export function OrdersGrid() {
  const server = useDataGridServerRows<Order>({
    defaultPageSize: 25,
    fetchRows: async ({ start, end, spec, signal }) => {
      const response = await fetch("/api/orders", {
        method: "POST",
        body: JSON.stringify({ start, end, spec }),
        signal,
      });
      const { rows, total } = await response.json();
      return { rows, totalRowCount: total };
    },
  });
  return (
    <>
      <DataGrid {...server.gridProps} columns={columns} />
      <DataGridPaginationBar {...server.pager} />
    </>
  );
}
```

Your API reads `start` and `end` as the row range and returns the rows with the count of the filtered result.

## Save policy types [#save-policy]

- `SaveRefreshPolicy` is the value of `refreshAfterSave`: `false`, `"each"`, `"settled"`, or a function of a `SaveRefreshReport`.
- `SaveRefreshReport` describes the saves of one batch. It holds the `saved`, `rejected`, and `failed` counts. It holds the `changes` of those saves, oldest first, at most 100. It holds `pending`, the saves still in flight. `pending` is above 0 only when the 10 second wait forced the decision.

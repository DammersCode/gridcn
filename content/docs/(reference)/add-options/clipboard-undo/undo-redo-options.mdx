The `data-grid-history` add-on has two hooks. `useDataGridHistory` adds a history to a grid whose data you own. `useDataGridState` owns the data array and the history together. Both options objects are optional. [Undo and redo](/docs/clipboard-undo/undo-redo) explains the behavior.

This sample sets all three options of `useDataGridHistory`:

```tsx
import { useState } from "react";
import { DataGrid, defineColumns } from "@/components/data-grid/data-grid";
import { useDataGridHistory } from "@/components/data-grid-history/data-grid-history";

type Row = { id: string; name: string };

const columns = defineColumns<Row>()([
  { id: "name", header: "Name", accessorKey: "name" },
]);

export function HistoryGrid({ rows }: { rows: Row[] }) {
  const [data, setData] = useState<readonly Row[]>(rows);
  const history = useDataGridHistory<Row>({
    capacity: 50,
    datasetKey: "2026",
    recordSources: ["edit", "paste", "fill"],
  });
  return (
    <DataGrid
      data={data}
      columns={columns}
      onDataChange={setData}
      plugins={[history.plugin]}
    />
  );
}
```

The stack keeps the last 50 entries. Only edits, pastes, and fills go on it.

## UseDataGridHistoryOptions [#usedatagridhistoryoptions]

<AutoTypeTable path="./registry/default/blocks/data-grid-history/use-data-grid-history.ts" name="UseDataGridHistoryOptions" />

The `recordSources` example in the table leaves out `replace`. To record streams too, pass the default list of the second bullet below plus `"stream"`.

- `capacity` defaults to `100`. It counts entries, not operations. A change of `capacity` between renders starts an empty history.
- `recordSources` defaults to `edit`, `paste`, `fill`, `delete`, `row-operation`, `import`, `replace`, and `app`. The default leaves out `stream`, `history`, and `rollback`.
- The history never records `history` or `rollback`, whatever the list says.
- A change of `datasetKey` between renders clears both stacks. The first render clears nothing.

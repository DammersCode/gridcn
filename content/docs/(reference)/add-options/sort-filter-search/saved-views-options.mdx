`useDataGridViews` keeps the saved views of a grid and returns the state and the actions. `DataGridViews` renders the toolbar button on top of it. The behavior is on [Saved views](/docs/sort-filter-search/saved-views).

| Symbol | Purpose | Guide |
| --- | --- | --- |
| [`useDataGridViews`](#options) | Keeps the views and returns the state and the actions | [Saved views](/docs/sort-filter-search/saved-views) |
| [`DataGridViews`](#options) | Renders the toolbar button | [Saved views](/docs/sort-filter-search/saved-views) |
| [`labels`](#labels) | Replaces the strings of the menu | [Saved views](/docs/sort-filter-search/saved-views) |
| [`DataGridViewsStorage`](#storage) | Persists the views | [Saved views](/docs/sort-filter-search/saved-views) |

`DataGridViews` is the ready button. `useDataGridViews` drives a control of your own, such as this select:

```tsx
import {
  DataGridViews,
  useDataGridViews,
} from "@/components/data-grid-views/data-grid-views";

export function ViewsButton() {
  return <DataGridViews storage="orders-views" />;
}

export function ViewsSelect() {
  const { views, activeViewId, selectView } = useDataGridViews({
    storage: "orders-views",
  });
  return (
    <select
      value={activeViewId ?? ""}
      onChange={(event) => selectView(event.target.value || null)}
    >
      <option value="">No view</option>
      {views.map((view) => (
        <option key={view.id} value={view.id}>
          {view.name}
        </option>
      ))}
    </select>
  );
}
```

Render each one inside `DataGridProvider`.

## Result [#result]

<AutoTypeTable path="./registry/default/blocks/data-grid-views/use-data-grid-views.ts" name="UseDataGridViewsResult" />

The result reads and changes the views:

- `activeViewId` and `activeView` name the open view, or are `null`.
- `modified` is `true` when the grid differs from the active view.
- `overLimit` names the part of the grid state that exceeds a view limit, and is `false` when none does. The limits are 64 sorts, 64 filters, 16 filter groups, 1,000 characters in a filter value, and 1,000 entries in a value list. A search text holds up to 500 characters. The layout limits are a width of 10,000 px and 1,000 entries in a list. State of a column that the grid lacks is not a limit. `saveView` then returns `null` and `updateView` returns `false`. See [Limits](/docs/sort-filter-search/saved-views#limits).
- `defaultViewId` names the view that opens first.
- `selectView(id)` opens a view, and `selectView(null)` clears the active view. `saveView(name)` saves the grid state under a name. `updateView(id)` replaces a view with the grid state. Without an `id`, `updateView` and `exportView` use the active view. `renameView(id, name)` and `deleteView(id)` edit the list. `setDefaultView(id)` picks the default view.

A `DataGridView` has an `id`, a `name`, and a `DataGridViewState` with the sorts, the filters, the search text, the search options, and the column layout. The storage adapter persists a `DataGridViewsDocument`: its `version`, its `views`, and its `defaultViewId`.

`importView(text, { name })` returns an `ImportViewResult`: `{ ok: true, view, dropped }` or `{ ok: false, reason }`. `name` applies when the file has none. `exportView(id)` returns the view as compact JSON text, or `null` for an unknown id or a view over 100,000 characters.

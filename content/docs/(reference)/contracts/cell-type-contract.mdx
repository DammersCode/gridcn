A cell type is one object. Two components draw and edit the value. Four value functions drive the clipboard, the fill handle, delete, search, sort, and import and export. Optional members add behavior. One generic implementation in the grid runs against this contract for every type.

## CellType [#celltypetdata-tvalue-toptions]

The type takes three parameters: the row type, the value type, and the options type.

{/* props: CellType */}
| Member | Required | Purpose |
|---|---|---|
| `Cell` | Yes | Draws the value in read mode |
| `Editor` | Yes | Draws the editor in edit mode |
| `toText` | Yes | Turns a value into its canonical text |
| `fromText` | Yes | Turns text into a value |
| `clearValue` | Yes | The empty value of the type |
| `isEmpty` | Yes | Says whether a value counts as empty |
| `toDisplayText` | No | A formatted text for display only |
| `compare` | No | The sort comparator |
| `align` | No | `"start"`, `"center"`, or `"end"` |
| `numeric` | No | Renders digits with fixed width |
| `toSearchText` | No | The text that quick search reads |
| `validate` | No | The default validator for columns of this type |
| `activate` | No | An in-place edit gesture that skips the editor |
| `href` | No | The link target of a value |
| `filter` | No | The filter operators, matcher, and value input |

## Value pipeline [#value-pipeline]

Each feature reads the value through its own member. One override does not reach every feature.

| Feature | Reads |
|---|---|
| Print, autosize, set values of the header filter | `toDisplayText`, else `toText` (a custom `Cell` shows what it renders) |
| Status bar totals of one column | `toDisplayText`, else a number format |
| Clipboard copy and export | `toText`. Export with `text: "display"` reads `toDisplayText`, else `toText` |
| Sort | The column's `sortCompare`, else `compare`, else a numeric-aware collation of `String(value)` |
| Quick search | `toSearchText`, else `toText` |
| Filter | The raw value, through the `filter.match` of the column or the cell type, or the built-in text matcher |
| Fill | `toText` of the source cells, then the `fromText` of the target column. A vertical repeat writes the stored source value of the column. A horizontal repeat writes the `fromText` of the source text |

A custom `toText` changes copy, export, and search. It does not change what a filter matches. A column with no declared type searches `String(value)`.

A text `compare` <NewBadge /> calls `sortCollator().compare` from `data-grid-sdk`, so it follows `sortLocale`. `localeCompare` follows the language of the runtime, so a server and a browser order rows differently. Call it synchronously. The scope ends at the first `await`, and outside a scope the collator uses `"en-US"`. The sample compares two texts:

```ts
import { sortCollator } from "@/components/data-grid/data-grid-sdk";
const compare = (a: string, b: string) => sortCollator().compare(a, b);
```

## Members [#the-contract-member-by-member]

### Cell [#cell]

`Cell` receives `value`, `row`, `rowId`, `columnId`, `viewRowIndex`, `column`, `options`, and `isActive`. It runs for every visible cell and mounts again while the user scrolls. Keep its work small, and cache any formatter outside the component. `CellSpan` truncates text and applies `align`. `displayText(type, value, options)` returns `toDisplayText ?? toText`.

### Editor [#editor]

`Editor` receives `value`, `initialText`, `row`, `rowId`, `columnId`, `column`, `options`, `onChange`, `commit`, `cancel`, `pending`, and `rejectionCount`.

- `value` is the last committed value. If the user starts the edit by typing, `initialText` holds the typed text.
- `onChange(value)` stashes the draft. It writes nothing. `commit(movement)` validates and applies the last stashed value, closes the editor, and moves the active cell by `{ dx, dy }`. Enter is `{ dx: 0, dy: 1 }`. A blur is `{ dx: 0, dy: 0 }`.
- `commit()` with no earlier `onChange` commits the old value.
- `cancel()` discards the draft and emits no change.
- `pending` is true while an async Standard Schema validates the commit. Set the input to `readOnly`, never `disabled`, so that Escape and blur still work.
- `rejectionCount` rises on each refused commit attempt. A new session resets it. If it rises, re-arm a commit guard.

Content that the editor portals out of the cell, such as a popover, carries `data-grid-cell-editor`. Without it, a click in that content counts as a click away and ends the edit.

### toText, fromText, clearValue, and isEmpty [#totext-fromtext-clearvalue-and-isempty]

`fromText` <NewBadge /> parses typed, pasted, and imported text. For text it cannot parse, return the result of `clearValue`. If `fromText` throws, the grid rejects that cell. Paste and fill leave it unchanged and report it through `onValidationError`. Import lists it in `rejected`, and replace skips it.

`toText` must round-trip through `fromText` for every value the type can hold.

`clearValue` is the value that Delete writes into a cleared cell. It is also the value that `fromText` returns for text it cannot parse.

`isEmpty` decides how Select All and the Ctrl or Cmd plus Arrow jump read a blank cell. For a type or column with a comparator, it also decides which values sort last. It also sets the status bar `count` and the Replace skip for unparseable text. The built-in types differ: `""` is empty for `text`. For `number` and `checkbox`, only `null` and `undefined` are empty, so `0` and `false` are values. With a comparator, empty values sort last in both directions, and `compare` never receives one. A fill writes no series to a column or row when `fromText` returns an empty value for a generated text that is not blank.

### validate [#validate]

`validate` takes a function `(value, row, options) => string | null` or a Standard Schema. `options` holds the `options` of the column, so the `longText` type reads `maxLength` from it. Every validation path resolves `column.validate ?? cellType.validate`: a cell commit, a paste, a fill, `updateCells`, and an import.

### activate [#activate]

A type with `activate` has no editor session. Enter, F2, Space, a stationary click, and a double-click commit `activate(value, options)` directly, so `onBeforeEditStart` and `onEditEnd` never fire. The `checkbox` type declares `(value) => !value`.

### href [#href]

`href` returns a link target. The grid passes every result through `safeHref`, so only `http`, `https`, and `mailto` links survive. The `openLink` action (Alt+Enter), Ctrl or Cmd click, and middle click open the link.

### filter [#filter]

`filter` holds four optional members. Each falls back to the default for the type name.

- `operators` replaces the operator list of the filter menu.
- `match(value, filter)` is a predicate over the raw value. It replaces the text matcher.
- `compare(text, bound)` orders cell text against a filter bound for `gt`, `gte`, `lt`, `lte`, and `isBetween`. A `NaN` result or a throw falls back to the default order.
- `valueInput` picks the value widget: `"text"`, `"number"`, `"date"`, `"boolean"`, `"choices"`, or a component. A component receives `FilterValueInputProps`: `column`, `operator`, `value`, and `onValueChange`. It renders for every operator that takes a value. `value` is a string, a `[from, to]` pair for `isBetween`, or a `string[]` for `isAnyOf` and `isNoneOf`. For a custom type, add `isNoneOf` to `filter.operators`. A `filter.match` predicate sees that operator after you do.

## Example [#example]

This type stores a plain `number | null` and shows a currency format:

```tsx
import {
  CellSpan,
  useCellEditor,
  type CellEditorProps,
  type CellRenderProps,
  type CellType,
} from "@/components/data-grid/data-grid";
import { Input } from "@/components/ui/input";

const money = new Intl.NumberFormat("en-US", {
  style: "currency",
  currency: "USD",
});

const show = (value: number | null) =>
  value == null ? "" : money.format(value);

function parseAmount(text: string): number | null {
  const digits = text.replace(/[^0-9.-]/g, "");
  const amount = Number(digits);
  return digits === "" || Number.isNaN(amount) ? null : amount;
}

function CurrencyCell({ value }: CellRenderProps<unknown, number | null>) {
  return <CellSpan text={show(value)} />;
}

function CurrencyEditor(props: CellEditorProps<unknown, number | null>) {
  const bindings = useCellEditor(props, {
    toDraft: (value) => (value == null ? "" : String(value)),
    toValue: parseAmount,
  });
  return <Input {...bindings} className="h-full border-0 p-0 shadow-none" />;
}

export const currencyCellType: CellType<unknown, number | null> = {
  Cell: CurrencyCell,
  Editor: CurrencyEditor,
  toText: (value) => (value == null ? "" : String(value)),
  toDisplayText: show,
  fromText: parseAmount,
  clearValue: () => null,
  isEmpty: (value) => value == null,
  compare: (a, b) => (a ?? 0) - (b ?? 0),
  align: "end",
  numeric: true,
};
```

## useCellEditor [#usecelleditorprops-codec]

`useCellEditor(props, codec)` builds a text-input editor. It owns the draft state, the end-caret focus, and a one-shot commit guard. It binds Enter, Escape, and blur. Enter commits and moves down. Escape cancels. A blur commits in place. It skips keys during IME composition.

The `codec` is a `CellEditorCodec`. It holds `toDraft(value)` and `toValue(draft)`. If `toValue` throws, the editor stays open with the draft unchanged, and the next commit runs again. The hook returns `ref`, `value`, `onChange`, `onKeyDown`, `onBlur`, `readOnly`, `aria-label`, `aria-busy`, and `dir`. Spread the result onto an input.

For an editor that is not a text input, import `useCommitGuard` and `useSeedFocus` from the same entry point. `tryCommit()` returns `true` once. `reset()` re-arms it.

## Register a type [#register-a-type]

The `cellTypes` prop of `DataGrid` and `DataGridProvider` merges over the built-in types `text`, `number`, `checkbox`, `select`, `date`, `url`, and `longText`. A key that you leave out keeps its built-in type. A key that names a built-in replaces it. A key set to `null` removes the type. Define each type once, outside the component. 

The grid also exports each built-in type, such as `textCellType` and `numberCellType`, to wrap or extend. `AnyCellType` types a registry entry.

`useDataGridCellTypes()` returns the resolved registry: the built-in types merged with your `cellTypes`.

A column whose `type` resolves to nothing renders as `text`. The grid drops its edits, pastes, and deletes. Development mode warns once per column.

### GridCellTypes [#gridcelltypes]

`GridCellTypes` maps each type key to its value type and options type. Augment it for every custom key that a `defineColumns` column names. A plain `ColumnDef` takes any `type` string. `CellTypeKey`, `CellValueOf<K>`, and `CellOptionsOf<K>` read the map. This sample adds a `currency` key:

```ts
export {};

declare module "@/components/data-grid/types" {
  interface GridCellTypes {
    currency: { value: number | null; options: { currency: string } };
  }
}
```

Set the module path to where `components.json` installs `types.ts`.

### defineCellType [#definecelltypekey-type]

`defineCellType(key, type)` checks at the definition that `key` is a key of `GridCellTypes` and that the type matches the value and options of that key. It returns the type unchanged. This sample defines the type of the example above:

```ts fragment="imports the type from the example above"
import { defineCellType } from "@/components/data-grid/data-grid";
import { currencyCellType } from "./currency-cell-type";

export const currency = defineCellType("currency", currencyCellType);
```

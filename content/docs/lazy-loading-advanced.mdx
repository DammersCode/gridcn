Follow-up to [Lazy loading](/docs/lazy-loading): how to bring your own cache into `fetchRows`,
and what to do when a block fails permanently instead of transiently.

## Wiring a fetch/cache library (React Query)

`fetchRows` is a plain `({ start, end, signal, spec }) => Promise<{ rows, totalRowCount }>`. Nothing about
`useDataGridServerRows` knows or cares whether that promise came from `fetch`, a cache, or a data
library. Block alignment already keeps requests infrequent (`overscan` and `blockSize` rounding,
in-flight dedup), so most apps do not need one. If you already use
[React Query](https://tanstack.com/query) elsewhere and want its cache, retry, and dedup behavior
for these blocks too, wire it through `fetchRows` with a per-block query key:

<Callout type="idea" title="Consumer wiring, not an add-on dependency">
  This is a snippet for your own app, not part of `data-grid-server`. The add-on has no React Query
  dependency, and installing it through `shadcn add` never pulls React Query in. Add
  `@tanstack/react-query` to your own app first if you want this pattern. For a grid without
  on-demand loading (a plain fetched array), see
  [Recipes: TanStack Query wiring](/docs/recipes/data-fetching/tanstack-query) for the `useQuery` +
  `useMutation` shape instead.
</Callout>

```tsx
"use client";

import { QueryClient } from "@tanstack/react-query";
import { useDataGridServerRows } from "@/components/data-grid-server/data-grid-server";

const queryClient = new QueryClient();

/** One query key per fetched block: same-block requests dedupe and cache instead of re-fetching. */
function orderBlockKey(start: number, end: number) {
  return ["orders", "block", start, end] as const;
}

function OrdersGrid() {
  const server = useDataGridServerRows<Order>({
    mode: "scroll",
    getRowId: (row) => row.id,
    fetchRows: ({ start, end, signal }) =>
      queryClient.fetchQuery({
        queryKey: orderBlockKey(start, end),
        queryFn: async () => {
          const answer = await api.orders({ start, end, signal });
          return { rows: answer.rows, totalRowCount: answer.total };
        },
        staleTime: 60_000,
      }),
  });

  // ...
}
```

`useDataGridServerRows` already merges adjacent loaded blocks and never requests a covered
block itself. So the cache of React Query mostly pays off for blocks that get *unloaded* and
scrolled back into view later. Two cases apply: a failed block, and a range you unload
yourself with `server.evict(range)`. Use `server.getLoadedRanges()` to find the candidates for your
policy. When the evicted range comes back into view, the refetch runs through `fetchRows`. It
serves from cache instead of the network, as long as it is within `staleTime`.

## When a block fails permanently

The base case (see [Errors](/docs/lazy-loading#errors)) is a transient failure. `onError` fires,
the block stays a hole, and scrolling back over it retries automatically. But the underlying
cause can be permanent instead, for example an expired auth token or a route the backend
removed. If so, that automatic retry only fails again in the same way every time the block comes
back into view.

`useDataGridServerRows` does not distinguish transient failures from permanent ones. It has no way
to, because `fetchRows` is opaque to it. What you get for a permanent failure is exactly what you
get for a transient one:

- The block's rows stay holes and render as skeleton cells. A failed block is never marked loaded.
- `onError(error)` fires once per failed attempt, and `error` holds the failure.
- The next time `onRenderedRowsChange` reports a range that covers the failed block, the hook requests it
  again. This happens whether you scroll away and back, or the very first request failed. If the cause
  is still there, the request fails again.

`server.gridProps` shows the error bar with a Retry button, so a permanently failing block does not retry
silently forever every time it is scrolled past. The user forces a retry once whatever was wrong is fixed.
For your own retry UI, read `error` and call `retry()`:

```tsx
"use client";

import { useDataGridServerRows } from "@/components/data-grid-server/data-grid-server";

function OrdersGrid() {
  const server = useDataGridServerRows<Order>({
    mode: "scroll",
    getRowId: (row) => row.id,
    fetchRows,
  });

  return (
    <>
      {server.status === "error" && (
        <div role="alert" className="flex items-center justify-between gap-2 border-b border-destructive/30 bg-destructive/10 px-3 py-2 text-sm">
          <span>Couldn't load rows.</span>
          <button type="button" onClick={server.retry}>
            Retry
          </button>
        </div>
      )}
      {/* ...DataGridProvider / DataGridRoot as usual */}
    </>
  );
}
```

`server.retry()` repeats the failed blocks only. Blocks that already loaded stay loaded.

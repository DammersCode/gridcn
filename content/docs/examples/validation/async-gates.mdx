Some checks need a server before the grid acts. A paste may need normalizing. A new row may need
an id. Each of these gates accepts a function that returns a value or a promise. The grid holds
the gesture until the promise settles, then writes once.

## The gates

| Gate | A promise holds | A pending promise | A rejection |
|---|---|---|---|
| `processPaste` | the whole paste | blocks a second paste | cancels the paste |
| `processCellFromClipboard` | the whole paste, until every cell settles | blocks a second paste | cancels the paste |
| `onEditStart` | the editor | blocks a second edit start | cancels the edit start |
| `createRow` | the insert, until every row settles | blocks a second insert | cancels the insert |
| `duplicateRow` | the duplicate, until every copy settles | blocks a second duplicate | cancels the duplicate |
| `validateRow` | nothing. The write commits first | is replaced by a newer verdict for the same row | adds no error |
| `onBeforeDeleteRows` | the delete | blocks a second delete | cancels the delete |
| `mapColumn` and the import `createRow` | the import dialog | n/a | see [Import & export](/docs/addons/import-export) |

A synchronous result writes in the same call.

## What the grid checks when a promise settles

The grid reads its state again after the promise settles. It drops the result when:

- the grid is `readOnly` now,
- the row the gesture aimed at is gone,
- a sort or filter changed during a paste.

The grid drops these results without an error, also when a refetch removed the row. The grid
blocks a second gesture of the same kind until the promise settles.

A row that moved keeps its gesture: the grid follows the row id, not the old view position.
`onEditStart` also drops the result when the user moved to another cell.

## Cancel a request with the signal

<NewBadge />

Every gate receives an `AbortSignal` as its last argument. The signal aborts in three cases:

- A newer run of the same gate replaces the run. For example, the user moves to another cell
  before `onEditStart` settles.
- The grid unmounts.
- The result can no longer apply. For example, the grid turned `readOnly`, or the row is gone.

Pass the signal to `fetch`, and the request stops when the signal aborts:

```tsx
<DataGridProvider
  processPaste={async ({ cells, signal }) => {
    const response = await fetch("/api/normalize", {
      method: "POST",
      body: JSON.stringify(cells),
      signal,
    });
    return response.ok ? response.json() : false;
  }}
  {...grid}
  columns={columns}
/>
```

An aborted gate result is dropped. A rejection after an abort adds no warning, so an `AbortError`
from `fetch` needs no `catch`.

| Gate | Signal position |
|---|---|
| `processPaste` | `({ cells, target, signal })` |
| `validateRow` | `(row, rowId, { signal })` |
| `onEditStart` | `(cell, { signal })` |
| `createRow` | `(index, { signal })` |
| `duplicateRow` | `(row, index, { signal })` |
| `onBeforeDeleteRows` | `({ rowIds, hiddenCount, signal })` |
| `mapColumn` | `(header, index, { signal })` |

A gate that ignores the extra argument keeps working.

## Show the pending state

<NewBadge />

`useDataGridGatePending()` returns the set of gate names whose promise has not settled. Call it
inside the provider:

```tsx
function PendingLabel() {
  const pending = useDataGridGatePending();
  return pending.has("processPaste") ? <span>Normalizing the paste</span> : null;
}
```

The set is empty while no gate runs. The grid root also sets `aria-busy="true"` and `data-gate-pending`
while a gate runs. The attribute value lists the gate names, separated by spaces, for example
`data-gate-pending="processPaste validateRow"`. Style the busy grid with CSS on
`[data-gate-pending]`.

## Client and server modes

- Controlled `data`: one gesture writes one `onDataChange`, when the promise settles.
- Pagination and lazy sources: a result for a row that left the loaded rows is dropped.
- `sortMode="server"`: the grid never reorders rows when a promise settles. The server owns the
  order.

For a server grid, see [Server-side data](/docs/recipes/data-fetching/server-side#writes-and-async-gates).

<Callout type="warn" title="Return a promise only from an event-time gate">
  `processCellForClipboard`, command `when`, and the context-menu resolvers stay synchronous. The
  browser needs their answer while the event runs. Cell render and `accessorFn` functions stay
  synchronous too.
</Callout>

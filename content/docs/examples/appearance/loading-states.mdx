One prop, `loading`, plus whether rows exist, covers all three states. The demo's two switches
(loading, rows present) reach each one live.

<ComponentPreview name="data-grid-loading-demo" />

<InstallCommand item="data-grid-loading-demo" />

| Rows | `loading` | What renders |
|---|---|---|
| none | `true` | A viewport-filling skeleton: pulsing rows in place of the empty grid. |
| present | `true` | A slim indeterminate bar under the header while the existing rows stay on screen. |
| none | `false` | The ordinary empty state (the `labels.grid.emptyState` string). |

<Callout type="info" title="Where the data comes from">
`loading` is a rendering concern, not a fetch hook. Pass it from whatever owns your request
state (`isPending` from React Query, `isLoading` from SWR, your own flag). The data-fetching
patterns it pairs with are on the
[Data & Integrations](/docs/examples/data) pages.
</Callout>

## Customizing the look

`loadingState` replaces the skeleton (zero rows) or the indeterminate bar (rows present) while
`loading` is true. It accepts a plain node or a function receiving `{ reason }`: `"no-data"`
or `"rows-present"`. The replacement renders directly under the header at full width, and the
node owns its own accessibility.

`emptyState` takes the same two forms. Its `reason` is `"no-data"` when the data array is empty
and `"filtered"` when rows exist but none are in view.

Client mode: the demo holds all 240 rows, and `defaultPageSize` on the provider shows one page of the view at a time.
No round trip, and no row count to manage. Sort, filter, and search cover all 240 rows.

## Client paging vs server mode

```tsx
// client mode: the grid pages its own view
<DataGridProvider data={rows} columns={columns} getRowId={(row) => row.id} defaultPageSize={25}>
  {/* grid parts */}
  <DataGridPaginationBar />
</DataGridProvider>

// server mode: you own page/pageSize/totalRowCount and fetch the page yourself
const { pager } = useDataGridServerPager({
  page,
  pageSize,
  totalRowCount: serverTotal,
  onPageChange: setPage,
  onPageSizeChange: (next) => {
    setPageSize(next);
    setPage(1);
  },
});
```

Both feed the same footer. Client mode reads the pager from the provider; server mode spreads `{...pager}` onto the bar.

Use client mode when the dataset already fits in memory (a few hundred to a few thousand
rows). Switch to server mode when a page is a real API call. See
[TanStack Query](/docs/examples/data/pagination/react-query) and
[SWR](/docs/examples/data/pagination/swr).

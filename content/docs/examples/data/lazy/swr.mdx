title: SWR

SWR has no `queryClient.fetchQuery`. `preload(key, fetcher)` is its imperative entry point.
It runs the fetcher once per key, hands back its promise, and stores the result in the
global cache. So a second grid or a detail panel on the same page that calls `useSWR` with
the same key gets the block for free.

## The seam

```tsx
const server = useDataGridServerRows<Row>({
  mode: "scroll",
  getRowId: (row) => row.id,
  fetchRows: async ({ start, end, signal }) => ({
    rows: await preload(["rows", start, end] as [string, number, number], (key) =>
      api.fetchRows({ start: key[1], end: key[2], signal }),
    ),
    totalRowCount: 10_000,
  }),
});
```

The fetcher receives the key itself as its argument (the SWR 2.x convention. `useSWR`
works the same way), hence the tuple cast rather than destructured parameters. Concurrent
requests for the same block share one fetch, and the cached block survives for the
session. Scrolling back never refetches.

<Callout type="info" title="Revalidate on focus">
`useSWR` components revalidate on window focus and reconnect by default. The scroll-mode blocks
here are plain cache entries consumed through the hook, so they stay put for the session (
no focus-time churn while you scroll). If you also mount `useSWR` consumers on the same keys,
decide once whether you want that focus revalidation (`revalidateOnFocus: false`) or rely on
it as a cheap freshness check.
</Callout>

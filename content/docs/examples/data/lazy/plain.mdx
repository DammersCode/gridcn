The baseline: `useDataGridLazyRows` owns the sparse row array and the window bookkeeping.
You own `fetchRows(start, end, signal)`. The demo has 100,000 rows — only the windows that
actually scroll into view are ever fetched, and skeleton rows hold the space until each
window lands. The two failure buttons show the transient/permanent error split. The third
page covers what a real fetcher replaces.

## The seam

```tsx
const lazy = useDataGridLazyRows<Row>({
  total: 100_000,
  getRowId: (row) => row.id,
  fetchRows: (start, end, signal) => api.fetchRows(start, end, signal),
  onError: (error, range) => {
    /* transient: auto-retries on next scroll; permanent: surface a retry button */
  },
});
```

- `fetchRows` resolves exactly the `[start, end)` slice, positionally aligned to `start`.
  The hook writes it into the sparse array. The core renders real rows over the skeletons.
- `signal` aborts the in-flight fetch when the window leaves view. A rejection after abort
  is ignored, so an abort is not an error — reject with an `AbortError` and move on.
- Failed ranges revert to unloaded and the next scroll into them retries automatically
  ("refetch on next visibility"). `onError` still fires, so a permanent failure (an expired
   token, for example) can surface a manual retry — re-fire
   `gridProps.onRowWindowChange(range)`, and the range takes the same path as a real scroll.

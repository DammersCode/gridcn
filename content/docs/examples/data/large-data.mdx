The opposite of lazy loading: the whole dataset is in memory from the start, and
virtualization does the work — only the rows around the viewport ever mount, no matter the
row count.

## How it works

The grid renders rows through a virtualized viewport: it measures row height, computes
which rows intersect the scroll window, and mounts only those plus overscan. Sorting,
filtering, and editing all run against the in-memory array; the DOM is a window onto it.

<Callout type="info" title="When to lazy-load instead">
If the dataset is bigger than a browser should hold, stop loading it all:
[lazy loading](/docs/examples/data/lazy) fetches only the scrolled-into windows, and
[server pagination](/docs/examples/data/pagination) only the current page.
</Callout>

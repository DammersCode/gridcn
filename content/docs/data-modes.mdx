A grid feature can behave differently on a local array, on server pages and on lazy rows. The table below sets every feature against every data mode. A gap cell is a known gap, and the notes below the table describe it.

## Data modes

- **L**: Local array. `data` holds every row in memory.
- **PC**: Client pagination. `useDataGridPagination` slices `data` into pages.
- **PS**: Server pagination. The server returns one page per request.
- **Z**: Lazy rows. `useDataGridLazyRows` fetches row ranges on scroll.
- **C**: Controlled state. The app owns `sortState`, `filterState` or `searchText`.
- **SS**: Server sort. `sortMode="server"`: the grid never reorders `data`.
- **FS**: Server filter. `filterMode="server"`: the grid never filters `data`.
- **API**: Own API. `onDataChange` writes through to the app's backend.

## Notes

### Sort

- **FS**: n/a: Filter mode concerns filters only.

### Filter set values

- **API**: n/a: Set values are read-only input of the filter; writes through onDataChange or onSave never read them.

### Quick search

- Search highlights and navigates loaded rows. It has no server mode by design.
- **FS**: n/a: Search highlights loaded rows and never filters.
- **API**: n/a: Search writes no data.

### Row ids

- **API**: Gap: No swap from a client id to the server-assigned id after create.

### Row grouping

- **L**: Gap: Row grouping is not available.
- **PC**: Gap: Row grouping is not available.
- **PS**: Gap: Server grouping is not defined.
- **Z**: Gap: Server grouping is not defined.
- **C**: n/a: Grouping has no controlled state.
- **SS**: Gap: Server grouping is not defined.
- **FS**: Gap: Server grouping is not defined.
- **API**: Gap: Server grouping is not defined.

### Pinned rows and aggregates

- **PS**: Gap: Aggregates cover the current page or warn; no server totals.
- **Z**: Gap: Aggregates cover loaded rows or warn; no server totals.

### Column pin, hide, order and size

- Mode-neutral. Autosize measures loaded rows only on lazy data and on one page.

### Fill

- Fill skips rows not loaded yet and warns.

### Import

- **PC**: n/a: Import hands the built rows to onImport and reads no sort, filter, page, or server state; the app decides where they land.
- **PS**: n/a: Import hands the built rows to onImport and reads no sort, filter, page, or server state; the app decides where they land.
- **Z**: Gap: Appended rows fight `total`.
- **C**: n/a: Import hands the built rows to onImport and reads no sort, filter, page, or server state; the app decides where they land.
- **SS**: n/a: Import hands the built rows to onImport and reads no sort, filter, page, or server state; the app decides where they land.
- **FS**: n/a: Import hands the built rows to onImport and reads no sort, filter, page, or server state; the app decides where they land.

### Export

- **PC**: Gap: Exports the rows of the current page only.
- **PS**: Gap: Exports loaded rows only.
- **Z**: Gap: Exports loaded rows only.
- **SS**: Gap: Exports loaded rows only.
- **FS**: Gap: Exports loaded rows only.
- **API**: Gap: Exports loaded rows only.

### Print

- **PC**: n/a: Print covers loaded rows by design.
- **PS**: n/a: Print covers loaded rows by design.
- **Z**: n/a: Print covers loaded rows by design.

### Undo and redo

- **Z**: Gap: Undo warns over rows not loaded yet.
- **API**: Gap: The local undo stack never learns whether the server accepted the write.

### URL state

- **C**: n/a: URL state drives the controlled props itself.
- **FS**: Gap: Deep-linked set-filter values outside static `choices` are dropped.

### Presence

- Mode-neutral by design.

### Find and replace

- **PS**: Gap: Loaded rows only; no server scope.

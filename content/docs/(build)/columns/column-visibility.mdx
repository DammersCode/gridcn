Users hide the columns they do not need. `hidden: true` starts a column hidden. `setColumnHidden` toggles a column from code. `DataGridColumnsMenu` gives users a checkbox for each column. The same page covers saving the whole column layout, so it survives a reload.

## Hide and show columns [#visibility]

`hidden: true` in a `ColumnDef` sets the first state. `setColumnHidden(id, hidden)` and the columns menu override it. The flag applies again only for a new `columns` array. A render with the same array keeps the choice of the user.

`DataGridColumnsMenu` ships with the [toolbar add-on](/docs/sort-filter-search/toolbar). It is a dropdown with a checked row for each column. The menu shows and hides. It does not pin. The header menu of the [context menu add-on](/docs/rows-pages-menus/context-menu#header-surface) has a "Hide column" item.

```tsx
import {
  DataGridBody,
  DataGridHeader,
  DataGridProvider,
  DataGridRoot,
  defineColumns,
} from "@/components/data-grid/data-grid";
import {
  DataGridColumnsMenu,
  DataGridToolbar,
} from "@/components/data-grid-toolbar/data-grid-toolbar";

type Row = { id: string; name: string; email: string };

const rows: Row[] = [{ id: "1", name: "Ada", email: "ada@example.com" }];
const columns = defineColumns<Row>()([
  { id: "name", header: "Name", accessorKey: "name" },
  { id: "email", header: "Email", accessorKey: "email", hidden: true },
]);

export function ColumnsGrid() {
  return (
    <DataGridProvider defaultData={rows} columns={columns}>
      <DataGridToolbar>
        <DataGridColumnsMenu />
      </DataGridToolbar>
      <DataGridRoot className="h-80">
        <DataGridHeader />
        <DataGridBody />
      </DataGridRoot>
    </DataGridProvider>
  );
}
```

Result: the grid starts with the Name column, and the menu shows Email unchecked.

## Read column state [#reading-column-state]

These hooks read column state for your own UI. Call them under `DataGridProvider`.

| Hook | Returns |
| --- | --- |
| `useDataGridVisibleColumns()` | the columns that are not hidden, in display order |
| `useDataGridAllColumns()` | every column, hidden ones included, in column order |
| `useDataGridIsColumnHidden(id)` | `true` while the column is hidden |
| `useDataGridColumnWidth(id)` | the stored width in px, or `undefined` while the column has none |
| `useDataGridColumnWidths(ids)` | the stored widths of a list of columns |

The visible and all-columns hooks return the full `ColumnDef` of each column. Pass your row type, for example `useDataGridVisibleColumns<Row>()`, to type `accessorFn` and `setValue`. The actions of `useDataGridActions()` write the state: `setColumnWidth`, `resetColumnWidth`, `setColumnOrder`, `setColumnPin`, `setColumnHidden`, `setColumnLayout`, and `autosizeColumns`. This sample shows a button for each hidden column:

```tsx
import {
  useDataGridActions,
  useDataGridAllColumns,
  useDataGridIsColumnHidden,
} from "@/components/data-grid/data-grid";

function ShowButton({ id, label }: { id: string; label: string }) {
  const actions = useDataGridActions();
  const hidden = useDataGridIsColumnHidden(id);
  if (!hidden) return null;
  return (
    <button onClick={() => actions.setColumnHidden(id, false)}>
      Show {label}
    </button>
  );
}

function RestoreBar() {
  return useDataGridAllColumns().map((column) => (
    <ShowButton
      key={column.id}
      id={column.id}
      label={
        column.headerText ??
        (typeof column.header === "string" ? column.header : column.id)
      }
    />
  ));
}
```

## Persist a user's layout [#persisting-a-users-layout]

`onColumnLayoutChange` receives a `ColumnLayout` snapshot after every committed change. Store the snapshot, and feed it back on the next visit.

A `ColumnLayout` holds four parts:

- `widths` maps column ids to px, for resized columns only.
- `order` lists the ids of all columns in column order, hidden ones included. Pins do not move a column in this list.
- `pins` maps column ids to `"left"` or `"right"`.
- `hidden` lists the ids of hidden columns.

{/* props: DataGridSyncProps */}

| Prop | Type | Default |
| --- | --- | --- |
| `defaultColumnLayout` | `Partial<ColumnLayout>` | none |
| `columnLayout` | `Partial<ColumnLayout>` | none |
| `onColumnLayoutChange` | `(next: ColumnLayout) => void` | none |

`defaultColumnLayout` seeds the layout once, at mount. The grid ignores later changes. If the first render already has the saved layout, for example from a cookie, seed it here.

`localStorage` does not exist on the server, so a layout from it is unknown at the first render in Next.js. Use `columnLayout` and load the value in an effect. The grid shows the default layout first, then the saved one:

```tsx
"use client";

import { useEffect, useState } from "react";
import {
  DataGrid,
  defineColumns,
  type ColumnLayout,
} from "@/components/data-grid/data-grid";

type Row = { id: string; name: string; email: string };

const rows: Row[] = [{ id: "1", name: "Ada", email: "ada@example.com" }];
const columns = defineColumns<Row>()([
  { id: "name", header: "Name", accessorKey: "name" },
  { id: "email", header: "Email", accessorKey: "email" },
]);

const LAYOUT_KEY = "my-grid-layout";

export function SavedLayoutGrid() {
  const [layout, setLayout] = useState<Partial<ColumnLayout>>();

  useEffect(() => {
    const saved = localStorage.getItem(LAYOUT_KEY);
    if (saved) setLayout(JSON.parse(saved) as ColumnLayout);
  }, []);

  return (
    <DataGrid
      defaultData={rows}
      columns={columns}
      className="h-80"
      columnLayout={layout}
      onColumnLayoutChange={(next) => {
        setLayout(next);
        localStorage.setItem(LAYOUT_KEY, JSON.stringify(next));
      }}
    />
  );
}
```

`onColumnLayoutChange` fires once for each committed change. That covers a resize release, an autosize, a width reset, a reorder drop, a pin or unpin, and a hide or show. It does not fire on each frame of a drag, and it does not fire for a change that alters nothing. [Column and viewport events](/docs/events-state/column-viewport-events) lists the payloads.

Each part of `columnLayout` replaces that part. An omitted part stays under the control of the grid. So `columnLayout={{ widths }}` controls widths, and a user reorder survives.

The grid cleans a layout before it applies it:

- It drops ids that match no column.
- It adds columns that `order` does not list after the listed ones, in `columns` order. A `hidden: true` column that `order` does not list stays hidden.
- It clamps each width to `minWidth` and `maxWidth`.
- It drops a pin on a `pinnable: false` column. When `pins` is present, a column that it does not list loses its own `pin`.
- It ignores a part with the wrong shape, so a damaged saved layout does not break the grid.

To keep order and hidden columns in a shareable link, use the [URL state add-on](/docs/sort-filter-search/url-state#column-layout).

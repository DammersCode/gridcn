Import reads a CSV, TSV, XLSX, or XLS file into rows. `DataGridImportButton` opens a dialog where the user picks a file, maps its columns, and checks a preview. The dialog runs every cell through the `fromText` of its column's cell type, as a paste does, and hands the rows to your `onImport`. It never writes rows to the grid itself.

## Import a file [#import]

Render this component inside the grid's provider. It appends the rows as one undoable change:

```tsx
"use client";

import { useDataGridActions } from "@/components/data-grid/data-grid";
import { useDataGridStoreApi } from "@/components/data-grid/data-grid-sdk";
import { DataGridImportButton } from "@/components/data-grid-io/data-grid-io";
import type { Order } from "./orders";

function createImportedRow(): Order {
  return { id: crypto.randomUUID(), customer: "", total: 0 };
}

export function ImportOrders() {
  const actions = useDataGridActions();
  const storeApi = useDataGridStoreApi();
  return (
    <DataGridImportButton
      createRow={createImportedRow}
      onImport={(rows) => {
        const start = storeApi.getState().data.length;
        actions.commitChange({
          source: "import",
          ops: rows.map((row, offset) => ({
            type: "insert",
            rowId: row.id,
            row,
            index: start + offset,
          })),
        });
      }}
    />
  );
}
```

`createRow(index)` builds the base row, with defaults for columns that the file lacks.

`createRow` can return a promise. A rejected promise imports nothing, and Cancel stops a pending import.

`onImport(rows)` decides where the rows land: append, replace, or send to a server. It can return a promise, which the dialog awaits. If it rejects, the dialog stays open with an error, and the user can retry. If it resolves, the dialog clears the grid selection. If the build cleared cells, it stays open (see [Confirm](#confirm)). Otherwise it closes. On a `readOnly` grid, `commitChange` writes nothing, and the dialog still closes.

A `commitChange` runs the grid's `validateRow` for each inserted row, so imported rows show the same cross-field errors as edited rows. <NewBadge /> You need no extra validation call after the commit. See [Cross-field rules](/docs/editing-cells/validation).

`commitChange` reaches `onDataChange` and `onSave` like a gesture, and `useDataGridHistory` records one entry. Replacing `data` does neither.

## Walk through the dialog

### Choose a file [#choose-a-file]

Drop a file on the zone or click it. The dialog takes `.csv`, `.tsv`, `.xlsx`, and `.xls`. The zone ignores a file whose name and type match none of these formats. A file over `maxFileBytes` shows the size message, whatever its type. A workbook opens on its first sheet, and a sheet picker switches sheets. A switch drops the column mapping that the user set by hand. A compact zone then shows the file name and replaces the file on a drop or click.

### Header row [#header-row]

Clear the "first row is a header" toggle, which starts on, for a file without headers. The dialog then numbers the columns, keeps the mapping, and imports the first row as data.

### Delimiter [#delimiter]

A CSV or TSV file shows a delimiter menu with comma, semicolon, and tab. The dialog detects the delimiter on load. If `importDefaults` sets one, the dialog uses it. A delimiter change drops the column mapping that the user set by hand. An Excel file has no delimiter menu.

### Map columns [#map-columns]

The dialog matches each header to a grid column by header text, then by column id. The match ignores case and the spaces around a header. A header without a match maps to "skip". Each grid column takes one source column at most. When two headers match one grid column, the first maps and the later one maps to "skip". The other menus disable a claimed column. A button next to each mapped menu skips it in one click.

### Preview [#preview]

The preview shows the first 10 rows with a note such as "Showing 10 of 250 rows".

### Confirm [#confirm]

The dialog clears a cell that fails the `validate` of its column and keeps its row. The rows still reach `onImport`. The dialog then shows the count of cleared cells, disables Import, and stays open. A file over 5,000 data rows builds in chunks, and Cancel stops the build between chunks.

## Read Excel files [#excel-files]

The dialog reads the bytes of an `.xlsx` or `.xls` file, not its name. A zip file reads as XLSX, and an OLE2 file (the container of Excel 97-2003 files) reads as XLS.

- An XLSX cell comes in as the text that Excel shows, so a date, a currency, or a percentage follows its number format. A number without a format keeps 15 significant digits, so `0.1 + 0.2` comes in as `0.3`.
- A boolean comes in as `TRUE` or `FALSE`. An error cell comes in as its code, such as `#DIV/0!`.
- An XLS cell has no number format. A date comes in as an ISO date such as `2024-01-15`, and a date with a time comes in as `2024-01-15 13:45:00`.

The dialog rejects an HTML table, Excel 2003 XML, or an Excel 5.0 file with an `.xls` name. The message asks for an `.xlsx` file.

## Import limits [#import-limits]

The dialog rejects a file over a limit with a message and never cuts a file.

- `maxFileBytes`: 50 MiB, checked before the read.
- `maxRows`: 1,000,000, header row included. `maxColumns`: 1,000.
- `maxCells`: 5,000,000, rows times columns. A CSV file counts its widest row as its columns, before the parse.
- `maxDecompressedBytes`: 256 MiB of unpacked data in one XLSX part, such as a worksheet or the shared strings.

Each XLSX part also has a cap of `maxCells` times 10 bytes plus 1 MiB, about 51 million bytes at the default. The lower of the two caps applies. The shared strings of a workbook count as one part, so a text-heavy sheet with few cells can need a higher `maxCells`. A higher `maxCells` raises the part cap and the memory that a read can use. An XLS file counts the cells of all its sheets against `maxCells`. An XLSX file counts the selected sheet only.

The dialog rejects an XLS file with more than `maxCells / 2 + 100,000` records. The drop zone shows `maxFileBytes`.

If its number format meets one of these rules, an XLSX cell comes in as its plain value (Excel's General format), not as formatted text:

- over 255 characters
- a fraction with four or more denominator placeholders, such as `# ?/????`
- a format that fails on use

A damaged file, or a workbook that the size check cannot follow, gets a read-error message. A file or a sheet without rows gets a "no rows" message.

Pass `importLimits={{ maxRows: 10_000 }}` to the button or the dialog to change a limit. `parseImportFile` takes the same fields.

## Preset the dialog [#import-options]

`importDefaults` sets where the dialog starts, and the user can change every choice:

- `defaultDelimiter` sets the delimiter and skips detection. `autoDetectDelimiter: false` without it means a comma.
- `defaultHeaderRow` sets the header toggle.
- `defaultSkipColumns` skips source columns by header text (any case) or 0-based index.
- `mapColumn(header, index, { signal })` returns a grid column id, `null` to skip, or `undefined` to keep the built-in match. It wins over `defaultSkipColumns` and can return a promise. A rejected promise falls back to the built-in match with `defaultSkipColumns`. The dialog does not compare the answers. When two answers name one grid column, the later one wins on import.

[Import options](/docs/add-options/import-export/import-options) lists every field.

## Build your own import UI [#lower-level-pieces]

`useDataGridImportPreview({ columnFallback })` and the plain functions `parseImportFile`, `matchImportColumns`, `applyImportOptions`, and `buildImportedRows` build your own import UI. [Import options](/docs/add-options/import-export/import-options) lists their options and results.

### Drop zone [#dropzone]

The dialog's drop target is the `dropzone` item, which `data-grid-io` installs. Use `Dropzone` alone for any file drop. [Import options](/docs/add-options/import-export/import-options#dropzone) lists its props.

## Server mode

Import reads no sort, filter, page, or server state. The dialog never writes rows into the grid. A grid with a `totalRowCount` or unloaded rows cannot take appended rows, so send the rows to your API from `onImport` and call `server.refresh()`. See [Import into a server grid](/docs/import-export/import-server-grid). <NewBadge />

The `keymap` is one data table that binds keys to grid actions. The grid handles a key only while DOM focus is inside the grid. <kbd>Tab</kbd> moves focus into the grid. Outside an edit, <kbd>Tab</kbd> and <kbd>Shift</kbd>+<kbd>Tab</kbd> leave the grid. <NewBadge />

With zero rows, no cell can take focus. Each column header then has one tab stop. It is the filter button, or the menu button when the column has no filter button. Press <kbd>Enter</kbd> or <kbd>Space</kbd> on the filter button to open it and clear the filter that emptied the grid. A focused header button takes only those two keys. Every other key, such as <kbd>ArrowRight</kbd> and <kbd>Delete</kbd>, still goes to the grid.

The built-in editors handle their keys themselves, so a `keymap` entry for `commitDown`, `commitUp`, `commitRight`, or `commitLeft` changes no editor key. In the `text`, `number`, `url`, and `date` editors, <kbd>Shift</kbd>+<kbd>Enter</kbd> commits and moves down, like <kbd>Enter</kbd>.

## Move and edit

- Arrow keys move the active cell. In a right-to-left grid, <kbd>ArrowRight</kbd> moves to the next column on the screen.
- <kbd>Alt</kbd>+<kbd>Arrow</kbd> moves the active cell and keeps the selection.
- <kbd>Ctrl</kbd>/<kbd>Cmd</kbd>+<kbd>Arrow</kbd> jumps along the row or column. From a non-empty cell whose neighbour is non-empty, it stops at the last non-empty cell of the run. From an empty cell, or from a non-empty cell whose neighbour is empty, it stops at the next non-empty cell. If there is none, it stops at the grid edge. With <kbd>Shift</kbd>, it scans from the far end of the selection and extends the selection to that cell.
- <kbd>PageUp</kbd> and <kbd>PageDown</kbd> move by the visible rows minus four.
- <kbd>Ctrl</kbd>/<kbd>Cmd</kbd>+<kbd>Enter</kbd> scrolls the active cell into view without moving it.
- <kbd>Enter</kbd>, <kbd>F2</kbd>, and <kbd>Space</kbd> start an edit. On a checkbox cell they toggle the value. A read-only grid does not edit.
- A printable key on the active cell starts an edit seeded with that character. A checkbox cell ignores it.
- <kbd>Alt</kbd>+<kbd>Enter</kbd> opens the link of a link cell in a new tab.
- <kbd>Shift</kbd>+<kbd>F10</kbd> opens the [cell menu](/docs/rows-pages-menus/context-menu#cell-surface-row-operation-items) of the active cell on Windows and Linux. It needs `DataGridContextMenu`.

## Undo and redo outside the grid [#undo-and-redo-outside-the-grid]

The in-grid undo and redo bindings work only while focus is inside the grid. [Global shortcuts](/docs/selection-shortcuts/global-shortcuts) extends them to a toolbar or any other focus position.

## Moving rows [#moving-rows]

<kbd>Shift</kbd>+<kbd>Alt</kbd>+<kbd>PageUp</kbd> (`moveRowsUp`) and <kbd>Shift</kbd>+<kbd>Alt</kbd>+<kbd>PageDown</kbd> (`moveRowsDown`) move rows one place. They move the checked rows. Without checked rows, they move the rows of the main range, or the active row.

They need a `reorder` family `rowMarkers` mode and `enableRowReorder`, which defaults to `true`. A read-only grid ignores them. See [Row order](/docs/rows-pages-menus/row-order).

## Opening the column filter [#opening-the-column-filter]

<kbd>Shift</kbd>+<kbd>Alt</kbd>+<kbd>ArrowUp</kbd> (`openColumnFilter`) opens the header filter of the active cell's column. It needs a `renderHeaderFilter` slot on the root and a column that offers a set filter. Otherwise it does nothing.

<kbd>Shift</kbd>+<kbd>Alt</kbd>+<kbd>ArrowDown</kbd> (`openColumnMenu`) opens the column menu, which needs a `renderHeaderMenu` slot.

## Two-stage Ctrl+A [#two-stage-ctrla]

The first <kbd>Ctrl</kbd>/<kbd>Cmd</kbd>+<kbd>A</kbd> selects the data region around the active cell: the rectangle of adjacent rows and columns that hold values. When the active cell is empty, the region is that cell. Press the keys again to select the whole grid. On a paged grid, the whole grid is the shown page. When the data fills the whole grid, the first press selects everything.

<kbd>Ctrl</kbd>/<kbd>Cmd</kbd>+<kbd>A</kbd> selects cells and never checks rows. It unchecks the checked rows, also with `'until-cleared'` and `'across-filters'`. It also clears the remembered checks of hidden rows and ends "all matching". The header checkbox and the marker checkboxes show checked rows only, so a range over every row leaves them unchecked. With `enableRangeSelection={false}`, the keys do nothing.

## Escape clears the selection

With no editor open, <kbd>Esc</kbd> (`cancel`) clears the whole selection: the cell range and its stack, the checked rows, and the selected columns. To keep a selection across <kbd>Esc</kbd>, unbind `cancel`. The built-in text editors still cancel an edit on <kbd>Esc</kbd>.

The following example unbinds `cancel`:

```tsx
import { DataGrid, defineColumns } from "@/components/data-grid/data-grid";

type Task = { id: string; title: string };

const columns = defineColumns<Task>()([
  { id: "title", header: "Title", accessorKey: "title", type: "text" },
] as const);

export function Tasks({ tasks }: { tasks: Task[] }) {
  return (
    <DataGrid
      data={tasks}
      columns={columns}
      getRowId={(task) => task.id}
      keymap={{ cancel: [] }}
    />
  );
}
```

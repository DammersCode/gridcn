Users expect a right-click on a cell to offer copy, paste, and row actions. They expect a column header to offer sort and pin. `data-grid-context-menu` adds two surfaces. The first is a header dropdown, which a right-click on a header also opens. The second is a right-click menu on cells. Both menus are lists of items that you can filter, extend, or replace.

`DataGridContextMenu` wraps `DataGridRoot` and handles the right-click. `DataGridHeaderDropdown` renders through the `renderHeaderMenu` prop of the root:

```tsx
import {
  DataGridBody,
  DataGridHeader,
  DataGridProvider,
  DataGridRoot,
  defineColumns,
} from "@/components/data-grid/data-grid";
import {
  DataGridContextMenu,
  DataGridHeaderDropdown,
} from "@/components/data-grid-context-menu/data-grid-context-menu";

type Row = { id: string; name: string };

const columns = defineColumns<Row>()([
  { id: "name", header: "Name", accessorKey: "name" },
]);

const rows: Row[] = [{ id: "1", name: "Ada" }];

function MyGrid() {
  return (
    <DataGridProvider defaultData={rows} columns={columns}>
      <DataGridContextMenu>
        <DataGridRoot
          renderHeaderMenu={(ctx) => <DataGridHeaderDropdown {...ctx} />}
        >
          <DataGridHeader />
          <DataGridBody />
        </DataGridRoot>
      </DataGridContextMenu>
    </DataGridProvider>
  );
}
```

`DataGridContextMenu` belongs inside `DataGridProvider`. Outside it, the grid throws an error that names the provider.

## Header surface

The header dropdown and the right-click header menu show the same items:

- **Sort ascending** and **Sort descending**. A column with `sortable: false` shows neither, and no sort group.
- **Clear sort**, only for a sorted column.
- **Pin to start** and **Pin to end**. If the column cannot pin, they stay but turn off.
- **Unpin**, only for a pinned column.
- **Hide column**.
- **Autosize column** and **Autosize all columns**, only while column resize is on and the column is resizable.

The `pin` field of a column sets the first pin. These items change it at run time. [Column order and pinning](/docs/columns/column-order-pinning) owns the pin behavior.

<kbd>Shift</kbd>+<kbd>Alt</kbd>+<kbd>ArrowDown</kbd> (the `openColumnMenu` action) opens the dropdown of the active cell's column. Arrow keys move through the items. <kbd>Escape</kbd> closes the menu and returns focus to the cell.

## Cell surface items [#cell-surface-row-operation-items]

A right-click on a cell outside the selection selects that cell first. A right-click inside the selection keeps it. The row items act on every view row that the selection covers, or on the clicked row if nothing is selected. With a `checkedRowsLifetime` of `'until-cleared'` or `'across-filters'` and a checked row, they act on the checked rows only. With `'until-click'` (the default without `totalRowCount`), a right-click outside the selection ends the checks. Set `'until-cleared'` to keep them for bulk menu actions.

<kbd>Shift</kbd>+<kbd>F10</kbd> opens the cell menu of the active cell on Windows and Linux. The browser sends it to the focused cell as a right-click.

The cell menu holds these items, in order:

1. **Cut**, **Copy**, and **Paste**. They use the [clipboard](/docs/clipboard-undo/clipboard) pipeline.
2. **Clear contents**. It empties the selection to the `clearValue()` of each cell type.
3. **Insert row above** and **Insert row below**, anchored at the clicked row. They need `createRow`.
4. **Duplicate rows**. It needs `duplicateRow`.
5. **Delete rows**, a destructive item. It runs `onBeforeDeleteRows` first.

Without `createRow` or `duplicateRow`, the menu hides the matching items. A `readOnly` grid turns off every item except Copy. With `checkedRowsLifetime="across-filters"`, when every checked row is hidden, Duplicate and Delete turn off too. While [all matching](/docs/rows-live-data/select-server-rows) is on, they turn off as well. The insert items stay on, because they insert next to the right-clicked row. A turned-off row item shows the reason as its tooltip: `labels.contextMenu.rowActionReadOnly`, `rowActionHiddenChecked`, or `rowActionAllMatching`.

The shortcut of each item <NewBadge /> shows as a key hint. [Row operations](/docs/rows-pages-menus/row-operations) owns what each operation does.

If a Cut or Copy write fails, the next menu opens with both items turned off and the `labels.contextMenu.clipboardFailed` tooltip. After that menu closes, both items work again.

Row markers, the empty space below the last row, the scrollbar gutter, pinned rows, and unloaded rows have no menu. A right-click on them opens no browser menu either.

## Custom menu items

Each surface resolves its items through a function prop of `DataGridContextMenu`. The function receives the built-in items as `defaults` and returns the complete list. Return `defaults` unchanged, filter it, reorder it, extend it, or build a new list:

{/* props: DataGridContextMenuProps */}

| Prop | Type | Default |
| --- | --- | --- |
| `className` | `string` | none |
| `children` | `ReactNode` | none |
| `getCellMenuItems` | `CellMenuItemsResolver` | built-in cell items |
| `getHeaderMenuItems` | `HeaderMenuItemsResolver` | built-in header items |

`getCellMenuItems(ctx, defaults)` receives `ctx` with `rowId`, `viewRowIndex`, `columnId`, `canInsertRow`, and `canDuplicateRow` of the clicked cell. `getHeaderMenuItems(ctx, defaults)` receives `columnId` and `scrollRoot`, the scroll container element. If the clicked element has no grid ancestor, `scrollRoot` is `null`. The header resolver applies to the right-click header menu and to every `DataGridHeaderDropdown` inside the wrapper.

Built-in items have stable ids, so a resolver can keep or drop them by id:

| Surface | Built-in ids, in order |
| --- | --- |
| Cell | `cut`, `copy`, `paste`, `sep-clipboard`, `clear-contents`, `fill-down`, `fill-right`, `sep-rows`, `insert-row-above`, `insert-row-below`, `duplicate-rows`, `delete-rows` |
| Header | `sort-asc`, `sort-desc`, `clear-sort`, `sep-sort`, `pin-left`, `pin-right`, `unpin`, `hide-column`, `sep-autosize`, `autosize`, `autosize-all` |

The fill items exist only for a touch selection while the fill add-on runs. An item is an object with `id`, `label`, `icon`, `shortcut`, `disabled`, `destructive`, `tooltip`, and `onClick`. `shortcut` is a keymap binding that the menu shows as keycaps. `tooltip` shows on hover while the item is off. A separator is `{ id, separator: true }`. The types are `GridMenuItemSpec`, `CellMenuItemsResolver`, and `HeaderMenuItemsResolver`.

This menu keeps two row items for cells and one sort item for headers. Render it inside `DataGridProvider`:

```tsx
import {
  DataGridBody,
  DataGridHeader,
  DataGridRoot,
} from "@/components/data-grid/data-grid";
import { DataGridContextMenu } from "@/components/data-grid-context-menu/data-grid-context-menu";

const KEEP_CELL = new Set(["insert-row-below", "duplicate-rows"]);

function FilteredMenus() {
  return (
    <DataGridContextMenu
      getCellMenuItems={(_ctx, defaults) =>
        defaults.filter((item) => KEEP_CELL.has(item.id))
      }
      getHeaderMenuItems={(_ctx, defaults) =>
        defaults.filter((item) => item.id === "sort-asc")
      }
    >
      <DataGridRoot>
        <DataGridHeader />
        <DataGridBody />
      </DataGridRoot>
    </DataGridContextMenu>
  );
}
```

This menu adds an item. Render the component inside `DataGridProvider`. The resolver closes over the actions that the component holds:

```tsx
import { Plus } from "lucide-react";
import {
  DataGridBody,
  DataGridHeader,
  DataGridRoot,
  useDataGridActions,
} from "@/components/data-grid/data-grid";
import { DataGridContextMenu } from "@/components/data-grid-context-menu/data-grid-context-menu";

function GridWithExtraItem() {
  const actions = useDataGridActions();

  return (
    <DataGridContextMenu
      getCellMenuItems={(ctx, defaults) => [
        ...defaults,
        {
          id: "new-row-here",
          label: "New row here",
          icon: <Plus className="size-4 text-muted-foreground" />,
          onClick: () => actions.insertRow(ctx.viewRowIndex, "below"),
        },
      ]}
    >
      <DataGridRoot>
        <DataGridHeader />
        <DataGridBody />
      </DataGridRoot>
    </DataGridContextMenu>
  );
}
```

<Callout type="warn" title="Do not call hooks in a resolver">
  A resolver is a plain function that runs while the open menu renders. Read hook values in the enclosing component and close over them, as the sample does.
</Callout>

## Touch

Long-press a cell or a header for 500 ms to open its menu. The grid raises one `contextmenu` event, so `onCellContextMenu` fires as it does for a right-click. The browser's own touch menu stays closed. While the fill add-on runs, the cell menu of a touch selection also lists **Fill down** and **Fill right**. Their text comes from `labels.contextMenu.fillDown` and `labels.contextMenu.fillRight`.

## Paste permission

The Paste item reads the system clipboard, which needs the `clipboard-read` permission. If the browser denies it, the item turns disabled and shows the `labels.contextMenu.pasteBlocked` hint, which points to <kbd>Ctrl</kbd>+<kbd>V</kbd>, or <kbd>Cmd</kbd>+<kbd>V</kbd> on macOS. The hint stays for later menus of the same wrapper. The paste formats are on [Clipboard](/docs/clipboard-undo/clipboard).

## Labels [#internationalization]

Every item text comes from `labels.contextMenu`. The right-click menu and the header dropdown share the same keys. See [Labels](/docs/components-props/labels).

A totals or averages row must stay in sight while the data rows scroll. `useDataGridPinnedRows` pins one band of rows under the header and one band at the bottom edge of the viewport. Data rows scroll underneath both bands. The same add-on computes sums and averages over the rows that the view shows.

## Wiring it up [#wiring-it-up]

The hook returns one plugin. Pass the plugin to the grid through `plugins`. Each band takes its own array of rows. The arrays do not index into `data`:

```tsx
import { DataGrid, defineColumns } from "@/components/data-grid/data-grid";
import { useDataGridPinnedRows } from "@/components/data-grid-pinned-rows/data-grid-pinned-rows";

type Row = { id: string; item: string; price: number };

const columns = defineColumns<Row>()([
  { id: "item", header: "Item", accessorKey: "item" },
  { id: "price", header: "Price", accessorKey: "price", type: "number" },
]);

const rows: Row[] = [
  { id: "1", item: "Pen", price: 2 },
  { id: "2", item: "Ink", price: 8 },
];

const bottomRows = [{ id: "total", item: "Total", price: 10 }];

function PricesGrid() {
  const { plugin } = useDataGridPinnedRows({ bottomRows });

  return <DataGrid defaultData={rows} columns={columns} plugins={[plugin]} />;
}
```

A band renders every row of its array in order, so a band can stack several rows. Pinned cells use the cell type of their column, so alignment and formatting match the data rows. They follow the column tracks, so pinned columns and column resize apply to them.

## Pinned row behavior [#api]

A pinned row is display-only. It is not part of `data` or the view index. As a result:

- It never sorts or filters. It stays in the order that you pass.
- It never joins the selection. A click on it does nothing, and it never becomes the active cell.
- It has no tab stop, and arrow keys skip it.
- Unless the column sets `readOnly` to `false` or to a function that returns `false` for the row, its cells carry `data-readonly`.

A pinned row goes through the `getRowId` of the grid, so `ctx.rowId` in a pinned cell is that id. If `getRowId` throws or returns an empty or non-string value, the row gets a band id. The band id is `__pinned-top-<index>` or `__pinned-bottom-<index>`, where `<index>` is the position of the row in its band.

## Computing a totals row [#computing-a-totals-row]

`useDataGridAggregate(specs)` reduces the columns that `specs` names over the rows of the view. It returns a `{ [columnId]: value }` object. That shape is a valid pinned row, because pinned cells read their values through `accessorKey` or `accessorFn`, like data rows do.

A hook that reads the grid store must run below the provider, and the `plugins` prop lives on the provider. `DataGridAggregateReporter` bridges the two. It renders nothing, and it reports the result through `onChange` into state of the parent:

```tsx
import { useCallback, useMemo, useState } from "react";
import {
  DataGridBody,
  DataGridHeader,
  DataGridProvider,
  DataGridRoot,
  defineColumns,
} from "@/components/data-grid/data-grid";
import {
  DataGridAggregateReporter,
  useDataGridPinnedRows,
  type AggregateSpecs,
} from "@/components/data-grid-pinned-rows/data-grid-pinned-rows";

type Row = { id: string; item: string; price: number };

const columns = defineColumns<Row>()([
  { id: "item", header: "Item", accessorKey: "item" },
  { id: "price", header: "Price", accessorKey: "price", type: "number" },
]);

const rows: Row[] = [
  { id: "1", item: "Pen", price: 2 },
  { id: "2", item: "Ink", price: 8 },
];

const TOTALS_SPECS: AggregateSpecs = { price: "sum" };

function TotalsGrid() {
  const [totals, setTotals] = useState<Record<string, unknown>>({
    id: "total",
    item: "Total",
  });
  const onTotalsChange = useCallback((row: Record<string, unknown>) => {
    setTotals((prev) => ({ ...prev, ...row }));
  }, []);

  const bottomRows = useMemo(() => [totals], [totals]);
  const { plugin } = useDataGridPinnedRows({ bottomRows });
  const plugins = useMemo(() => [plugin], [plugin]);

  return (
    <DataGridProvider defaultData={rows} columns={columns} plugins={plugins}>
      <DataGridAggregateReporter
        specs={TOTALS_SPECS}
        onChange={onTotalsChange}
      />
      <DataGridRoot>
        <DataGridHeader />
        <DataGridBody />
      </DataGridRoot>
    </DataGridProvider>
  );
}
```

A reducer is `"sum"`, `"avg"`, `"min"`, `"max"`, `"count"`, or a function. The numeric reducers skip `null` and `undefined` values. `count` counts the values that are not empty. The aggregate ignores a spec key that matches no column id and warns once in development.

<Callout type="warn" title="Keep the band arrays stable">
  `useDataGridPinnedRows` returns a stable `plugin` only while `topRows` and `bottomRows` keep their identity. A fresh array on every render rebuilds the plugin on every render. Memoize the arrays, as the sample does.
</Callout>

### Custom reducers [#custom-reducers]

A reducer function receives every resolved value, empty ones included, and the source rows. It owns its own empty handling. Type the specs as `AggregateSpecs<Row>` to type `rows`:

```tsx
import type { AggregateSpecs } from "@/components/data-grid-pinned-rows/data-grid-pinned-rows";

type Row = { id: string; item: string; price: number };

const specs: AggregateSpecs<Row> = {
  item: (_values, rows) => `${rows.length} rows`,
  price: (_values, rows) => Math.max(...rows.map((row) => row.price), 0),
};
```

### Manual computation [#manual-computation]

For anything else, compute the band rows yourself from the data in a `useMemo`. Rows from your data array ignore the active filter. If the band must match the filtered view, reduce over `useDataGridViewIndex()`.

## Options

{/* props: UseDataGridPinnedRowsOptions */}

| Prop | Type | Default |
| --- | --- | --- |
| `topRows` | `readonly unknown[]` | none |
| `bottomRows` | `readonly unknown[]` | none |

{/* props: UseDataGridAggregateOptions */}

| Prop | Type | Default |
| --- | --- | --- |
| `scope` | `"view" \| "all"` | `"view"` |

`scope: "view"` reduces over the rows that the filter and sort leave visible. `scope: "all"` reduces over all of `data`, filter ignored.

## Geometry [#geometry]

The top band shrinks the space above the data rows, like the header. The bottom band shrinks the bottom of the viewport. Both work with row virtualization and with `useDataGridScrollToCell`, so keyboard navigation never scrolls a data row under a band. A pinned-left or pinned-right column stays fixed inside a band.

Each band casts a soft shadow on the edge that faces the data rows. The shadow appears only after a data row scrolls beneath the band. It uses the `--grid-pin-shadow` token.

## Accessibility [#a11y]

The `aria-rowindex` order is: header rows, pinned-top rows, data rows, pinned-bottom rows. `aria-rowcount` includes both bands. Pinned cells carry `role="gridcell"`, `data-type`, and `data-readonly` like data cells. They carry no `tabindex` and no `aria-selected`.

## Server mode

Aggregates reduce the rows that the grid holds in memory. Two server modes limit that scope:

- **Pagination.** `data` is the current page, so `useDataGridAggregate` covers that page. `scope: "all"` covers the same page. Fetch totals for the whole dataset from your server and pin them as a static row. See [Load rows by page](/docs/server-pagination/load-rows-page).
- **Scroll mode.** Unloaded rows are `undefined` holes. The aggregate skips them and warns once in development, so the band covers loaded rows only. Use server totals. See [Scroll mode](/docs/scroll-mode).

With `filterMode="server"` or `sortMode="server"`, the view holds the rows of the response, so `scope: "view"` covers the response.

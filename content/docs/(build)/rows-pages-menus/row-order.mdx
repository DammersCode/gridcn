Some lists have a meaning in their order, such as a playlist or a priority queue. Users drag the handle in the [row marker](/docs/rows-pages-menus/row-markers) column to move a row. A thin line marks the drop target, and the row moves on release. Keyboard shortcuts and `reorderRows` do the same without a pointer.

## Enable reordering [#reorder]

Set `rowMarkers` to a mode of the reorder family: `"reorder"`, `"reorder-number"`, `"reorder-checkbox"`, or `"reorder-both"`. The other marker modes have no handle. This grid uses `"reorder-checkbox"`:

```tsx
import { DataGrid, defineColumns } from "@/components/data-grid/data-grid";

type Row = { id: string; title: string };

const columns = defineColumns<Row>()([
  { id: "title", header: "Title", accessorKey: "title" },
]);

const rows: Row[] = [
  { id: "1", title: "Intro" },
  { id: "2", title: "Verse" },
];

function Playlist() {
  return (
    <DataGrid
      defaultData={rows}
      columns={columns}
      rowMarkers="reorder-checkbox"
    />
  );
}
```

{/* props: DataGridSyncProps */}

| Prop | Type | Default |
| --- | --- | --- |
| `rowMarkers` | `RowMarkersMode` | `"none"` |

A `reorder` family mode arms the drag and the keyboard moves. A plain mode (`"number"`, `"checkbox"`, `"both"`) or `"none"` turns them off. `reorderRows` runs in every mode.

## Drag a row

The press location decides the gesture. In the reorder family, the drag handle zone is the only way to start a reorder. The zone is a 1.25rem column (20 px at the default font size) at the start of the marker cell. In `"reorder"` mode, it is the whole cell. A press on the handle never changes the selection. A vertical drag that leaves the pressed row reorders it. Press <kbd>Escape</kbd> during the drag to cancel.

The number and the checkbox in the marker cell only select rows. A press on them selects a row, and a drag selects a row range. A selection drag never reorders. <kbd>Shift</kbd> on the handle never starts a reorder either.

A press on the handle of a checked row drags every checked row. They land together at the drop line and keep their order. A press on an unchecked row drags that row alone and leaves the checks as they are. The marker cells of the dragged rows dim until the drag ends. If the pointer stays near the top or bottom edge, the grid scrolls, so you can reach rows that are not rendered yet.

## Move rows from the keyboard

<kbd>Shift</kbd>+<kbd>Alt</kbd>+<kbd>PageUp</kbd> (`moveRowsUp`) and <kbd>Shift</kbd>+<kbd>Alt</kbd>+<kbd>PageDown</kbd> (`moveRowsDown`) move rows one place. They act on the checked rows. With no checked row, they act on the rows of the selected range, then on the active row. The gaps between rows stay.

A row at the edge blocks the whole move. The keys need a reorder marker mode, and do nothing in a `readOnly` grid or while a cell editor is open. With `'across-filters'`, they do nothing when every checked row is hidden or while "all matching" is on. Each press is one change. With the [history add-on](/docs/clipboard-undo/undo-redo), it is one undo step. Remap the keys through the `keymap` prop.

## Move rows from code

`reorderRows(rows, to)` and `moveRowsBy(rows, delta)` come from `useDataGridActions`. If rows moved, both return `true`. Both address view indexes:

```tsx
import { useDataGridActions } from "@/components/data-grid/data-grid";

function MoveTools() {
  const actions = useDataGridActions();

  return (
    <>
      <button type="button" onClick={() => actions.reorderRows(0, 3)}>
        Row 1 to position 4
      </button>
      <button type="button" onClick={() => actions.moveRowsBy([4, 5], -1)}>
        Rows 5 and 6 up
      </button>
    </>
  );
}
```

`rows` is one view index or a list. `to` is the final index of the first row. Moving row 0 to index 3 shifts rows 1 to 3 up. A list moves as one block: the rows keep their order and land next to each other. A repeated index counts once. `to` must leave room for the whole block. `moveRowsBy` shifts every listed row by `delta` and keeps the gaps.

Under client pagination, `reorderRows` and `moveRowsBy` take page rows, and a move stays inside the shown page. A row, a `to`, or a shift that leaves the page counts as outside the grid, so the call returns `false`. `from` and `to` in `change.ops` are indices of the whole data array.

These calls return `false`, change nothing, and report through [`onRowActionSkipped`](/docs/rows-live-data/handle-row-action-results) with `action: "moveRows"`. The reason tells why:

| Reason | When |
| --- | --- |
| `"readOnly"` | The grid is `readOnly`. |
| `"view-ordered"` | A client sort or filter is active, because the sort or filter owns the view order. |
| `"unloaded-rows"` | The grid holds unloaded rows in scroll mode. |
| `"nothing-to-do"` | The drop leaves the rows where they are. The list is empty. An index or `to` is outside the grid. `moveRowsBy` shifts a row out of the grid. |

In development, the grid also warns for `"view-ordered"` and `"unloaded-rows"`.

After a move, the checked rows and the active cell follow their rows. An open editor follows its row too. If the rows of a selected range end up next to each other, the range stays. Otherwise it collapses onto the active cell. The grid announces each move in its live region through `labels.markers.reorderAnnouncement` for one row and `labels.markers.reorderRowsAnnouncement` for several rows. Under client pagination, the announced positions count the rows of the shown page, like the row numbers.

The grid does not recompute search matches after a move. They point at other rows until the next view rebuild, such as a new search text. Presence highlights in the view-index range form go stale the same way. The row-id range form follows its rows. See [Show presence](/docs/rows-live-data/show-presence).

## Server mode

A move is one change with `source: "row-operation"`. It reaches `onDataChange` and `onSave`. `change.ops` holds one `move` operation per moved row. In each operation, `from` is the index before the whole batch and `to` is the index after it. Apply the operations together with `applyChange`. A server that applies them one at a time ends with the wrong order.

With `sortMode="server"`, the grid does not sort, so the sort block does not apply. Scroll mode blocks a move while the grid holds unloaded rows.

A grouped grid shows one total per group. A pivot splits that total by the keys of a second column. `pivot` names the pivot column. The grid keeps one group row per key of `groupBy` and adds one generated column per pivot key. Each cell is the `aggregate` of the rows that share the group and the key. For a pivot on your server, see [Pivot server rows](/docs/data-modes/pivot-server-rows).

## Pivot the rows [#pivot-rows]

Set `groupBy` to the row columns and `pivot` to `{ columnIds: [id] }`. The `aggregate` of a column sets its value. This grid shows the revenue per region and make, and a button turns the pivot off:

```tsx
"use client";

import { useState } from "react";
import { DataGrid, defineColumns, type PivotSpec } from "@/components/data-grid/data-grid";

type Sale = { id: string; region: string; make: string; price: number };

const columns = defineColumns<Sale>()([
  { id: "region", header: "Region", accessorKey: "region" },
  { id: "make", header: "Make", accessorKey: "make" },
  {
    id: "price",
    header: "Revenue",
    accessorKey: "price",
    type: "number",
    aggregate: "sum",
  },
]);

const rows: Sale[] = [{ id: "1", region: "North", make: "Kestrel", price: 1 }];

export function SalesPivot() {
  const [pivot, setPivot] = useState<PivotSpec>({ columnIds: ["make"] });
  return (
    <>
      <button onClick={() => setPivot({ columnIds: [] })}>Pivot off</button>
      <DataGrid
        defaultData={rows}
        columns={columns}
        defaultGroupBy={["region"]}
        pivot={pivot}
        onPivotChange={setPivot}
      />
    </>
  );
}
```

`{ columnIds: [] }` turns the pivot off. The source columns then return with their order, pins, widths, and hidden state. The grid reads the first id of `columnIds` only.

## Values and keys [#values]

- Each column with a built-in `aggregate` (`sum`, `avg`, `min`, `max`, `count`) adds one value, in column order. A function `aggregate` adds no value.
- With no value, the group rows show their row counts only.
- With 1 value, a generated header holds the key text. With 2 or more values, each key gets one header over its value columns. `labels.pivot` names the values and the empty key.
- Keys ascend, and a sort on the pivot column sets their order. Text keys follow the client collator, as `groupBy` groups do. The empty key comes last.
- Filters apply before the pivot, so a key that the filters remove drops out.
- A pivot with 2 to 4 `groupBy` levels shows subtotals on each level. The innermost group row never opens.

## Limits [#limits]

- A group row holds no data, so its pivot cells show values and take no edit.
- The grid keeps the first `floor(200 / values)` keys, so it shows at most 200 generated columns. A note below the grid reads "+N more columns" for the cut columns.
- Above 1,000,000 cells (group rows times generated columns), the grid shows the rows ungrouped.
- A lazy source, `totalRowCount`, and `sortMode="server"` show the rows ungrouped. The client does not hold every row there.
- A pivot without `groupBy` does nothing. An unknown pivot column, a `groupable: false` column, and a `groupBy` column keep the grid grouped without the pivot.
- With `pageSize` set, a page holds `pageSize` top-level group rows. See [Client pagination](/docs/rows-pages-menus/client-pagination).
- A stream write to a value column and an appended row in a known group and key refresh the cells in place. Other changes rebuild the pivot.

<Callout type="warn">
If a number has more than 15 significant digits, the pivot cell loses its last digits. A pivot cell holds a JavaScript number, also in a server answer. On the client, a decimal string in a number column adds nothing to a pivot cell.
</Callout>

## Development warnings [#warnings]

Each of these warns once in development, with the prefix `[data-grid] `. Each text reads as follows, with `<id>` for the column id:

- `pivot needs groupBy: the grid ignores the pivot until groupBy names a column`
- `pivot names the column "<id>", which is unknown, not groupable, or a groupBy column, so the grid ignores the pivot`
- `the pivot holds more than 1,000,000 cells (group rows times generated columns), so the grid shows the rows ungrouped; filter the rows, or pivot or group by a column with fewer keys`

## Control the pivot [#control]

{/* props: DataGridSyncProps */}

| Prop | Type | Default |
|---|---|---|
| `pivot` | `PivotSpec` | Uncontrolled |
| `defaultPivot` | `PivotSpec` or a function | Off |
| `onPivotChange` | `(next: PivotSpec) => void` | None |

`onPivotChange` fires after `setPivot` changes the pivot. When the pivot turns off, it fires with `{ columnIds: [] }`. The action `setPivot` from `useDataGridActions` sets the pivot column. `setPivot(undefined)` turns it off. A `defaultPivot` function runs once on the client after mount.

## Menu and sort list [#menu]

- The [context menu](/docs/rows-pages-menus/context-menu) add-on adds **Pivot by** and **Turn off pivot** to the header menu while `groupBy` is set. The last **Ungroup** turns the pivot off too.
- Under a pivot, [`DataGridSortList`](/docs/sort-filter-search/sorting) offers the pivot column. Its sort orders the generated columns.
- `labels.pivot.pivotBy`, `labels.pivot.turnOff`, and `labels.pivot.sortColumn` name these items.

## Server mode [#server-mode]

`useDataGridServerRows` pivots on your server. Set `spec.pivot` together with `groupBy` and `aggregates`, or pass the hook the same `pivot`, `defaultPivot`, and `onPivotChange` props. Each groups request carries `spec.pivot`, and the server answers `pivotColumns` and one `pivotCells` list per group. [Pivot server rows](/docs/data-modes/pivot-server-rows) lists the request, the answer, and the checks.

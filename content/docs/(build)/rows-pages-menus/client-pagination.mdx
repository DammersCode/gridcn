Readers who want a numbered page, a page size, and a "21-40 of 240" label need a pager. Set `defaultPageSize` on `DataGridProvider` to page the view of a local array. `DataGridPaginationBar` renders the footer. If your server returns one page per request, see [Load rows by page](/docs/server-pagination/load-rows-page).

## Page the grid [#client-mode]

Pass the whole array as `data` and set `defaultPageSize` on the provider. The grid keeps every row and shows one page of the sorted and filtered view. `DataGridPaginationBar` with no props reads the pager from the provider:

```tsx
import {
  DataGridBody,
  DataGridHeader,
  DataGridProvider,
  DataGridRoot,
  defineColumns,
} from "@/components/data-grid/data-grid";
import { DataGridPaginationBar } from "@/components/data-grid-pagination/data-grid-pagination";

type Order = { id: string; customer: string };

const columns = defineColumns<Order>()([
  { id: "customer", header: "Customer", accessorKey: "customer" },
]);

function OrdersGrid({ rows }: { rows: Order[] }) {
  return (
    <DataGridProvider data={rows} columns={columns} defaultPageSize={25}>
      <DataGridRoot>
        <DataGridHeader />
        <DataGridBody />
      </DataGridRoot>
      <DataGridPaginationBar />
    </DataGridProvider>
  );
}
```

The provider keeps the page and the page size in its own state. `defaultPage` and `defaultPageSize` seed them once. To control a value, pass `page` with `onPageChange`, or `pageSize` with `onPageSizeChange`. `actions.setPage(page)` and `actions.setPageSize(size)` change them from code. `actions.setPageSize(null)` turns paging off.

<NewBadge />

If the data shrinks, the grid shows the last page. A page-size change keeps the first visible row on screen. A filter change goes back to page 1 and calls `onPageChange(1)`, also when the filter comes from props.

{/* props: UseDataGridPaginationClientOptions */}

| Prop | Type | Default |
| --- | --- | --- |
| `pageSize` | `number` | none (every row shows) |
| `defaultPageSize` | `number` | none |
| `onPageSizeChange` | `(pageSize: number) => void` | none |
| `page` | `number` | `1` |
| `defaultPage` | `number` | `1` |
| `onPageChange` | `(page: number) => void` | none |

## The whole array stays in the grid [#client-slice-vs-server-mode]

<NewBadge />

The grid holds every row. Only the rows on screen are one page. The footer shows the count of the rows that the sort and filter leave.

- **Sort and filter** cover every row, not the page. A header click sorts the whole array.
- **Quick search** marks matches on the current page and never filters.
- **Edits, inserts, and deletes** reach `onDataChange` with the whole array. Store it as it is.
- **Selection** follows row ids. A page change drops the checks, the cell range, and the active cell of rows that left the page. To keep the checks, pass `rememberCheckedRows`. The grid remembers each check by row id and restores it on a return to the page.
- **Streaming patches** reach every row, also rows on other pages.
- **Totals** from [pinned rows](/docs/rows-pages-menus/pinned-rows) cover every page. Pass `scope: "page"` to `useDataGridAggregate` to total the shown page only.
- **Export and print** cover every page. Pass `scope: "page"` to `exportGrid` or `printGrid` to write the shown page only.

Read the pager from your own components with `useDataGridPager()` under the provider. It returns the same controls that the bar uses. `useDataGridPager({ pageSizeOptions })` sets the sizes of the select.

## Page a list outside the grid [#slice-hook]

<NewBadge />

`useDataGridPagination` slices an array for a list that is not a grid. It returns `pageData`, the rows of the current page, and `pager` for the footer:

```tsx
import {
  DataGridPaginationBar,
  useDataGridPagination,
} from "@/components/data-grid-pagination/data-grid-pagination";

type Order = { id: string; customer: string };

function OrderList({ rows }: { rows: Order[] }) {
  const { pageData, pager } = useDataGridPagination({
    data: rows,
    defaultPageSize: 25,
  });
  return (
    <>
      <ul>
        {pageData.map((row) => (
          <li key={row.id}>{row.customer}</li>
        ))}
      </ul>
      <DataGridPaginationBar {...pager} />
    </>
  );
}
```

The hook takes the same `page`, `pageSize`, `defaultPage`, `defaultPageSize`, `onPageChange`, and `onPageSizeChange` as the provider, plus `pageSizeOptions` (default `[10, 25, 50, 100]`). Do not pass `pageData` to a grid. Page the grid with `pageSize` on the provider, so sort, filter, and totals cover every row.

## The pager footer

`DataGridPaginationBar` takes the `pager` object, or none inside a paged provider, plus these props:

{/* props: DataGridPaginationBarProps */}

| Prop | Type | Default |
| --- | --- | --- |
| `pageSizeOptions` | `readonly number[]` | `[10, 25, 50, 100]` |
| `className` | `string` | none |
| `labels` | `Partial<DataGridPaginationLabels>` | `labels.pagination` defaults |
| `windowSize` | `number` | `5` |
| `children` | `ReactNode` | the default layout |

The default layout has a range label, a page-size select, first and previous buttons, a sliding window of page numbers, and next and last buttons. The window stays centered on the current page. Inside `DataGridProvider` the bar reads the pager of the grid. Outside it, or for a list or a server grid, spread a `pager` onto it. Its root carries `data-grid-pagination`.

With `children`, the bar renders only the parts that you pass. This footer has no page numbers:

```tsx
import {
  DataGridPaginationBar,
  DataGridPaginationFirst,
  DataGridPaginationLast,
  DataGridPaginationNext,
  DataGridPaginationPrev,
  DataGridPaginationRange,
  type DataGridPaginationControls,
} from "@/components/data-grid-pagination/data-grid-pagination";

function CompactBar({ pager }: { pager: DataGridPaginationControls }) {
  return (
    <DataGridPaginationBar {...pager}>
      <DataGridPaginationRange />
      <div className="flex items-center gap-1">
        <DataGridPaginationFirst />
        <DataGridPaginationPrev />
        <DataGridPaginationNext />
        <DataGridPaginationLast />
      </div>
    </DataGridPaginationBar>
  );
}
```

The other parts are `DataGridPaginationPageSize` and `DataGridPaginationPages`. A part reads its controls and labels from the bar, so it throws outside `DataGridPaginationBar`. The default strings are the `labels.pagination` group. Override them through the `labels` prop of `DataGridPaginationBar`. The `labels` prop of the grid does not reach the footer. See [Labels](/docs/components-props/labels).

## Server mode

For server data, use `useDataGridServerRows`. It fetches each page and returns the `pager`. If you fetch with your own code, `useDataGridServerPager({ page, pageSize, totalRowCount, hasMore, onPageChange })` builds the pager and returns `{ pager }`. [Load rows by page](/docs/server-pagination/load-rows-page) owns the detail. [Keep pages in URL](/docs/server-pagination/keep-pages-url) covers a page in the address bar.

Users fix the same typo in many cells without editing each cell. `data-grid-find-replace` adds a panel with a Find field and a Replace field. `useDataGridFindReplace` returns the `plugin` that mounts the panel. The plugin binds <kbd>Mod</kbd>+<kbd>F</kbd> to open Find and <kbd>Shift</kbd>+<kbd>Alt</kbd>+<kbd>Enter</kbd> to open Find and Replace.

Pass the plugin to the grid. `findReplace.open()` opens the panel from your own button, with the Replace field hidden, as <kbd>Mod</kbd>+<kbd>F</kbd> does. `findReplace.open("replace")` shows the Replace field. `findReplace.close()` closes it:

```tsx
"use client";

import {
  DataGridBody,
  DataGridHeader,
  DataGridProvider,
  DataGridRoot,
  defineColumns,
} from "@/components/data-grid/data-grid";
import {
  useDataGridFindReplace,
} from "@/components/data-grid-find-replace/data-grid-find-replace";

type Person = { id: string; name: string };

const columns = defineColumns<Person>()([
  { id: "name", header: "Name", accessorKey: "name" },
]);

export function PeopleGrid({ rows }: { rows: Person[] }) {
  const findReplace = useDataGridFindReplace();

  return (
    <DataGridProvider
      defaultData={rows}
      columns={columns}
      plugins={[findReplace.plugin]}
    >
      <button onClick={() => findReplace.open()}>Find</button>
      <DataGridRoot className="h-96">
        <DataGridHeader />
        <DataGridBody />
      </DataGridRoot>
    </DataGridProvider>
  );
}
```

## Find

The Find field writes the grid's quick search. The highlights, the next and previous buttons, and the cells that Replace changes are the same cells. The toolbar search shows the same text. See [Quick search](/docs/sort-filter-search/quick-search).

The search is a literal text match. It ignores spaces at both ends of the Find text. Two toggles inside the Find field change the match:

- **Match case** matches letter case. It is off by default.
- **Whole cell** matches only cells that equal the Find text. It is off by default.

Find reads each cell as its search text: the `toSearchText` of its cell type, else its `toText`. A `select` cell searches its label. A `number` cell searches its plain value rounded to `decimals`, not its `format`, so `12.5` finds a cell that shows `$12.50`. A `date` cell searches its ISO text. A custom cell type can set `toSearchText`.

The status line is the last row of the panel. It shows `2 of 4 cells` for the current match, `No results` when nothing matches, and `Type to search` while the Find field is empty. The number gets a `+` when more than 1,000 cells match.

### Typing

The Find field waits for the `inputDebounceMs` prop of the grid (default 200 ms) after the last keystroke before it searches. <kbd>Enter</kbd> and blur search at once. Closing the panel with anything but <kbd>Escape</kbd> searches the waiting text.

## Replace

Replace swaps each occurrence of the Find text in the search text of the cell, then converts the result with `fromText`.

- **Replace** changes the current match and moves to the next one. After the last match, it moves to the first. When the active cell is a match, Replace changes that cell. When the new text still matches the Find text, the active cell still moves on.
- **Replace all** changes every matching cell in the view.

Each click writes one change with the source `"replace"`. With the [undo add-on](/docs/clipboard-undo/undo-redo) mounted, one undo reverts it. Replace all leaves the selection and the active cell where they are.

Replace skips a cell when:

- the column is read-only, as a flag or for that row,
- the replaced text cannot become a value of the type, such as `x` in a `number` column,
- the replaced text is longer than 100,000 characters,
- the column's `validate` rejects the new value. `onValidationError` receives these cells with the source `"replace"`.

The status line shows how many cells changed and how many Replace skipped. With an async `validate`, it shows `Validating…` until the batch settles.

### Where Replace works

Replace covers the visible columns of the rows in the view, on every page of a paged grid. Hidden columns, filtered-out rows, pinned rows, and the unloaded rows of a scroll-mode grid never change. With `scope: "selection"`, it covers only the selected cells.

One Replace all changes at most `replaceAllLimit` cells. When more cells match, the status line says so, and the next click continues. That click skips the cells the earlier one changed, even when the replacement contains the find text. A change to the find text, the replacement, or an option starts over.

The chevron button at the start of the Find row shows and hides the Replace field. Every open sets it: <kbd>Mod</kbd>+<kbd>F</kbd>, `open()`, and `open("find")` hide it, and <kbd>Shift</kbd>+<kbd>Alt</kbd>+<kbd>Enter</kbd> and `open("replace")` show it. In a `readOnly` grid, the Find field works, the chevron is hidden, and Replace stays disabled. While a cell editor is open, Replace does nothing.

### Check a replace before it runs

`processReplace` runs after the panel builds the list of changes and before it writes them. It gets the `plan` and a `signal`. Return the plan to write, or `false` to cancel:

```tsx
import {
  useDataGridFindReplace,
} from "@/components/data-grid-find-replace/data-grid-find-replace";

export function useCheckedFindReplace() {
  return useDataGridFindReplace({
    processReplace: async ({ plan, signal }) => {
      const response = await fetch("/api/check-edit", {
        method: "POST",
        body: JSON.stringify(plan.patches),
        signal,
      });
      return response.ok ? plan : false;
    },
  });
}
```

The hook can drop, add, or change patches. A patch holds the new value of one cell. The grid runs the column's `validate` on it. A string for a non-string cell goes through `fromText` first. An unparseable one is skipped. The panel skips a returned patch on a hidden column with the reason `"hidden"`.

The replace is cancelled, and the status line says `Replace cancelled`, when:

- the returned plan holds more than `replaceAllLimit` patches,
- the hook returns `false`, returns something that is not a plan, or rejects,
- a row that the plan writes changes or goes away while the hook runs,
- the grid turns `readOnly`, or a cell editor opens, while the hook runs.

## Keyboard

| Key | Where | Action |
|---|---|---|
| <kbd>Mod</kbd>+<kbd>F</kbd> | grid | Opens the panel with the cursor in Find. The Replace field stays hidden. |
| <kbd>Shift</kbd>+<kbd>Alt</kbd>+<kbd>Enter</kbd> | grid | Opens the panel with the cursor in Find and the Replace field shown. |
| <kbd>Enter</kbd> | Find | Goes to the next match. |
| <kbd>Shift</kbd>+<kbd>Enter</kbd> | Find | Goes to the previous match. |
| <kbd>Enter</kbd> | Replace | Replaces the current match. |
| <kbd>Mod</kbd>+<kbd>Enter</kbd> | Replace | Replaces all matches. |
| <kbd>Escape</kbd> | panel | Closes the panel and drops find text that is still waiting. |

Focus stays in the panel field while Enter, Next, or Previous moves the active cell to a match. To move focus into the grid, call `api.focus()` on the grid ref. When the panel opened from the grid, <kbd>Escape</kbd> returns focus to the header button or grid. <kbd>Mod</kbd> is <kbd>Cmd</kbd> on macOS and <kbd>Ctrl</kbd> elsewhere. Outside the grid, <kbd>Mod</kbd>+<kbd>F</kbd> opens the browser's find bar. To change a key, bind `openFindReplace` or `openFind` in the grid's `keymap`.

With `DataGridSearch` also on screen, <kbd>Mod</kbd>+<kbd>F</kbd> opens this panel and takes the key from the `focusSearch` action, which is then unbound. Bind `focusSearch` in `keymap` to reach the toolbar search with another key.

## Server mode

Find and Replace work on the rows the grid holds: the loaded rows in scroll mode, and the current page in pages mode. A client grid that pages its view holds every row. Its search and "Replace all" cover every page. A jump to a match changes the page. A search that finds nothing does not mean the server result has no match.

A grid with a `totalRowCount`, or with a server `sortMode` or `filterMode`, shows "Searches loaded rows only" under the fields. To hide the note, set `labels.findReplace.scopeLoadedRows` to `""`.

### Find over the result

Set `findScope: "result"` when your server narrows the rows by `spec.searchText`. The count line then shows the size of the result, such as "11 rows match". Next and Previous go on into unloaded rows. Scroll mode scrolls to the next block. Pages mode asks for the next page. Replace and Replace all change loaded rows only.

Replace writes through the same path as an edit. `onDataChange` and `onSave` receive each Replace as one change with the source `"replace"`. A refused save reverts the refused cells. See [Save edits](/docs/save-server/save-edits).

## Options

{/* props: UseDataGridFindReplaceOptions */}

| Prop | Type | Default | Description |
|---|---|---|---|
| `scope` | `"view" \| "selection"` | `"view"` | Which cells Replace covers. |
| `replaceAllLimit` | `number` | `10000` | Most cells one Replace all changes. Clamped to 1 to 100,000. |
| `processReplace` | `({ plan, signal }) => plan \| false \| Promise` | none | Checks or changes the plan before it writes. `false` cancels. |
| `findScope` | `"loaded" | "result"` | `"loaded"` | `"result"` steps through the whole server result. See [Find over the result](#find-over-the-result). |
| `className` | `string` | none | Classes merged into the panel root. |

### planReplace

`planReplace(state, find, replacement, options)` is the pure function behind the buttons. It returns `{ patches, skipped, remaining }` and writes nothing. Pass `patches` to `actions.updateCells(patches, { source: "replace" })` to write them. Each entry of `skipped` has a `reason`: `"readonly"`, `"unparseable"`, `"too-long"`, `"no-occurrence"`, or `"hidden"`. The panel adds `"hidden"` for a `processReplace` patch on a hidden column. Find and replacement text longer than 1,000 characters is cut.

### Labels

The panel strings live under `labels.findReplace`. See [Labels and i18n](/docs/theme-style-language/labels-i18n).

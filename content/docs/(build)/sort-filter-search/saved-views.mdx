Users set up a grid the way they like it, then lose it on the next visit. `data-grid-views` saves the sort, the filters, the search text, and the column layout under a name and opens it with one click. `DataGridViews` is the toolbar button. `useDataGridViews` is the hook behind it.

Place the button inside the provider:

```tsx
"use client";

import {
  DataGridBody,
  DataGridHeader,
  DataGridProvider,
  DataGridRoot,
  defineColumns,
} from "@/components/data-grid/data-grid";
import {
  DataGridToolbar,
} from "@/components/data-grid-toolbar/data-grid-toolbar";
import {
  DataGridViews,
} from "@/components/data-grid-views/data-grid-views";

type Order = { id: string; customer: string };

const columns = defineColumns<Order>()([
  { id: "customer", header: "Customer", accessorKey: "customer" },
]);

function OrdersGrid({ rows }: { rows: Order[] }) {
  return (
    <DataGridProvider data={rows} columns={columns}>
      <DataGridToolbar>
        <DataGridViews storage="orders-views" />
      </DataGridToolbar>
      <DataGridRoot>
        <DataGridHeader />
        <DataGridBody />
      </DataGridRoot>
    </DataGridProvider>
  );
}
```

With no props, views persist in `localStorage` under `gridcn-views`. Grids with the same columns can share it and stay in sync. Two mounted grids with other columns on one key warn in development, so give such a grid its own `storage` key. If `localStorage` is blocked or full, the views stay in memory for the page.

## What a view holds [#what-a-view-holds]

A view holds the sort, the `groupBy` columns, and the filters, with their groups, the join of the top level, and custom operators. A negated group stays negated. It holds the search text with its two options, match case and whole cell. It holds the column layout: order, hidden columns, pins, and widths. Under [pivot](/docs/rows-pages-menus/pivot), it holds the pivot column and up to 200 generated column widths. A view holds no rows, no selection, no page, and no scroll position.

Opening a view runs the same actions as a user gesture, and only for the parts that differ from the grid. The change callbacks of a controlled `sortState`, `filterState`, `searchText`, `pivot`, or `columnLayout` fire for those parts.

## The button [#the-button]

The button shows the name of the active view. A "Modified" badge appears when the grid differs from that view. The popover has:

- one row per view: open, default star, rename, and delete (the second press deletes)
- "Update" for the active view, shown only while the grid differs from it
- a name field and "Save as new view"
- a text area with "Export active view" and "Import view"

Opening the active view again reverts the changes. Every control sits in the tab order of the popover. <kbd>Enter</kbd> saves a rename and <kbd>Esc</kbd> cancels it. A polite status message announces each action, and a failure shows as an alert with a Retry button.

## Default view [#default-view]

The star marks one view as the default. After the views load, the default view applies if all of these hold:

- `enableDefaultView` is not `false`.
- `value` and `defaultValue` are both unset.
- The grid still holds its first state.

With both add-ons mounted, a [URL state](/docs/sort-filter-search/url-state) link with a param that changes the first state wins over the default view.

`value` and `onValueChange` control which view is active, and `defaultValue` seeds it once:

```tsx
"use client";

import { useState } from "react";
import { DataGridViews } from "@/components/data-grid-views/data-grid-views";

export function ControlledViews() {
  const [viewId, setViewId] = useState<string | null>(null);

  return <DataGridViews value={viewId} onValueChange={setViewId} />;
}
```

When `value` changes, the hook opens that view. A pick only calls `onValueChange`. Saving or importing a view opens it at once and then calls `onValueChange` with its id.

## Storage [#storage]

A storage adapter has two functions. `load` returns the stored document, or `undefined` for none. `save` receives the whole document. Both can be async. `load` gets a signal that aborts on unmount. The hook checks everything that `load` returns, so a hand-edited document cannot break the grid.

Throw from `load` when the store cannot be read. The popover then shows a Retry button and runs no save, so the stored views stay safe. A document with an unknown `version` counts as a read failure. The grid never saves a document over 1,000,000 characters.

This adapter keeps the views on your server:

```ts
import type {
  DataGridViewsStorage,
} from "@/components/data-grid-views/data-grid-views";

const serverViews: DataGridViewsStorage = {
  load: async ({ signal }) => {
    const response = await fetch("/api/grid-views/orders", { signal });
    if (response.status === 404) return undefined;
    if (!response.ok) throw new Error("Loading views failed");
    return response.json();
  },
  save: async (document) => {
    const response = await fetch("/api/grid-views/orders", {
      method: "PUT",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(document),
    });
    if (!response.ok) throw new Error("Saving views failed");
  },
};
```

Pass it as `storage`. A thrown error from `save` shows in the popover with a Retry button, and `onError` receives it. Saves that start while another save runs collapse into one, so the last document wins. `createLocalStorageViewsStorage(key)` is the default adapter. `createMemoryViewsStorage(seed?)` keeps views for the life of the page.

The default adapter listens to the `storage` event, so a save in one tab reloads the views of another tab on the same key. A custom adapter that offers `subscribe` gets the same reload.

## Share a view as text [#share-a-view-as-text]

"Export active view" writes the view as JSON into the text area. "Import view" reads that text and adds it as a new view. Import bounds the text and checks it against the live columns:

- Import refuses text over 100,000 characters, and anything but a gridcn view file.
- An entry for a column that does not exist, or that opted out with `sortable`, `groupable`, or `filterable` set to `false`, goes away. A sort or filter on a column that the file hides goes away too. The status message reports how many entries it left out.
- A built-in operator with a value of the wrong shape goes away. An operator that a column or its cell type registers in `filter.operators` keeps a value of the shape its `input` names. Any other shape drops the filter.
- A column with `choices` keeps the blank entry and the set filter values that match a choice or a loaded value. The match ignores case. With `filterMode="server"` or `fetchFilterValues`, the server lists the values, so every value stays.
- An `isAnyOf` list is cut to 1,000 entries. An `isNoneOf` list or a custom operator list over 1,000 entries drops the filter.
- A view keeps at most 64 sorts, 4 group columns, 64 filters, and 16 filter groups. A filter value over 1,000 characters drops the filter.
- The name of a view has at most 80 characters, and a stored view needs an id of at most 64 characters.
- A column id has no length limit. A stored view keeps ids of columns the grid lacks, and applying the view skips them. A column width over 10,000 px goes away. Each layout list is cut to 1,000 entries. The search text is cut to 500 characters. The document keeps at most 50 views.

## Use the hook [#use-the-hook]

`useDataGridViews(options)` takes the options of the button and returns the state and the actions for your own UI. Call it inside the provider. The full lists are on [Saved views options](/docs/add-options/sort-filter-search/saved-views-options):

```tsx
"use client";

import { useDataGridViews } from "@/components/data-grid-views/data-grid-views";

export function SaveViewButton() {
  const views = useDataGridViews({ storage: "orders-views" });

  return <button onClick={() => views.saveView("My view")}>Save</button>;
}
```

### Limits [#limits]

A save never cuts a view. `overLimit` names the part that is over a limit. It is `"sorts"`, `"filters"`, `"search"`, or `"layout"`. An entry for a column that the grid lacks is not over a limit.

A filter whose value does not fit its operator, such as a list on `contains`, also counts as over the `"filters"` limit. A filter without a value on an operator that takes one, such as `equals`, is not over a limit.

"Save as new view" and "Update" are off with a line for that part. `saveView` returns `null` and `updateView` returns `false`.

## Server mode [#server-mode]

A view stores the grid state only, so it works in every data mode:

- **Local array and client pagination.** Opening a view sorts and filters the local rows again.
- **Server pagination and scroll mode** with `sortMode="server"` or `filterMode="server"`. Opening a view calls `onSortChange`, `onFilterChange`, and `onSearchTextChange` for the parts that differ, and `useDataGridServerRows` sends the new spec. Every set filter value stays, and your server checks the values. For a pivot, pass `pivot` and `onPivotChange` to the grid and `spec.pivot` to the hook.
- **Controlled state.** Your props receive the change callbacks.

A view saves no page number. A view that changes the sort, the filters, or the search text sends server rows back to page 1. A layout-only view keeps the page.

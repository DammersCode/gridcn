Users set up a grid the way they like it, then lose it on the next visit. `data-grid-views` saves the sort, the filters, the search text, and the column layout under a name and opens it with one click. `DataGridViews` is the toolbar button. `useDataGridViews` is the hook behind it.

Place the button inside the provider:

```tsx
import {
  DataGridBody,
  DataGridHeader,
  DataGridProvider,
  DataGridRoot,
  defineColumns,
} from "@/components/data-grid/data-grid";
import { DataGridToolbar } from "@/components/data-grid-toolbar/data-grid-toolbar";
import { DataGridViews } from "@/components/data-grid-views/data-grid-views";

type Order = { id: string; customer: string };

const columns = defineColumns<Order>()([
  { id: "customer", header: "Customer", accessorKey: "customer" },
]);

function OrdersGrid({ rows }: { rows: Order[] }) {
  return (
    <DataGridProvider data={rows} columns={columns} getRowId={(row) => row.id}>
      <DataGridToolbar>
        <DataGridViews storageKey="orders-views" />
      </DataGridToolbar>
      <DataGridRoot>
        <DataGridHeader />
        <DataGridBody />
      </DataGridRoot>
    </DataGridProvider>
  );
}
```

With no props, views persist in `localStorage` under `gridcn-views`. Every grid on the same origin shares that key, so give each grid its own `storageKey`. If `localStorage` is blocked or full, the views stay in memory for the page. The popover shows a save error with a Retry button.

## What a view holds [#what-a-view-holds]

A view holds the sort and the filters, with their groups and custom operators. It holds the search text with its two options, match case and whole cell. It holds the column layout: order, hidden columns, pins, and widths. A view holds no rows, no selection, no page, and no scroll position.

Opening a view runs the same actions as a user gesture, and only for the parts that differ from the grid. The change callbacks of a controlled `sortState`, `filterState`, `searchText`, or `columnLayout` fire for those parts.

## The button [#the-button]

The button shows the name of the active view. A "Modified" badge appears when the grid differs from that view. The popover has:

- one row per view: open, default star, rename, and delete (the second press deletes)
- "Update" for the active view, shown only while the grid differs from it
- a name field and "Save as new view"
- a text area with "Export active view" and "Import view"

Opening the active view again reverts the changes. Every control is a native button or text field in the tab order of the popover. The default star is a toggle button with `aria-pressed`, and the active view has `aria-current`. Renaming accepts <kbd>Enter</kbd> to save and <kbd>Esc</kbd> to cancel. A polite status message announces each action, and a load or save failure shows as an alert with a Retry button.

## Default view [#default-view]

The star marks one view as the default. After the views load, the default view applies if all of these hold:

- `enableDefaultView` is not `false`.
- `value` and `defaultValue` are both unset.
- The grid still holds its start state.

A grid that something else already changed keeps its state. When you mount both add-ons, a link from [URL state](/docs/sort-filter-search/url-state) with any param that changes the first state wins over the default view. Sort, filter, search, and column layout params all count.

`value` and `onValueChange` control which view is active, and `defaultValue` seeds it once:

```tsx
const [viewId, setViewId] = useState<string | null>(null);

<DataGridViews value={viewId} onValueChange={setViewId} />;
```

When `value` changes, the hook opens that view. A pick only calls `onValueChange`. The grid changes when you pass the new `value` back. Saving or importing a view opens it at once and then calls `onValueChange` with its id.

## Storage [#storage]

A storage adapter has two functions. `load` returns the stored document, or `undefined` for none. `save` receives the whole document. Both can be async. `load` gets a signal that aborts on unmount. The hook checks everything that `load` returns, so a hand-edited document cannot break the grid.

Throw from `load` when the store cannot be read. The popover then shows a Retry button and runs no save, so the stored views stay safe. A document with an unknown `version` counts as a read failure. A document over 1,000,000 characters is never saved.

This adapter keeps the views on your server:

```ts
import type { DataGridViewsStorage } from "@/components/data-grid-views/data-grid-views";

const serverViews: DataGridViewsStorage = {
  load: async ({ signal }) => {
    const response = await fetch("/api/grid-views/orders", { signal });
    if (response.status === 404) return undefined;
    if (!response.ok) throw new Error("Loading views failed");
    return response.json();
  },
  save: async (document) => {
    const response = await fetch("/api/grid-views/orders", {
      method: "PUT",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(document),
    });
    if (!response.ok) throw new Error("Saving views failed");
  },
};
```

Pass it as `storage`. A thrown error from `save` shows in the popover with a Retry button, and `onError` receives it. The change stays on screen. Saves that start while another save runs collapse into one, so the last document wins. `createLocalStorageViewsStorage(key)` is the default adapter. `createMemoryViewsStorage(seed?)` keeps views for the life of the page. Two tabs that share one `localStorage` key overwrite each other's saves.

## Share a view as text [#share-a-view-as-text]

"Export active view" writes the view as JSON into the text area. "Import view" reads that text and adds it as a new view. Import bounds the text and checks it against the live columns:

- Import refuses text over 100,000 characters, and anything but a gridcn view file.
- A sort, filter, or layout entry for a column that does not exist, or that opted out with `sortable: false` or `filterable: false`, goes away. The status message reports how many entries it left out.
- A built-in operator with a value of the wrong shape goes away. An operator that a column or its cell type registers in `filterOperators` keeps a value of the shape its `input` names. Any other shape drops the filter.
- An `isAnyOf` list is cut to 1,000 entries. An `isNoneOf` list or a custom operator list over 1,000 entries drops the filter.
- A view keeps at most 16 sorts, 64 filters, and 16 filter groups. A filter value over 1,000 characters drops the filter.
- A column id over 200 characters goes away when the stored document loads. It also goes away from a view file, unless a column of the grid has that id. A column width over 10,000 px goes away. Each of `order`, `hidden`, `widths`, and `pins` in a layout is cut to 1,000 entries. The search text is cut to 500 characters. The document keeps at most 50 views.

## Use the hook [#use-the-hook]

`useDataGridViews(options)` takes the same options as the button and returns the state and the actions for your own UI. Call it inside the provider. The full lists are on [Saved views options](/docs/add-options/sort-filter-search/saved-views-options):

```tsx
const views = useDataGridViews({ storage: serverViews });

<button onClick={() => views.saveView("My view")}>Save</button>;
```

### Limits [#limits]

<NewBadge />

A save never cuts a view. `overLimit` names the part that is over a limit. It is `"sorts"`, `"filters"`, `"search"`, or `"layout"`. These are the values of `OverLimitPart`.

"Save as new view" and "Update" are off with a line for that part. `saveView` returns `null` and `updateView` returns `false`. Remove a sort or a filter, shorten the search text, reset the column layout, or remove the settings of the long-id column to save. The limits are listed under [Share a view as text](#share-a-view-as-text).

## Server mode [#server-mode]

A view stores the grid state only, so it works in every data mode:

- **Local array and client pagination.** Opening a view sorts and filters the local rows again.
- **Server pagination and scroll mode** with `sortMode="server"` or `filterMode="server"`. Opening a view calls `onSortChange`, `onFilterChange`, and `onSearchTextChange` for the parts that differ, and `useDataGridServerRows` sends the new spec. A filter on a set column keeps its saved values even when they are not in the `choices` of the column.
- **Controlled state.** Your props receive the change callbacks.

A view saves no page number. A view that changes the sort, the filters, or the search text sends server rows back to page 1. A view that changes only the layout keeps the page.

A view can hold up to 16 sorts and a search text of 500 characters. See [Limits](#limits).

The `parseServerSpec` <NewBadge /> defaults allow 8 sorts and 200 characters, so raise `maxSorts` and `maxSearchLength`. See [Match the limits to the grid](/docs/contracts/server-rows-contract#match-limits).

`data-grid-url-state` syncs the sort, filter, search, column layout, and pagination state of the grid with the URL through [nuqs](https://nuqs.dev). A reload or a shared link restores the view.

The sample below also uses the [toolbar add-on](/docs/sort-filter-search/toolbar) for the search box and the filter menu. Install it as well.

## Usage

Mount `<DataGridUrlState>` once inside `<DataGridProvider>`. Put a `NuqsAdapter` for your framework somewhere above it in the tree:

```tsx
"use client";

import { NuqsAdapter } from "nuqs/adapters/next/app";
import {
  DataGridBody,
  DataGridHeader,
  DataGridProvider,
  DataGridRoot,
  defineColumns,
} from "@/components/data-grid/data-grid";
import {
  DataGridFilterMenu,
  DataGridSearch,
  DataGridToolbar,
} from "@/components/data-grid-toolbar/data-grid-toolbar";
import { DataGridUrlState } from "@/components/data-grid-url-state/data-grid-url-state";

type Order = { id: string; customer: string; total: number };

const columns = defineColumns<Order>()([
  { id: "customer", header: "Customer", accessorKey: "customer" },
  { id: "total", header: "Total", accessorKey: "total", type: "number" },
]);

export function OrdersGrid({ rows }: { rows: Order[] }) {
  return (
    <NuqsAdapter>
      <DataGridProvider
        defaultData={rows}
        columns={columns}
        getRowId={(row) => row.id}
      >
        <DataGridUrlState prefix="orders" />
        <DataGridToolbar>
          <DataGridSearch />
          <DataGridFilterMenu />
        </DataGridToolbar>
        <DataGridRoot className="h-96">
          <DataGridHeader />
          <DataGridBody />
        </DataGridRoot>
      </DataGridProvider>
    </NuqsAdapter>
  );
}
```

`nuqs/adapters/next/app` is the Next.js App Router adapter. The [nuqs adapter docs](https://nuqs.dev/docs/adapters) list the adapters for other routers.

<Callout type="warn" title="NuqsAdapter must not be nested">
  If your app already renders a `NuqsAdapter` near the root, drop the inner one shown above. `DataGridUrlState` needs one `NuqsAdapter` somewhere above it.
</Callout>

<Callout type="warn" title="Suspense required when statically prerendering">
  During a production build, a statically prerendered Next.js page that reads `useSearchParams` from a Client Component needs a `<Suspense>` boundary, or the build fails. Wrap the grid in one.
</Callout>

## Keys and prefix [#prefix]

The add-on writes the keys `sort`, `filter`, `q`, `cols`, `hide`, `widths`, and `pins`. `prefix` namespaces them, so several grids can share one page. `<DataGridUrlState prefix="orders" />` writes `orders_sort`, `orders_filter`, and `orders_q`.

A filter group <NewBadge /> is a segment `[or` or `[and`, then its rows, then a `]` segment:

```txt
?filter=country:equals:X,[or,name:contains:A,name:contains:B,]
```

The characters `[` and `]` are always percent-encoded inside ids and values, so a value cannot imitate a group. A group holds one more group at most. A deeper group drops with its rows. The parser skips a stray `]`, closes a group left open at the end, and drops an empty group.

An older link can carry a `join=or` param. The grid reads it once: when the `filter` param has no group, the rows wrap in one `or` group. Every filter write removes the param. With a `prefix`, the grid reads `<prefix>_join` the same way.

## Behavior

- URL params apply to the store once, on mount. A missing param keeps the grid's initial state. After that, the store drives the URL.
- `useDataGridUrlState()` returns `applyFromUrl()`. Call it when the URL changed outside the grid's own writes, such as back and forward navigation. The grid then mirrors the URL. A param that is missing from the URL clears its sort, filter, or search, and resets its layout part to the starting layout. It reads the params of the current render, so call it after your router has updated them.
- Every write uses `history: "replace"`, so changes never add browser history entries.
- Sort and filter writes are immediate. The search input waits for the typing to pause (`inputDebounceMs`) before the store changes, so typing does not spam the history.
- The grid drops a sort or filter for a removed or hidden column. It drops a sort for a `sortable: false` column, and a filter for a `filterable: false` column. In development, a warning names each dropped column. The grid also drops a layout entry for a removed column, with one warning that counts them.

A hand-edited URL cannot express an unbounded view. The `filter` param reads at most 256 segments and keeps at most 64 rows and 16 groups. An `isAnyOf` list keeps at most `max(number of choices, 64)` values for a column with `choices`, and 1,000 values for any other column. An `isNoneOf` list over the same bound drops the whole segment. The URL writes an empty list entry (the blank value) as a lone `%`. The `sort` param reads at most 256 segments and keeps at most 64 sorts, one per column, so the first segment of a column wins. A URL beyond these limits gives fewer filters and sorts.

<Callout type="warn" title="A URL-applied sort has no arrow in the default config">
  `?sort=name:asc` reorders the rows, but the sort arrow shows only with `headerClickBehavior="sort"`. Set it, or install `data-grid-sort-list`, so users can see and clear the sort.
</Callout>

## Column layout

The `layout` option picks which parts of the column layout go into the URL. The default is `["order", "hidden"]`. Widths depend on the screen of the viewer, so `widths` and `pins` are opt-in. `layout={[]}` turns layout sync off. `layout={["order", "hidden", "widths"]}` adds the widths and writes a URL such as `?cols=city,name,age&hide=age&widths=name:240`.

| Part | Key | Format |
| --- | --- | --- |
| `order` | `cols` | Column ids, comma-separated. |
| `hidden` | `hide` | Column ids, comma-separated. `-` means no hidden column. |
| `widths` | `widths` | `id:px` pairs, whole pixels. |
| `pins` | `pins` | `id:s` or `id:e` pairs. The codes `l` and `r` read as `s` and `e`. `-` means no pinned column. |

- A part is in the URL only while it differs from the layout the grid started with.
- The URL changes once per committed gesture: a drop, a resize release, a pin, or a hide. A resize drag writes nothing while the pointer moves.
- The grid drops an id that matches no column. A column missing from `cols` keeps its place at the end.
- The grid ignores a key longer than 16,384 characters, and it reads at most 1,024 entries of a key.

## Pagination

`useDataGridUrlPagination` syncs `page` and `pageSize` with the URL, apart from `<DataGridUrlState>`. Pagination has no store slot, so it is a standalone hook. The parent fetches `rows` for the page and page size in the URL:

```tsx
"use client";

import { DataGrid, defineColumns } from "@/components/data-grid/data-grid";
import {
  DataGridPaginationBar,
  useDataGridPagination,
} from "@/components/data-grid-pagination/data-grid-pagination";
import { useDataGridUrlPagination } from "@/components/data-grid-url-state/data-grid-url-state";

type Order = { id: string; customer: string };

const columns = defineColumns<Order>()([
  { id: "customer", header: "Customer", accessorKey: "customer" },
]);

export function OrdersPage({ rows, total }: { rows: Order[]; total: number }) {
  const url = useDataGridUrlPagination({ totalRowCount: total });
  const { pager } = useDataGridPagination({ totalRowCount: total, ...url });

  return (
    <>
      <DataGrid data={rows} readOnly columns={columns} getRowId={(r) => r.id} />
      <DataGridPaginationBar {...pager} />
    </>
  );
}
```

`page` is 1-based and leaves the URL at 1. A `page` beyond 1,000,000 falls back to 1. `pageSize` leaves the URL when it equals `defaultPageSize` (default 25). A `pageSize` outside the default list 10, 25, 50, 100 falls back to the default, and the hook returns the resolved `pageSizeOptions`. With `totalRowCount`, an out-of-range `page` clamps to the last page once the count is positive, and the clamped value goes back to the URL. A change of `pageSize` resets the URL `page` to 1.

## Server mode

The add-on restores sorts, filters, and search text through the store actions. Those actions call `onSortChange`, `onFilterChange`, and `onSearchTextChange` as any change does. With `sortMode="server"` and `filterMode="server"`, a link restores the spec and the grid never reorders or hides the rows you load. `useDataGridServerRows` sets both modes. Without the hook, set both modes on a scroll-mode grid. Otherwise the add-on sorts and filters the partial `data` on the client.

The request is the restored spec, and the answer is the rows for it. Fetch the rows for the restored spec on mount. For page numbers in the URL, see [Keep pages in URL](/docs/server-pagination/keep-pages-url).

On a column with `choices`, a restored `isAnyOf` or `isNoneOf` list keeps at most `max(number of choices, 64)` values.

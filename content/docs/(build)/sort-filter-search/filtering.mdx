A filter hides the rows that fail a condition on one column. `filterState` holds the filters as a list. The top level combines its entries with "and". A group inside the list combines its own entries with "and" or "or". Users build the list in the `DataGridFilterMenu` popover, and **Clear all** empties it. Code sets it with `actions.setFilters()`, and `setFilters([])` clears it.

<ComponentPreview name="data-grid-sorting-filtering-demo" />

`DataGridFilterMenu` comes with the [toolbar add-on](/docs/sort-filter-search/toolbar#wiring). Put it inside `<DataGridToolbar>`. Filtering from code needs no add-on.

## Filter from code

A `FilterSpec` is one condition: `columnId`, `operator`, and `value`. A `FilterGroup` is `{ join, filters }`. Pass both kinds to `actions.setFilters()`, or seed the list once with `defaultFilterState`:

```tsx
"use client";

import {
  DataGridBody,
  DataGridHeader,
  DataGridProvider,
  DataGridRoot,
  defineColumns,
  useDataGridActions,
  type FilterNode,
} from "@/components/data-grid/data-grid";

type Order = { id: string; country: string; name: string };

const columns = defineColumns<Order>()([
  { id: "country", header: "Country", accessorKey: "country" },
  { id: "name", header: "Name", accessorKey: "name" },
]);

const filters: FilterNode[] = [
  { columnId: "country", operator: "equals", value: "NL" },
  {
    join: "or",
    filters: [
      { columnId: "name", operator: "contains", value: "A" },
      { columnId: "name", operator: "contains", value: "B" },
    ],
  },
];

function ApplyButton() {
  const actions = useDataGridActions();
  return <button onClick={() => actions.setFilters(filters)}>Apply</button>;
}

export function OrdersGrid({ rows }: { rows: Order[] }) {
  return (
    <DataGridProvider
      defaultData={rows}
      columns={columns}
      getRowId={(row) => row.id}
    >
      <ApplyButton />
      <DataGridRoot className="h-96">
        <DataGridHeader />
        <DataGridBody />
      </DataGridRoot>
    </DataGridProvider>
  );
}
```

After the click, a row stays if its country is NL and its name contains A or B. A group with `join: "and"` needs every child to match. A group with `join: "or"` needs one child. Any other `join` value acts as `"and"`, and an empty group matches every row.

A group can contain one level of nested groups. `setFilters` drops a group nested deeper, with its rows. `filterId` is an optional stable key for a row or group. The store adds one when it is missing.

## Operators

By default, every column offers the text operators: `contains`, `notContains`, `equals`, `notEquals`, `startsWith`, `endsWith`, `empty`, and `notEmpty`. `number` and `date` columns add `gt`, `gte`, `lt`, `lte`, and `isBetween`. `text`, `number`, `date`, `select`, and untyped columns add `isAnyOf` and `isNoneOf`. The `longText`, `url`, and `checkbox` columns offer the text operators only.

| Operator | `value` | Matches a row when |
|---|---|---|
| Text operators | `string` | The cell text compares to the value. Case does not matter. |
| `gt`, `gte`, `lt`, `lte` | `string` | The cell is not blank and compares to the value. |
| `isBetween` | `[from, to]` | The cell is not blank and lies between both bounds, inclusive. An empty bound is open. |
| `isAnyOf` | `string[]` | The cell text equals one entry. Case does not matter. An empty list matches no row. |
| `isNoneOf` | `string[]` | The cell text equals no entry. Case does not matter. An empty list matches every row. |
| `empty`, `notEmpty` | none | The cell text is empty, or is not. |

Every value is text, even for number and date columns, as in `{ columnId: "stock", operator: "lt", value: "5" }`. A comparison reads both sides as numbers when both parse. Otherwise it compares them as text.

The `filter` object of a column changes this behavior for that column:

- `filter.operators` replaces the list of operators the filter menu offers.
- `filter.match(value, filter)` replaces the built-in test. It receives the raw cell value and returns whether the row passes. A thrown error fails the row. A `text` or untyped column with `filter.match` has no `isAnyOf`, `isNoneOf`, or header filter button, unless `filter.operators` lists them. A cell type with `filter.match` and no `filter.operators` does the same. `number`, `date`, and `select` keep them.
- `filterable: false` keeps the column out of the filter menu and the header filter.
- `filter.compare(text, bound)` orders the cells of a column for `gt`, `gte`, `lt`, `lte`, and `isBetween`. Use it for ranks or versions. A result of `NaN` or a thrown error falls back to the default order. A column with `filter.match` ignores `filter.compare` for built-in operators.

A cell type takes the same `filter` object, with a fourth member, `valueInput`, for the value widget of the filter row. Each member of the column wins over the same member of the cell type.

### Custom operators [#custom-operators]

A column can list its own operators next to the built-in ones. List an object with an `id` and a `label` in `filter.operators`. The filter menu shows the `label`, and the filter stores the `id`. A `FilterOperator` is a built-in operator or any string. `BuiltInFilterOperator` is the closed set of built-in operators.

This column registers one operator:

```tsx
const inRegion = {
  id: "inRegion",
  label: "is in region",
  input: "single",
} as const;

const columns = defineColumns<Order>()([
  {
    id: "city",
    header: "City",
    accessorKey: "city",
    filter: { operators: ["contains", inRegion] },
  },
]);
```

{/* props: CustomFilterOperator */}

| Field | Meaning |
|---|---|
| `id` | Stored in `filterState`, in the URL, and in the spec your server receives. It must not equal a built-in operator. |
| `label` | The text of the operator select. |
| `input` | The value shape: `"single"` (default), `"range"` for a from and to pair, `"list"` for a list of values, or `"none"` for no value. |
| `match(text, filter)` | Decides on the client whether a row passes. `text` is the cell text that the built-in operators compare. A thrown error fails the row. |

With `filterMode="server"`, the grid never calls `match`, so leave it out. In client mode, a custom operator without `match` does not narrow rows, and the grid warns once in development. `useDataGridUrlState` writes a custom `id` to the URL and reads it back.

[Custom operators on the server](/docs/contracts/server-rows-contract#custom-operators) maps the `id` to a query.

An empty grid shows `labels.grid.noResults` ("No results") when a filter or a server search hides every row. A grid with no rows and no filter shows `labels.grid.emptyState`.

## Filter menu

The popover lists the filter tree. The first entry of the top level and of each group reads "Where". Later top-level entries read "And". Later entries of a group show a select with "And" and "Or". That select sets the join of the whole group, so all its entries show the same word.

Each row has a column select, an operator select, and a value input. It also has a remove button and a drag handle. The foot of the popover holds the "Add filter" and "Add group" buttons. Each group has its own "Add filter" button. A top-level group also has its own "Add group" button.

A new group takes the opposite join of its parent, so a group in the top level starts as "Or". The value input follows the cell type. `isBetween` shows two inputs, and `isAnyOf` and `isNoneOf` show a checkbox list.

The menu offers the visible columns. A filter on a hidden column keeps applying, and its row shows that column with its own operators. Pass `allColumns` to offer hidden columns for new filters.

### Filter menu keyboard & accessibility

| Key | Action |
|---|---|
| <kbd>Tab</kbd> | Moves through a row: column, operator, value, remove, drag handle. |
| <kbd>ArrowUp</kbd> / <kbd>ArrowDown</kbd> on the drag handle | Moves the row or group one place among its siblings. |
| <kbd>Backspace</kbd> / <kbd>Delete</kbd> on the drag handle | Removes the row or group. |
| <kbd>Escape</kbd> during a drag | Cancels the drag and keeps the popover open. |

While a pointer drags, a line shows where the row lands. A reorder announces the new place through `labels.toolbar.filterReorderAnnouncement`. Focus stays on the moved handle. The drop line fades in unless the user prefers reduced motion. After a removal, focus moves to the handle of a sibling. When the row was the last of its group, the group goes too, and focus moves to a sibling of the group. If no sibling remains at any level, focus moves to "Add filter".

## Controlled and initial filters

`filterState` makes the prop the source of truth, and `onFilterChange(next)` fires on every change. A controlled grid changes its filters only after the prop changes. `defaultFilterState` seeds the list once.

## Server mode

If your server filters the rows, set `filterMode="server"`. The grid tracks `filterState`, shows the filter indicators, and calls `onFilterChange`. It never filters `data`. A grid with `totalRowCount` defaults to `"server"`. Set `filterMode="client"` to filter its `data` in the browser.

The request is the `FilterNode[]` that `onFilterChange` receives. The answer is the rows that match. `useDataGridServerRows` sets `filterMode` for you and passes each fetch the list as `request.spec.filters`. See [Query server rows](/docs/data-modes/query-server-rows).

On a column with `choices`, the `isAnyOf` input lists the choices. On other columns, the header filter and the `isAnyOf` input list the set values of the loaded rows. Pass `fetchFilterValues` to read them from your server. See [Header filter](/docs/sort-filter-search/header-filter#server-values).

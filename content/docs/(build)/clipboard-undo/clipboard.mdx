Users move data between the grid and spreadsheets with Ctrl+C, Ctrl+X, and Ctrl+V. The grid listens for the native clipboard events, so the core needs no add-on and no permission prompt. Three props change what the grid copies, how it reads a paste, and whether a paste can land.

## Copy [#copy]

Copy takes the range that the user selected last. Earlier Ctrl/Cmd+click ranges stay out of the copy. If no range exists, it takes the selected rows or the selected columns whole. <kbd>Ctrl</kbd>/<kbd>Cmd</kbd>+<kbd>C</kbd> writes two formats to the clipboard:

- **`text/plain`**: tab-separated values (TSV), one row per line. A cell that contains a tab, a line break, or a quote gets wrapped in quotes, and the grid doubles each inner quote.
- **`text/html`**: a `<table>`. Each cell carries its exact text in a `data-gridcn-raw` attribute.

A paste back into gridcn reads that attribute, so tabs and runs of spaces survive. A paste into a spreadsheet app reads the table.

<kbd>Ctrl</kbd>/<kbd>Cmd</kbd>+<kbd>X</kbd> copies the same way and then clears the copied cells. On a `readOnly` grid, cut only copies. While a cell editor is open, the editor handles copy, cut, and paste itself.

<Callout title="toText, not toDisplayText">
  The copied text of each cell comes from the `toText` of its cell type. Display formatting, such
  as a locale date string, stays out of the clipboard.
</Callout>

## Formula sanitizing [#formula-sanitizing]

If a pasted cell starts with `=`, `+`, `-`, `@`, TAB, or CR, a spreadsheet app runs it as a formula. To paste such cells as text, set `sanitizeClipboardFormulas` (default `false`):

```tsx
import { DataGrid, defineColumns } from "@/components/data-grid/data-grid";

type Row = { id: string; formula: string };

const rows: Row[] = [{ id: "1", formula: "=SUM(A1:A3)" }];
const columns = defineColumns<Row>()([
  { id: "formula", header: "Formula", accessorKey: "formula" },
]);

function MyGrid() {
  return <DataGrid data={rows} columns={columns} sanitizeClipboardFormulas />;
}
```

Result: copying the cell puts `'=SUM(A1:A3)` on the clipboard.

If the prop is on, Ctrl+C, Ctrl+X, and the context menu's Copy and Cut put a single quote in front of each formula-like cell. The quote goes into both the `text/plain` and the `text/html` payload. Plain numbers such as `-5` and `+5` stay unchanged. A paste back into gridcn restores the raw value.

The context menu writes through the async Clipboard API. If the browser lacks or denies that API, the copy writes plain text only. A paste back from that copy keeps the quote.

`DataGridProvider` takes the same prop. A custom copy UI built on `useDataGridClipboard` follows the prop, and its `sanitizeFormulas` option overrides it.

## Paste [#paste]

The grid reads the `text/html` payload first, for example from another gridcn grid, Excel, Sheets, or Numbers. If the payload has no table, it reads the `text/plain` payload with a quoted-TSV parser. The parser handles tabs, line breaks, and quotes inside quoted cells.

- **Anchored expand.** An N×M block lands at the top-left of the selected range and overwrites that N×M region. The block stops at the last row and the last column.
- **Single-row tiling.** If you paste one row into a taller selected range, the row repeats down every selected row.
- **Value steps.** The `fromText` of each target cell type reads the pasted text. Then `validate` runs. A cell that fails stays unchanged, and `onValidationError` reports it with the source `"paste"`.
- **Skipped cells.** Read-only cells keep their value. This covers a column's static `readOnly` and its per-row function form. A `readOnly` grid ignores the paste.
- **One change.** A paste calls `onDataChange` once, with one batch of operations (`ops`) and the source `"paste"`. The selection then covers the written cells.

A column with an async `validate` holds the paste until the schema answers. [Validation](/docs/editing-cells/validation#on-bulk-paths) owns that contract. For a large paste against a remote check, `processPaste` below validates the whole block in one request.

## Overrides [#overrides]

Three props replace one step of copy or paste. Each runs for every cell or paste, so handle the cases you do not change. This sample writes prices with a `$` sign and reads them back:

```tsx
import {
  DataGrid,
  defineColumns,
  type ClipboardProcessCtx,
} from "@/components/data-grid/data-grid";

type Row = { id: string; name: string; price: number };

const rows: Row[] = [{ id: "1", name: "Pen", price: 1.5 }];
const columns = defineColumns<Row>()([
  { id: "name", header: "Name", accessorKey: "name" },
  { id: "price", header: "Price", accessorKey: "price", type: "number" },
]);

function copyText(value: unknown, { column }: ClipboardProcessCtx<Row>) {
  return column.id === "price" ? `$${value}` : String(value ?? "");
}

function pasteValue(text: string, { column }: ClipboardProcessCtx<Row>) {
  return column.id === "price" ? Number(text.replace("$", "")) : text;
}

function MyGrid() {
  return (
    <DataGrid
      data={rows}
      columns={columns}
      processCellForClipboard={copyText}
      processCellFromClipboard={pasteValue}
    />
  );
}
```

- `processCellForClipboard(value, { row, column })` returns the text of one copied cell. Without it, the `toText` of the cell type decides.
- `processCellFromClipboard(text, { row, column })` returns the value of one pasted cell. Without it, the `fromText` of the cell type decides.
- `processPaste({ cells, target })` receives the text grid after single-row tiling and before the paste cap. `target` is the top-left cell of the paste. Return the grid to write, or `false` to veto the whole paste.

`processPaste` <NewBadge /> and `processCellFromClipboard` also accept a promise:

```tsx
async function processPaste({ cells }: { cells: string[][] }) {
  const response = await fetch("/api/normalize-paste", {
    method: "POST",
    body: JSON.stringify(cells),
  });
  return response.ok ? ((await response.json()) as string[][]) : false;
}
```

The grid holds the paste until the promise settles, then writes one change. The paste cap applies to the settled grid. A pending promise blocks a second paste. A rejection cancels the paste. The grid drops a late result in four cases:

- The grid went `readOnly`.
- A cell editor opened.
- The row or the column under the paste is gone.
- A sort or a filter changed.

If the row moved, the paste follows it. The [Async gates example](/docs/validation-examples/async-gates-example) shows the gate.

## Copy and paste from code [#copy-and-paste-from-code]

`useDataGridClipboard` returns `copy`, `cut`, and `pasteFromClipboard` for your own buttons. Call it under the grid's provider:

```tsx
import { useDataGridClipboard } from "@/components/data-grid/data-grid";

function CopyButton() {
  const clipboard = useDataGridClipboard();
  return <button onClick={() => void clipboard.copy()}>Copy selection</button>;
}
```

`copy` and `cut` resolve `"ok"`, `"fallback"` (plain text only), `"failed"`, or `"no-selection"`. `pasteFromClipboard` reads text from the clipboard and resolves `"ok"`, `"empty"`, or `"permission-denied"`. A paste through this hook carries no HTML.

### Context menu paste [#context-menu-paste]

The [context menu add-on](/docs/rows-pages-menus/context-menu#paste-permission) adds a Paste item that calls `pasteFromClipboard`. It needs the `clipboard-read` permission. If the browser withholds it, the item turns disabled and shows a "press Ctrl+V" hint.

## Server mode

Copy and paste work on the rows that `data` holds, in the order the grid displays them. In server pagination, `data` holds the current page, and a paste stops at the page's last row. With `sortMode="server"`, the displayed order is the order your server returned.

A paste is one change with the source `"paste"`. The grid calls `onDataChange` and `onSave` with it, and `onSave` sends it to the server. If `onSave` resolves with `{ rejected }` or rejects, the grid reverts the refused cells through `onDataChange` with the source `"rollback"`.

In scroll mode, a paste writes the loaded rows and skips rows that are not loaded. It adds no row. A copy gives empty cells for rows that are not loaded. [Data modes](/docs/data-modes) owns the detail for every mode.

## Known limitations [#known-limitations]

<Callout type="warn" title="Copy and paste are capped at 200,000 cells">
  A copy above `MAX_COPY_CELLS` (200,000 cells) writes only the rows that fit. A paste above
  `MAX_PASTE_CELLS` (200,000 cells) applies only the first rows that fit. A truncated copy or
  paste warns in the browser console in development.
</Callout>

<Callout type="warn" title="Real-world clipboard HTML is messy">
  The HTML reader takes the first `<table>` of the payload and ignores merged-cell spans. Excel,
  Sheets, and Numbers add inline styles that can hide this structure. If a paste does not
  round-trip from one app, patch it with `processPaste` or `processCellFromClipboard`.
</Callout>

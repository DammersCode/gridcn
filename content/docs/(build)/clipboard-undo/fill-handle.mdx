Typing the same value into many cells is slow. The fill handle is the small square at the bottom-right corner of a selection. Drag it up, down, left, or right to extend the selection. The grid fills the new cells from the source cells. `useDataGridFill` adds the handle and the keyboard fill commands.

## Wiring it up [#wiring-it-up]

The hook returns one plugin. Pass it to the grid through `plugins`:

```tsx
import { DataGrid, defineColumns } from "@/components/data-grid/data-grid";
import { useDataGridFill } from "@/components/data-grid-fill/data-grid-fill";

type Row = { id: string; name: string };

const data: Row[] = [{ id: "1", name: "Item 1" }];
const columns = defineColumns<Row>()([
  { id: "name", header: "Name", accessorKey: "name" },
]);

function MyGrid() {
  const { plugin } = useDataGridFill();

  return <DataGrid defaultData={data} columns={columns} plugins={[plugin]} />;
}
```

## Copy and series [#tiling-vs-series-inference]

The drag snaps to the axis that you move further on. Press <kbd>Escape</kbd> during a drag to cancel it. If the window loses focus or the browser cancels the pointer, the drag ends and fills nothing. By default, the fill repeats the source cells over the target. A single cell repeats, and a two-row source repeats every two rows.

If the source cells form a series, the fill continues the series instead:

- **Arithmetic runs.** `1, 2, 3` continues as `4, 5, 6`. `10, 20, 30` continues as `40, 50, 60`. Decimal steps work too: `0.5, 1` continues as `1.5, 2.0`.
- **Zero-padded numbers.** `001, 002` continues as `003, 004` and keeps the width.
- **Text with a trailing number.** `Item 1, Item 2` continues as `Item 3, Item 4`.

A series needs two source cells, because one value has no step. The grid finds a series per source column for a vertical fill and per source row for a horizontal fill. A number with more than 15 digits is an identifier, so the fill copies it. Dates have no series of their own. The text detector continues the trailing number, so `2026-01-30, 2026-01-31` continues as `2026-01-32`. A custom detector below handles real dates.

After a fill commits, the written cells play a short fade pulse. The pulse plays only for cells in the viewport.

### Forcing a plain copy [#forcing-a-plain-copy]

To force a plain copy, even over a series, hold <kbd>Alt</kbd> (<kbd>Option</kbd> on Mac) at the release of the drag.

## Keyboard fill [#keyboard-fill]

The handle has no keyboard equivalent and is hidden from screen readers. These keys give the same result:

- <kbd>Ctrl</kbd>/<kbd>Cmd</kbd>+<kbd>D</kbd> fills down. It copies the top row of the selection into every row below it.
- <kbd>Ctrl</kbd>/<kbd>Cmd</kbd>+<kbd>R</kbd> fills right. It copies the left column into every column to its right.

Both keys use the same copy and series logic as a drag. The source of each key is one row or one column, so the built-in detector always copies. They are core bindings. In a writable grid, outside an edit, <kbd>Ctrl</kbd>+<kbd>R</kbd> fills right and the page does not reload. The `fillDown` and `fillRight` flags of the [global shortcuts](/docs/selection-shortcuts/global-shortcuts) extend them to the whole window. Without this add-on, both keys do nothing. See [Pluggable built-ins](/docs/plugins/plugin-commands-shortcuts#pluggable-built-ins).

### Touch [#touch]

After a touch selection, the handle is hidden because the selection handle uses the same corner. With the [context menu](/docs/rows-pages-menus/context-menu) add-on, the cell menu shows **Fill down** and **Fill right** instead. They run the same commands.

## Skipped cells

A fill writes only to cells that accept a write:

- A read-only grid never fills. The handle is hidden and both commands do nothing.
- In a writable grid, a fill skips the read-only cells and fills the others. A column or a row function can mark a cell read-only. It shows no error, like a paste over a read-only cell.
- A fill commits as one change. When a column validator rejects a value, the grid reports the rejected cells through `onValidationError` with source `"fill"` and writes the rest.

## Server mode

<NewBadge />

A fill works on the rows that the grid holds in memory. It never asks the server for rows. Fill follows the displayed order, so a sorted grid fills in the order that you see.

A fill is one change. The grid applies it, then calls `onDataChange` and `onSave` with the same change. `change.source` is `"fill"`. `change.ops` holds one `update` operation per written row, and each operation lists the changed `cells`. Your `onSave` sends these updates to the server.

`onSave` returns nothing or a promise. If the promise resolves with nothing, the server accepted the fill. If it resolves with `{ rejected }`, the server refused part of it. If it rejects, the server refused all of it. A refusal reverts the cells through `onDataChange` with source `"rollback"`. The rows show as saving while the promise is pending. If a rejection carries `current`, the row as the server holds it, the revert puts that row in place instead.

In scroll mode, a fill target can cover rows that are not loaded. The grid fills the loaded rows, skips the others, and still expands the selection over the whole target. A development warning gives the number of skipped rows. When the fill must reach them, load the rows first. See [Load rows while scrolling](/docs/scroll-mode/load-rows-while-scrolling).

[Data modes](/docs/data-modes) owns the detail for every mode.

## Options

Pass these options to `useDataGridFill`. Every option is optional:

{/* props: UseDataGridFillOptions */}

| Prop | Type | Default |
| --- | --- | --- |
| `disabled` | `boolean` | `false` |
| `processFill` | `(ctx: ProcessFillContext) => string[][] \| false` | none |
| `detectSeries` | `(values: readonly string[]) => SeriesDescriptor \| null` | built-in detector |

### disabled [#turning-fill-off]

`disabled` hides the handle and turns both commands into no-ops.

### processFill

`processFill` <NewBadge /> runs on drag release and on both keyboard commands, before the grid applies the fill. It returns the text grid to write, or `false` to cancel the fill. The grid parses the returned text with the `fromText` of each column and validates it, like a paste. After `false`, the grid writes nothing and the selection does not expand. This gate cancels large fills:

```tsx
import { useDataGridFill } from "@/components/data-grid-fill/data-grid-fill";
import type { ProcessFillContext } from "@/components/data-grid-fill/data-grid-fill";

function processFill({ target, values }: ProcessFillContext) {
  return target.height > 100 ? false : values;
}

function MyGrid() {
  const { plugin } = useDataGridFill({ processFill });
  // render the grid with plugins={[plugin]}
}
```

`ProcessFillContext` also carries `source`, the rectangle of the source cells, and `values`, the text grid for the target before parsing. For Ctrl/Cmd+D, `source` is the top row. For Ctrl/Cmd+R, it is the left column. `target` covers the new cells only. `onDataChange` with the `"fill"` source reports each fill that the grid writes.

### detectSeries [#custom-series-detection]

`detectSeries` replaces the built-in detector. It receives the source cell texts along the fill axis, in source order. It returns a `SeriesDescriptor` with an `extrapolate(index)` function, or `null` to copy. `index` counts from the first source cell: `0` is the first source cell, and an up or left fill passes negative indexes. This detector adds date series:

```tsx
import { useDataGridFill } from "@/components/data-grid-fill/data-grid-fill";
import type { SeriesDescriptor } from "@/components/data-grid-fill/data-grid-fill";

const ISO_DATE = /^\d{4}-\d{2}-\d{2}$/;

const detectDates = (values: readonly string[]): SeriesDescriptor | null => {
  if (values.length < 2 || !values.every((v) => ISO_DATE.test(v))) return null;
  const times = values.map((v) => Date.parse(v));
  if (times.some(Number.isNaN)) return null;
  const step = times[1]! - times[0]!;
  for (let i = 2; i < times.length; i += 1) {
    if (times[i]! - times[i - 1]! !== step) return null;
  }
  return {
    extrapolate: (index) =>
      new Date(times[0]! + step * index).toISOString().slice(0, 10),
  };
};

function MyGrid() {
  const { plugin } = useDataGridFill({ detectSeries: detectDates });
  // render the grid with plugins={[plugin]}
}
```

Result: the source cells `2026-01-30, 2026-01-31` continue as `2026-02-01, 2026-02-02`.

To keep the built-in series, call the exported `detectSeries` for every input that your detector rejects:

```tsx fragment="continues the detectDates sample above"
import { detectSeries } from "@/components/data-grid-fill/data-grid-fill";

const detectBoth = (values: readonly string[]) =>
  detectDates(values) ?? detectSeries(values);
```

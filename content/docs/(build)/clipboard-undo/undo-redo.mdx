A user who pastes over the wrong cells needs a way back. The `data-grid-history` add-on keeps a stack of changes and reverts them. `useDataGridState` gives a grid undo and redo in one call. `useDataGridHistory` adds the same stack to a grid whose data you own.

## How it works [#how-it-works]

Each entry on the stack is one change: the operations (`ops`) of one `onDataChange` call. A paste, a fill, and the delete of a range are one entry each. Operations address rows by row id, so an entry finds its row again after a sort or a filter moves it.

Undo applies the inverse of the most recent entry as one change with `source: "history"`. Redo applies the entry again. A new change clears the redo stack.

If a row that the entry needs is missing from the data, undo and redo apply nothing. A refresh that removed the row causes this. See [Rows that are not loaded or gone](#rows-not-loaded).

## Quick start: useDataGridState [#quick-start-usedatagridstate]

`useDataGridState` owns the `data` array and passes it to the grid on every render as the controlled `data` prop. Undo and redo need this: each undo writes through the grid, and the hook stores the result. To use history, use this hook. `defaultData` seeds the grid once and keeps no history. Spread the result onto `DataGrid`:

```tsx
import { DataGrid, defineColumns } from "@/components/data-grid/data-grid";
import { useDataGridState } from "@/components/data-grid-history/data-grid-history";

type Row = { id: string; name: string };

const rows: Row[] = [{ id: "1", name: "Ada" }];
const columns = defineColumns<Row>()([
  { id: "name", header: "Name", accessorKey: "name" },
]);

function MyGrid() {
  const grid = useDataGridState(rows);
  const { canUndo, canRedo, undo, redo } = grid.history;

  return (
    <>
      <button disabled={!canUndo} onClick={undo}>Undo</button>
      <button disabled={!canRedo} onClick={redo}>Redo</button>
      <DataGrid {...grid} columns={columns} />
    </>
  );
}
```

Result: edit a cell, then press Undo. The cell returns to its earlier value and Redo turns on.

`getRowId` defaults to the `id` field of a row. `grid.history` holds `canUndo`, `canRedo`, `historySize`, `undo`, `redo`, `clear`, `record`, and `rollback`. `historySize` counts the entries on the undo stack. `clear` empties both stacks. To mount other plugins, pass `plugins` after the spread and keep `grid.plugins` in it: `<DataGrid {...grid} columns={columns} plugins={[fillPlugin, ...grid.plugins]} />`.

### Keyboard [#keyboard]

- <kbd>Ctrl</kbd>/<kbd>Cmd</kbd>+<kbd>Z</kbd> undoes.
- <kbd>Ctrl</kbd>/<kbd>Cmd</kbd>+<kbd>Y</kbd> and <kbd>Ctrl</kbd>/<kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>Z</kbd> redo.

The keys work while focus is in the grid. While a cell editor is open, the editor keeps them for its own text. Without this add-on, both keys do nothing. Remap them with the `undo` and `redo` actions of the [`keymap` prop](/docs/selection-shortcuts/shortcut-remapping).

When you mount [`DataGridGlobalShortcuts`](/docs/selection-shortcuts/global-shortcuts), the keys also work while focus is outside the grid. They skip text fields.

## Composable: useDataGridHistory [#composable-usedatagridhistory]

If you own the data array, call `useDataGridHistory` and pass its `plugin` to the grid. Your `onDataChange` keeps feeding your state. The hook records each change after your handler runs:

```tsx
import { useState } from "react";
import { DataGrid, defineColumns } from "@/components/data-grid/data-grid";
import { useDataGridHistory } from "@/components/data-grid-history/data-grid-history";

type Row = { id: string; name: string };

const rows: Row[] = [{ id: "1", name: "Ada" }];
const columns = defineColumns<Row>()([
  { id: "name", header: "Name", accessorKey: "name" },
]);

function MyGrid() {
  const [data, setData] = useState<readonly Row[]>(rows);
  const history = useDataGridHistory<Row>({ capacity: 50 });

  return (
    <>
      <button disabled={!history.canUndo} onClick={history.undo}>Undo</button>
      <DataGrid
        data={data}
        columns={columns}
        onDataChange={setData}
        plugins={[history.plugin]}
      />
    </>
  );
}
```

The result has the members of `grid.history` above, plus `plugin`.

## Capped stack [#capped-stack]

`capacity` limits the entries on the undo stack. The default is 100. When the stack is full, the oldest entries drop first. `capacity` counts entries, not operations: a paste of 10,000 cells is one entry.

## Read-only grids [#read-only-grids]

A `readOnly` grid refuses writes, so it records nothing. The keys, `undo`, and `redo` do nothing and keep their entries. `canUndo` <NewBadge /> and `canRedo` are `false` while the grid is `readOnly`. `historySize` still counts the entries.

## Server mode

Undo works in every data mode. Entries address rows by row id, so they follow server sort and server filter. In server pagination, `data` holds one page.

`onSave` receives an undo or a redo as a change with `source: "history"`. Your handler sends the inverse change to the server like any other change. If `onSave` refuses all or part of a change, the grid reverts the refused rows and removes the entry from the stack. A refused undo or redo goes back on its stack instead (see [Refused undo and redo](#refused-undo)).

If your `onDataChange` writes to your backend and you pass no `onSave`, the stack does not learn whether the server accepted the write. After a failed save, call `rollback(change)`.

### Rows that are not loaded or gone [#rows-not-loaded]

<NewBadge />

An update, delete, or move needs its row in `data`. An insert needs no row. If a row is missing, `undo` and `redo` apply nothing, and the live region announces the block. What happens to the entry depends on why the row is missing:

| Case | Entry | `onSkip` reason |
| --- | --- | --- |
| Every needed row is in `data` | applied | none |
| A needed row is a hole in a sparse `data` array (scroll mode) | stays on its stack | `"rows-not-loaded"` |
| A needed row is gone from a dense `data` array | dropped | `"rows-gone"` |

For `"rows-not-loaded"`, load the rows and call `undo` again. Pass `onSkip` to react:

```tsx
const history = useDataGridHistory({
  onSkip: ({ direction, reason, rowIds }) => {
    if (reason === "rows-not-loaded") {
      toast(`Scroll to load ${rowIds.length} rows, then ${direction} again`);
    }
  },
});
```

`onSkip` receives `{ direction, reason, rowIds }`. `direction` is `"undo"` or `"redo"`, and `rowIds` lists the missing rows. A throw in `onSkip` is logged and isolated. A `datasetKey` change clears both stacks without calling `onSkip`.

### Refused undo and redo [#refused-undo]

<NewBadge />

If `onSave` refuses an undo or a redo, the grid reverts the change with a `"rollback"` change. History then puts the entry back. A refused undo is on the undo stack again, and a refused redo is on the redo stack again. A refused ordinary change still drops its entry.

### Rows the server replaced [#server-replaced-rows]

<NewBadge />

- A save conflict that takes the server row, or a rollback or merge change with `serverRowIds`, replaces the content of those rows. History removes the operations on those rows from all older entries. An entry left with no operations goes. See [Handle refused saves](/docs/save-server/handle-refused-saves#resolve-a-conflict).
- `actions.replaceRowId(oldId, row)` swaps a server-assigned id into a row. History rewrites the older entries to the new id, so an earlier edit still undoes. History does not record the swap.

## Options

{/* props: UseDataGridHistoryOptions */}

| Prop | Type | Default |
| --- | --- | --- |
| `capacity` | `number` | `100` |
| `datasetKey` | `string \| number` | none |
| `onSkip` <NewBadge /> | `(ctx: { direction; reason; rowIds }) => void` | none |
| `recordSources` | `readonly DataChange<TData>["source"][] \| ((defaults) => readonly DataChange<TData>["source"][])` | `edit`, `paste`, `fill`, `delete`, `row-operation`, `import`, `replace`, and `app` |

`useDataGridState` takes `getRowId` and every option of `useDataGridHistory`. <NewBadge /> [Undo for code changes](/docs/clipboard-undo/undo-code-changes) explains `recordSources` and `datasetKey`.

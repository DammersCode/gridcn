When your server returns one page of rows per request, use `useDataGridServerRows` in pages mode. The hook calls your `fetchRows` for the current page and returns a `pager` for the footer. If the browser holds the whole array, see [Client pagination](/docs/rows-pages-menus/client-pagination).

## Fetch a page [#fetch-a-page]

1. Send `start`, `end`, and `spec` (the sort, the filters, and the search text) from `fetchRows` to your API.
2. Answer with the rows of that page and the row count of the whole result.
3. Spread `server.gridProps` onto the grid and `server.pager` onto `DataGridPaginationBar`.

This grid loads 25 orders per page:

```tsx
"use client";

import { DataGrid, defineColumns } from "@/components/data-grid/data-grid";
import { DataGridPaginationBar } from "@/components/data-grid-pagination/data-grid-pagination";
import { useDataGridServerRows } from "@/components/data-grid-server/data-grid-server";

type Order = { id: string; customer: string };

const columns = defineColumns<Order>()([
  { id: "customer", header: "Customer", accessorKey: "customer" },
]);

export function OrdersGrid() {
  const server = useDataGridServerRows<Order>({
    defaultPageSize: 25,
    fetchRows: async ({ start, end, spec, signal }) => {
      const response = await fetch("/api/orders", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ start, end, spec }),
        signal,
      });
      const answer = await response.json();
      return { rows: answer.rows, totalRowCount: answer.total };
    },
  });

  return (
    <>
      <DataGrid {...server.gridProps} columns={columns} className="h-96" />
      <DataGridPaginationBar {...server.pager} />
    </>
  );
}
```

On page 3 at 25 rows per page, `start` is 50 and `end` is 75. The request also carries `page` and `pageSize`. Pass `signal` to `fetch`, so the hook can abort a request that a newer page, size, or spec replaces.

The hook sets `sortMode="server"` and `filterMode="server"`, so your server applies `spec`. See [Query server rows](/docs/data-modes/query-server-rows). Every option is on [Server rows options](/docs/add-options/server/server-rows-options#server-mode).

## Control the page [#control-the-page]

The hook keeps the page and the page size in its own state. `defaultPage` and `defaultPageSize` seed them once. `pageSizeOptions` sets the sizes of the footer select (10, 25, 50, and 100 by default). To control a value, pass `page` with `onPageChange`, or `pageSize` with `onPageSizeChange`, as [Keep pages in URL](/docs/server-pagination/keep-pages-url) does. The hook sends a page below 1 as page 1.

## When the page resets [#when-the-page-resets]

- A change of the page size, the sort, the filter, or the search text goes back to page 1, because the pages hold other rows.
- A spec that URL state restores before the first answer keeps the page of the link.

If the count shrinks below the page, the pager moves to the last page. A count of `0` leaves the page unchanged.

## Show the count [#show-the-count]

`totalRowCount` is the row count of the filtered result. The footer uses it for the range label and for the last page. The hook also passes it to the grid with `checkedRowsLifetime="across-filters"`, so checked rows survive a page change. See [Select server rows](/docs/rows-live-data/select-server-rows).

If your server sends no count, answer `{ rows, hasMore }` and omit `totalRowCount`, or send `totalRowCount: null`. The footer then shows "Page 3" in place of a range, Next stays enabled while `hasMore` is `true`, and Last stays disabled. Without `hasMore`, a full page means that another page exists. For a cursor API, see [Tune page loading](/docs/server-pagination/tune-page-loading).

## Fetch the pages yourself [#own-fetch]

If you fetch with your own code, call `useDataGridServerPager` for the footer. It keeps no page state, so you control `page` and `pageSize`. Pass `totalRowCount` and a controlled `filterState`. The count makes `sortMode` and `filterMode` default to `"server"`, so the grid does not filter the page again.

If the page, the page size, or the filters change, this grid fetches again:

```tsx
"use client";

import { useEffect, useState } from "react";
import { DataGrid, defineColumns, type FilterNode } from "@/components/data-grid/data-grid";
import { DataGridPaginationBar, useDataGridServerPager } from "@/components/data-grid-pagination/data-grid-pagination";

type Order = { id: string; customer: string };

const columns = defineColumns<Order>()([
  { id: "customer", header: "Customer", accessorKey: "customer" },
]);

export function OrdersGrid() {
  const [page, setPage] = useState(1);
  const [pageSize, setPageSize] = useState(25);
  const [filters, setFilters] = useState<FilterNode[]>([]);
  const [answer, setAnswer] = useState({ rows: [] as Order[], total: 0 });

  useEffect(() => {
    const controller = new AbortController();
    fetch("/api/orders", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ page, pageSize, filters }),
      signal: controller.signal,
    })
      .then((response) => response.json())
      .then(setAnswer)
      .catch((error: unknown) => {
        if (!controller.signal.aborted) console.error(error);
      });
    return () => controller.abort();
  }, [page, pageSize, filters]);

  const { pager } = useDataGridServerPager({
    page,
    pageSize,
    totalRowCount: answer.total,
    onPageChange: setPage,
    onPageSizeChange: (size) => {
      setPageSize(size);
      setPage(1);
    },
  });

  return (
    <>
      <DataGrid
        data={answer.rows}
        onDataChange={(rows) => setAnswer({ ...answer, rows: [...rows] })}
        columns={columns}
        getRowId={(row) => row.id}
        filterState={filters}
        onFilterChange={(next) => {
          setFilters(next);
          setPage(1);
        }}
        totalRowCount={answer.total}
        className="h-96"
      />
      <DataGridPaginationBar {...pager} />
    </>
  );
}
```

The `controller` aborts the request of a replaced page. Without `onPageSizeChange`, the footer hides the page-size select.

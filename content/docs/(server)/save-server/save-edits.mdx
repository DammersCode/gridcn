The grid applies an edit at once. `onSave` sends the same change to your server. The grid calls it with a `DataChange` after `onDataChange`. If you return a promise, the grid tracks the save and reverts a refused change.

## Send a change [#send-a-change]

1. Pass `onSave` to the grid.
2. Send `change.ops` to your API. Each operation has a `type` and a `rowId`.
3. Return the promise of the request.
4. If the request fails, throw or reject.

This grid keeps its rows and saves every change:

```tsx
"use client";

import {
  DataGrid,
  defineColumns,
  type DataChange,
} from "@/components/data-grid/data-grid";

type Order = { id: string; customer: string };

const columns = defineColumns<Order>()([
  { id: "customer", header: "Customer", accessorKey: "customer" },
]);

async function save(change: DataChange<Order>) {
  const response = await fetch("/api/orders", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(change.ops),
  });
  if (!response.ok) throw new Error(`Save failed: ${response.status}`);
}

export function OrdersGrid({ rows }: { rows: Order[] }) {
  return (
    <DataGrid
      defaultData={rows}
      columns={columns}
      getRowId={(row) => row.id}
      onSave={save}
      onSaveRejected={() => alert("The server refused the change.")}
    />
  );
}
```

`defaultData` seeds the rows once, and the grid owns them. With controlled `data`, `onDataChange` must write each change into your state. Without it, your state keeps the old rows, and the grid drops the edit the next time it reads your `data`.

A request that fails reverts the whole change. After the revert, `onSaveRejected` runs once per refused change with `{ change, rejected, error }`. The grid isolates a throw in it. To revert only the rows that the server refused, see [Handle refused saves](/docs/save-server/handle-refused-saves).

## What onSave receives [#what-onsave-receives]

- It runs once per change, after `onDataChange`.
- The `source` of a change names its origin. The origins are an edit, a paste, a fill, a delete, a row operation, and an import. They also include a find and replace, a programmatic `record()`, and an undo or redo.
- `onSave` never receives a change with `source: "rollback"` or `source: "stream"`. A revert and a server push do not go back to the server.
- A `readOnly` grid writes nothing for a cell edit, so `onSave` does not run.
- A function that returns a promise sets the status of the rows. If the function returns nothing and does not throw, the grid sets no status and cannot refuse the change. A synchronous throw refuses the change.

## Read the save status [#read-the-save-status]

While the promise is pending, each row of the change is `saving`. The row element carries `data-save-status="saving"`. A refused row carries `failed` until the next save of that row or a call of `actions.clearSaveStatus()`.

- `useDataGridRowSaveStatus(rowId)` returns `"saving"`, `"failed"`, or `undefined`.
- `useDataGridPendingSaveCount()` returns the number of `onSave` promises that have not settled.

Both hooks work inside `DataGridProvider`, so call them in a composed layout with `DataGridProvider` and `DataGridRoot`. This rule dims a row while its save runs:

```css
[data-save-status="saving"] {
  opacity: 0.6;
}
```

## Save rows from a server source [#server-source]

With `useDataGridServerRows`, `gridProps` keeps the rows in step with each edit. Add `onSave` next to the spread. The hook offers `refresh` to fetch the current page again. A refresh keeps the local value of a row with a pending save or an open edit. To read the value the server holds, refresh after the save settles.

This grid sends the change, then fetches the page again:

```tsx
"use client";

import { DataGrid, defineColumns } from "@/components/data-grid/data-grid";
import {
  useDataGridServerRows,
} from "@/components/data-grid-server/data-grid-server";

type Order = { id: string; customer: string };

const columns = defineColumns<Order>()([
  { id: "customer", header: "Customer", accessorKey: "customer" },
]);

export function OrdersGrid() {
  const server = useDataGridServerRows<Order>({
    getRowId: (row) => row.id,
    fetchRows: async ({ start, end, signal }) => {
      const query = `offset=${start}&limit=${end - start}`;
      const response = await fetch(`/api/orders?${query}`, { signal });
      const answer = await response.json();
      return { rows: answer.rows, totalRowCount: answer.total };
    },
  });

  return (
    <DataGrid
      {...server.gridProps}
      columns={columns}
      onSave={(change) => {
        void fetch("/api/orders", {
          method: "POST",
          body: JSON.stringify(change.ops),
        }).then(() => server.refresh());
      }}
    />
  );
}
```

This `onSave` returns nothing, so the grid sets no status and reverts nothing. Return the promise instead to get the status and the revert, and refresh after it settles.

## Server mode [#server-mode]

`onSave` works the same on a local array, on a page, and on scroll rows. The grid sends no spec, page, or row count to `onSave`. Your server applies each operation by `rowId`.

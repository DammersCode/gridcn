A grid feature can behave differently on a local array, on server pages and on scrolled server rows. The table below sets every feature against every data mode. A gap cell is a known gap, and the notes below the table describe it.

## Data modes

- **L**: Local array. `data` holds every row in memory.
- **PC**: Client pagination. `defaultPageSize` pages the view of the whole `data`.
- **PS**: Server pagination. The server returns one page per request.
- **Z**: Scroll mode. `useDataGridServerRows` in scroll mode fetches row blocks on scroll.
- **C**: Controlled state. The app owns `sortState`, `filterState` or `searchText`.
- **SS**: Server sort. `sortMode="server"`: the grid never reorders `data`.
- **FS**: Server filter. `filterMode="server"`: the grid never filters `data`.
- **API**: Own API. `onDataChange` writes through to the app's backend.

## Notes

### Sort

**FS**: n/a: Filter mode concerns filters only.

### Filter set values

**API**: n/a: Set values are read-only input of the filter. Writes through onDataChange or onSave never read them.

### Quick search

- The grid's search highlights and navigates loaded rows and never narrows them. `useDataGridServerRows` sends the text as `spec.searchText`, so your server can narrow the result.
- **FS**: n/a: Search highlights loaded rows and never filters.
- **API**: n/a: Search writes no data.

### Row grouping

- **L, PC**: Gap: Row grouping is not available.
- **PS, Z, SS, FS, API**: Gap: Server grouping is not defined.
- **C**: n/a: Grouping has no controlled state.

### Server totals (`useDataGridServerAggregate`)

- **L**: n/a: A local array holds every row, so `useDataGridAggregate` totals it without a fetch.
- **PC**: n/a: A client grid with `defaultPageSize` holds every row, so `useDataGridAggregate` totals it without a fetch.

### Column pin, hide, order and size

Mode-neutral. Autosize measures loaded rows only on scroll data and on one page.

### Fill

Fill skips rows not loaded yet and warns.

### Import

**PC, C, SS, FS**: n/a: Import hands the built rows to onImport and reads no sort, filter, page, or server state. The app decides where they land.

### Print

Print covers the rows the grid holds: every page of a client-paged grid, the loaded page or blocks of a server grid.

### Pushes into a server-ordered view

**L, PC**: n/a: The client sorts and filters the pushed rows itself. With the default `reorder: "defer"`, a pushed row keeps its position and `viewStale` turns on. `reconcileView()` or the next sort, filter, or search change moves the row. `reorder: "immediate"` moves it at once. See [Stream updates](/docs/rows-live-data/stream-updates).

### URL state

- **C**: n/a: URL state drives the controlled props itself.
- **FS**: Gap: A deep-linked set-filter list keeps at most as many values as the static `choices` of the column, and at least 64. The grid drops the values past that bound, and an `isNoneOf` list past it drops the whole filter.

### Presence

Mode-neutral by design.

### Scroll row fetching

- **L, PC**: n/a: Rows are in memory.
- **PS**: n/a: The consumer supplies each page.
- **SS**: n/a: Not a sort concern.
- **FS**: n/a: Not a filter concern.
- **API**: n/a: Not a write concern.

### Scroll fetch limits

- **L, PC**: n/a: Rows are in memory.
- **PS**: n/a: A pages-mode request is one per state. A newer page aborts the older one.

### Revalidation on a timer

**L, PC**: n/a: Rows are in memory.

### Next page prefetch

- **L, PC**: n/a: Rows are in memory.
- **Z**: n/a: `overscan` already loads rows ahead on both sides.

### Pagination

- **L**: n/a: No pages.
- **Z**: n/a: Scroll mode and pagination are exclusive.

### Keys, labels and cell types

Mode-neutral.

### Unknown total and cursor paging

- Pages mode pages without a total through `hasMore`, or through a `nextCursor` chain: each page request carries the `cursor` of the page before. Scroll mode loads a source without a count in order.
- **L**: n/a: The array holds every row.
- **PC**: n/a: The length of `data` is the total.

### One server data source (`useDataGridServerRows`)

- **L**: n/a: A local array needs no fetch.
- **PC**: n/a: A client grid with `defaultPageSize` holds every row, so no fetch runs.

### Error state and retry

**L, PC**: n/a: No request can fail.

### Debounced text inputs

**API**: n/a: The inputs write no data.

### Async lookup cell

Mode-neutral: the editor fetches options, not rows.

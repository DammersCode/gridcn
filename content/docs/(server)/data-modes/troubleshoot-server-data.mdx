Find your symptom below. In a development build, the grid logs a warning for several of these causes. It starts with `[data-grid]` or the add-on name, such as `[data-grid-server]`. Read the console first.

## Rows are wrong or missing [#rows]

- **A header click selects the column and does not sort.** Without `totalRowCount`, `headerClickBehavior` is `"select"`. Set `headerClickBehavior="sort"`.
- **The grid sorts or filters the rows again.** Without `useDataGridServerRows`, the grid sorts and filters its `data`. Set `sortMode="server"` and `filterMode="server"`.
- **`status` is `"error"` and the grid shows the last good rows.** `fetchRows` rejected, threw, or resolved without a `rows` array. Fix the cause, then call `server.retry()` or select Retry in the error bar.
- **A page shows fewer rows than `pageSize`.** The answer repeats a row id, and the hook drops the later copies. [Make the sort order unique](/docs/data-modes/query-server-rows#sorting-a-scroll-grid).
- **Your route answers 400 with a `ServerSpecError` message.** `parseServerSpec` rejected the body, and the message names the part, for example `filters[2].value`. Fix the value that the client sends, or your `columns` and `limits`. See [Check the spec on your server](/docs/data-modes/query-server-rows#parse-the-spec).
- **A number or date filter matches the wrong rows.** Every filter value is text, such as `"5"`. Convert it on your server for number and date columns. See [Operators](/docs/sort-filter-search/filtering#operators).
- **A pushed row stays in its old place.** With a server sort or filter, the grid marks a pushed row stale and never moves it. Call `server.reshape()`, or set `reshapeDelayMs`. See [Push into a server-ordered view](/docs/rows-live-data/push-server-ordered-view).
- **Rows at the end of an answer do not show.** The answer holds more than `end - start` rows, and the hook uses the first `end - start`. Make your server honor the limit.
- **A slow answer replaces a newer page.** With your own fetch, abort the request of a replaced page, as [Load rows by page](/docs/server-pagination/load-rows-page#own-fetch) does. The hook does it for you when `fetchRows` passes `signal` to `fetch`.

## The pager and the count [#pager]

- **The footer shows "Page 3" in place of a range, and Last stays disabled.** The count is unknown. The first answer sent no valid `totalRowCount`. Send the count of the filtered result.
- **The count stays unknown although the server sends `total` or `hasNextPage`.** The hook reads `totalRowCount` and `hasMore` only. Rename the fields. Development builds warn.

- **The page goes back to page 1.** Nothing needs a fix. A change of the page size, the sort, the filter, or the search text gives other pages, so the hook resets the page.
- **The page-size select is missing.** With `useDataGridServerPager`, pass `onPageSizeChange`.

## Edits and saves [#saves]

- **Scroll mode loads no more blocks, and a warning names `onRenderedRowsChange`.** An `onRenderedRowsChange` prop after the spread of `server.gridProps` replaces the handler of the hook. Pass it as the `onRenderedRowsChange` option of the hook. An `onDataChange` prop after the spread runs next to the merge of the hook.
- **A warning says that the refresh guard never mounted.** A `plugins` prop after the spread replaced the guard. Pass your plugins in the `plugins` option of the hook. Without the guard, `refresh` cannot keep a row with a pending save or an open edit.
- **A failed save does not revert the edit.** Your `onSave` returns no promise and does not throw. Or the grid is `readOnly` at the refusal and keeps the refused value. Return a promise that rejects or resolves with `{ rejected }`. See [Save edits](/docs/save-server/save-edits).
- **A row stays marked `failed`.** The mark clears at the next save of the row, or with `actions.clearSaveStatus()`.
- **Two users edit the same row, and the later save overwrites the first.** Your server accepts every write. Compare `prev` with the stored row and refuse the row. See [Handle refused saves](/docs/save-server/handle-refused-saves#detect-a-conflict).
- **A new row keeps its client id after the save.** Call `actions.replaceRowId(oldId, row)` with the server row. See [Save edits](/docs/save-server/save-edits#id-swap).

## Scroll mode [#scroll-mode]

- **Rows show skeletons for a moment after a scroll.** A block starts after it stays in the wanted range for `loadDelayMs` (default 100). Pass `loadDelayMs: 0` to start at once.
- **Rows that you scrolled past load again.** `maxLoadedRows` (default 10,000) unloads the blocks viewed longest ago. Raise it, or pass `Infinity`. See [Tune row retention](/docs/scroll-mode/tune-row-retention).
- **The scroll height grows in steps.** The source sends no row count, so blocks load one at a time, in order. See [Load without row count](/docs/scroll-mode/load-without-row-count).
- **One block fails while the others load.** The grid keeps the loaded rows and shows an error state. Fix the cause, then call `server.retry()`. See [Recover from load errors](/docs/scroll-mode/recover-load-errors).

## Selection [#selection]

**Checked rows vanish on a page change, or select all matching does nothing.** Both need `totalRowCount` and `checkedRowsLifetime="across-filters"`, the default with `totalRowCount`. The hook passes both. With your own fetch, pass `totalRowCount` to the grid. `actions.selectAllMatching()` returns the missing one as its `reason`.

## The hook setup [#setup]

**A warning says that the mode changed.** The hook cannot switch `mode` after mount, and React reports a changed hook order. To switch between pages and scroll mode, remount the component with a new `key`.

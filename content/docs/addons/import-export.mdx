Import and export live in the `data-grid-io` add-on, kept separate so the core stays free of the
`xlsx` and `papaparse` dependencies. gridcn lazily imports SheetJS (`xlsx`) only when an xlsx
export or import actually happens.

```tsx
import { DataGridToolbar } from "@/components/data-grid-toolbar/data-grid-toolbar";
import {
  DataGridExportButton,
  DataGridImportButton,
} from "@/components/data-grid-io/data-grid-io";

// Module scope (or useCallback) so identity stays stable across renders.
function createImportedRow(index: number): Row {
  return { id: `imported-${index}` /* ...defaults */ };
}

function onImport(rows: Row[]) {
  // decide how to merge — replace, append, or run through onDataChange yourself
}

<DataGridToolbar>
  <DataGridImportButton createRow={createImportedRow} onImport={onImport} />
  <DataGridExportButton />
</DataGridToolbar>;
```

## Export

`DataGridExportButton` opens a dropdown for xlsx or CSV. Internally, `exportGrid(state, options)`
takes:

<AutoTypeTable path="./registry/default/blocks/data-grid-io/export-grid.ts" name="ExportGridOptions" />

<Callout title="Serialized the same way copy is">
  Every cell is serialized through the `toText` of its cell type, the same pipeline that
  clipboard copy uses. So exported values match what a manual copy produces, not a raw
  `JSON.stringify`.
</Callout>

<Callout title="Encodings and Excel">
  CSV exports are UTF-8 and carry a UTF-8 BOM by default — Excel only detects UTF-8 when the file
  starts with a BOM, so without it umlauts and other non-ASCII characters open as mojibake. Pass
  `csvBom: false` to `exportGrid` when a downstream consumer chokes on a leading BOM character.
  XLSX exports write every cell as text (SheetJS's `aoa_to_sheet` from `toText` strings): a
  `number` column opens in Excel as text, not as a number, so it must be re-converted there if
  Excel arithmetic on it matters.
</Callout>

```tsx
// export exactly what's on screen (default)
exportGrid(state, { format: "csv" });

// export every row regardless of the current sort/filter
exportGrid(state, { format: "csv", scope: "all" });

// export only the selected rows, in view order
exportGrid(state, { format: "csv", scope: "selection" });
```

`scope` controls which rows get exported. The default, `'view'`, follows whatever the user
sees, the active sort and filter, by walking `viewIndex` (quick search never narrows
`viewIndex` — see [Sorting, filtering & search](/docs/sorting-filtering-search#search)). `'all'`
ignores view order entirely and exports every row of the raw `data` array as-is.
`'selection'` walks only the selected rows, counting both the marker checkboxes and any cell range.

Every scope emits all visible columns, so an exported row always lines up with its header row. A
cell range that covers part of a row still exports that row in full.

Export covers only loaded rows: on a [lazy](/docs/lazy-loading) grid, unloaded rows are skipped
in every scope. Export after the window you need is loaded.

`DataGridExportButton` forwards its `options` prop to `exportGrid`, so
`<DataGridExportButton options={{ scope: "selection" }} />` makes its menu export the selection.

`maxRows` caps the number of data rows in the export. The header row is not counted. When the
scope holds more rows, the export keeps the first `maxRows` rows and the dev console warns.

XLSX exports name their single sheet `workbookName` (default `'Sheet1'`). `buildXlsx(state, options)`
builds the workbook as a `Blob` without triggering a download, for uploads to a server.

`DataGridExportButton` takes an `onError` callback for a failed export. Without one, a failure
logs a dev-only warning.

## Import

`DataGridImportButton` opens a dialog that walks through the same pipeline that a paste uses
(`fromText` per cell type of the target column):

<Steps>
  <Step>
    ### Choose a file

    CSV/TSV or xlsx/xls. Drag a file onto the drop zone, or click it to open the file picker. A
    file of another type is rejected. The drop zone stays ready for another file. A multi-sheet
    workbook opens on its first sheet, and a sheet picker in the dialog switches it before you
    confirm. After a file loads, a compact drop zone shows its name. Drop or click there to replace
    the file without closing the dialog. The drop zone is its own `dropzone` item, and installing
    `data-grid-io` installs it too.
  </Step>
  <Step>
    ### Header row

    If the file has a header row, toggle "first row is a header".
  </Step>
  <Step>
    ### Delimiter

    Pick a CSV delimiter (auto-detected by default).
  </Step>
  <Step>
    ### Map columns

    Map each source column to a grid column, or skip it.
  </Step>
  <Step>
    ### Preview

    Preview the first rows.
  </Step>
  <Step>
    ### Confirm

    Runs every mapped cell through the `fromText` of its column's cell type. A cell that fails the
    column's `validate` is cleared, not dropped: its row is still imported, and `buildImportedRows`
    lists it in `rejected`. The dialog shows the rejected count and stays open until you close it.
  </Step>
</Steps>

<Callout type="warn" title="createRow is required">
  It builds the base row, with defaults for any grid column absent from the imported file, and
  the dialog writes mapped values onto this base row.
</Callout>

In the dialog, each grid column can be mapped from at most one source column at a time. Once a
source column claims a grid column, that grid column disappears from every other source column's
select, so a duplicate mapping cannot be created. A custom mapping built with `setMapping` is not
checked. `buildImportedRows` logs a dev-time warning when two source columns claim one grid
column, and the later mapping wins. If the file's headers auto-match to the same grid column more
than once, `matchImportColumns` keeps the first match and leaves the rest on "— Skip —".

The dialog never writes to the grid directly. `onImport(rows)` hands you the fully-built row
array, and you decide how to apply it: replace all data, append it, or run it through your own
`onDataChange` for history or audit purposes. See the demo above, which routes imported rows
through `grid.onDataChange` with an explicit `delete` and `insert` ops batch.

## Import options

Pass `importDefaults` to set defaults for the dialog's preselection step:

```tsx
<DataGridImportButton
  createRow={createImportedRow}
  onImport={onImport}
  importDefaults={{
    autoDetectDelimiter: false,
    defaultDelimiter: ";",
    defaultSkipColumns: ["internal_id", 0],
    mapColumn: (header) => (header === "e-mail" ? "email" : undefined),
  }}
/>
```

<AutoTypeTable path="./registry/default/blocks/data-grid-io/match-import-column.ts" name="ImportDefaults" />

Every option only sets the dialog's starting point. The user can still change any mapping,
delimiter, or the header-row toggle by hand once the dialog is open.

`defaultSkipColumns` names a source column by its header text (case-insensitive) or its 0-based
index. `mapColumn` runs after the built-in header matcher and wins over `defaultSkipColumns`.
Return a grid column id from `mapColumn` to map the column. Return `null` to skip it. Return
`undefined` to keep the matcher's answer.

Each mapping row also has a quick-skip button next to its Select. Click it to skip that column in
one step. The button hides once the column is already skipped.

## Dropzone

The import dialog's drop target is its own registry item, `dropzone` — installing `data-grid-io`
installs it too. Use it standalone for any file-drop surface:

```tsx
import { Dropzone, DropzoneEmptyState, DropzoneContent } from "@/components/dropzone/dropzone";

<Dropzone accept={{ "text/csv": [".csv"] }} maxSize={5_000_000} onDrop={(files, rejections) => {}}>
  <DropzoneEmptyState />
  <DropzoneContent />
</Dropzone>;
```

| Prop | Type | Default | Meaning |
|---|---|---|---|
| `accept` | `Record<string, string[]>` | accepts every file | MIME-to-extensions map, e.g. `{ "text/csv": [".csv"] }`. |
| `maxFiles` | `number` | unlimited | Maximum files per drop or pick. Also sets the file input's `multiple` (off when this is 1). |
| `maxSize` | `number` | none | Maximum file size in bytes. |
| `minSize` | `number` | none | Minimum file size in bytes. |
| `disabled` | `boolean` | `false` | Ignores drop, click, and keyboard activation. |
| `compact` | `boolean` | `false` | Single-row layout (icon + content inline) instead of the tall centered box. |
| `onDrop` | `(accepted: File[], rejections: DropzoneRejection[]) => void` | — | Called after a drop or file-picker selection, win or lose. |
| `onError` | `(error: Error) => void` | — | Called when the native file read itself fails. |
| `src` | `File[]` | — | Currently held files, read by the default `DropzoneContent`. |
| `className` | `string` | — | Merged onto the drop-surface root after the built-in classes. |

### Styling hooks

| Attribute / prop | Meaning |
|---|---|
| `data-drag-active` | Present on the zone root while a file is dragged over it. |
| `data-disabled` | Present on the zone root while `disabled` is true. |
| `className` | Merges after the built-in classes — a conflicting utility wins. |

```css
[data-drag-active] {
  border-color: var(--color-primary);
  background-color: color-mix(in oklch, var(--color-primary) 8%, transparent);
}
[data-disabled] {
  cursor: not-allowed;
}
```

## Lower-level pieces

`useDataGridExport()` and `useDataGridImportPreview()` expose the same logic as hooks, if you want to
build custom UI instead of using the provided buttons and dialog. `parseImportFile`,
`matchImportColumns`, `applyImportOptions`, and `buildImportedRows` are the pure functions
underneath, for when you need to parse or map outside a React component entirely.

`parseImportFile` takes a `sheetName` option for multi-sheet workbooks (first sheet by default.
An unknown `sheetName` rejects), and the result's `sheetNames`/`sheetName` report what was in the
workbook and which one you got. Switching sheets re-parses and recomputes the column mapping from
scratch, discarding any manual mapping from the previous sheet:

```tsx
// import a specific sheet of a multi-sheet workbook
const { rows, sheetNames } = await parseImportFile(file, { sheetName: "Q3 Data" });

// loop over every sheet, e.g. to import each one into its own grid
for (const name of sheetNames ?? []) {
  const parsed = await parseImportFile(file, { sheetName: name });
}
```

```tsx
const { rows, rejected } = await buildImportedRows({ dataRows, mapping, columns, cellTypes, createRow, signal });
```

`buildImportedRows` resolves to `{ rows, rejected }`, where `rejected` lists every cell that failed
its column's `validate` and was cleared. It returns the object directly for a synchronous import of
5,000 rows or fewer. Above that (or with an async Standard Schema `validate` on a mapped column) it
returns a Promise — await the result either way. Large imports run in chunks that yield to the event
loop, and an `AbortSignal` passed as `signal` cancels between chunks, rejecting with
`"import-cancelled"`.

Each `rejected` entry is one cleared cell:

| Field | Type | Meaning |
|---|---|---|
| `rowIndex` | `number` | Index into `dataRows`, header row excluded. |
| `importColumnIndex` | `number` | Index of the source column in the import file. |
| `gridColumnId` | `string` | The grid column the value was mapped to and cleared in. |

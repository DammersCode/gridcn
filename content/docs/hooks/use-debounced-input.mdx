Committing on every key floods the parent with updates. Committing after a pause can lose the last keystrokes or cut an IME composition in half. `useDebouncedInput` waits for a pause and adds the rules that make the wait safe. The hook has no dependency on the grid.

<InstallCommand item="use-debounce" />

The item installs [`useDebounce`](/docs/hooks/use-debounce) and `useDebouncedInput` to `components/gridcn/use-debounce.ts`.

## Usage

Pass the committed value and a commit callback. Spread `inputProps` on the input:

```tsx
const [name, setName] = useState("");
const input = useDebouncedInput(name, setName);

<input {...input.inputProps} />
```

The input shows each keystroke at once. `onCommit` runs when the typing pauses for `delayMs`.

The hook takes `value`, `onCommit`, and an options object.

| Option | Type | Default |
|---|---|---|
| `delayMs` | `number` | `300` |

A `delayMs` of `0` commits each keystroke. The text inputs of the grid wait the provider prop `inputDebounceMs`, which is `200` by default.

| Result | Meaning |
|---|---|
| `inputProps` | The props of the input: `value`, `onChange`, `onBlur`, `onKeyDown`, `onCompositionStart`, `onCompositionEnd`. |
| `inputValue` | The text in the input. It is what the user typed while it is pending or until `value` reaches it, otherwise `value`. |
| `flush()` | Commits a pending value now. |
| `cancel()` | Drops a pending value and shows `value` again. |

## When the value commits

- Blur commits a pending value.
- Enter commits a pending value.
- Unmount commits a pending value, so closing a popover inside the wait never loses the last keystrokes.
- Escape drops a pending value and shows `value` again. Nothing is committed.
- During an IME composition, nothing commits and Enter does nothing. The commit is scheduled when the composition ends.
- A commit calls the latest `onCommit`, not the one from the render that scheduled it.

## What the input shows

- A change of `value` from outside shows in the input when nothing is pending. While text is pending, the input keeps the text.
- After a commit, the input keeps the typed text until the parent applies the commits. It also yields when `value` changes to a text that is not a commit of the input. Then it shows `value`.
- A parent that applies a commit late never flashes the old text. The echo of an older commit does not replace newer typing.
- If the user types the same text twice, the echo of the first commit can show for a moment.
- The hook remembers the last 64 commits that the parent has not applied. The echo of an older commit counts as a change from outside.
- A parent that never applies a commit leaves the typed text in the input. The text stays until Escape or until `value` changes to a text that is not a commit.

## Handlers after the spread

A handler that you place after the spread (`onKeyDown` or `onChange`) replaces the one in `inputProps`. Then call `flush()` for Enter and `cancel()` for Escape yourself. Call `inputProps.onChange` from your `onChange`:

```tsx
<input
  {...input.inputProps}
  onKeyDown={(event) => {
    if (isComposingKey(event)) return;
    if (event.key === "Enter") input.flush();
    if (event.key === "Escape") input.cancel();
  }}
  onChange={(event) => {
    input.inputProps.onChange(event);
    // Your own work on the typed text
  }}
/>
```

<Callout type="warn" title="Your own Enter and Escape handlers">
  If you replace `onKeyDown`, test `isComposingKey(event)` first. Enter confirms an IME composition. Without the test, the handler commits half-composed text.
</Callout>

# ViewIndex branding: not shipped

`ViewIndex` already exists as a brand (`types.ts`) and the `At` row actions accept it. The condition was that every view index the library hands out is typed `ViewIndex`. That cannot be met cleanly. The library hands out view indexes in `ViewCoord.row`, `viewRowIndex` in about ten callback and event types, `GetRowClassName`, selection and range channels, and the store state, about 530 mentions of `ViewCoord` or `viewRowIndex` in the registry. Each construction site would need a `viewIndex()` cast, and the code does arithmetic on these values (`row + 1`, range loops, clamps) that returns plain `number` and loses the brand. A partial brand is worse than none: a type-test could not pin "every" index, and callers would see a mix of branded and plain values. The inputs stay `number`, the `At` actions keep the brand, and the stable row id stays the primary key.
